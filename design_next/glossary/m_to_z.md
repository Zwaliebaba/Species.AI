# Glossary M–Z

> Status: Reference · Glossary · Related: [Glossary index](README.md), [Glossary A–L](a_to_l.md), [Conventions](../CONVENTIONS.md)

This file defines the Species terms that start with the letters M to Z. [README.md](README.md) explains how to read an entry; Species identifiers and string-id prefixes for each term are in [CONVENTIONS.md §8](../CONVENTIONS.md#8-naming).

## M

| Term | Kind | Definition | Owning document |
|---|---|---|---|
| main loop | engine term | The loop that runs a participant's frames. In a match, each iteration of the in-match loop pumps input, takes command frames, runs the update slices of the ticks that are due and renders the frame; the front end and the loading view run loops of their own. | [Tick timing and main loop](../reference/12_simulation_model/01_tick_timing_and_main_loop.md) |
| map | player concept | One playable level: a map definition that sets the terrain, structures, starting forces and match options for its modes and its player count. Maps are named `map_<mode>_<players>p_<nn>`; the reference map set has 49 maps, and every Species map is authored new (see DEC-063). | [Maps and level design](../reference/08_maps_and_level_design/README.md); [Map rules and conventions](../reference/08_maps_and_level_design/rules_and_conventions.md) |
| map definition | data term | The authored content of one map, in blocks: the terrain definition, terrain tiles, terrain flatten areas, map lights, structures, routes, start positions with their camera views, camera animations, starting forces and match options. The content build validates it against its schema (ADR-059), and it is identified by its map id. | [Data schemas](../architecture/components/data_schemas/README.md); [Map rules and conventions](../reference/08_maps_and_level_design/rules_and_conventions.md) |
| map editor | engine term | The in-game map editor, with its map editor window, hub page and map file picker. The reference has no reachable map editor; the library records its hooks: what a map can express and an editor edits, the entry and exit flow and custom-map handling (see DEC-045). | [Map editor hooks](../reference/08_maps_and_level_design/map_editor_hooks.md) |
| map effect | data term | One of the five effect flags that a map definition can set, in this order: snow, lightning, dust wind, Essence-orb rain and special lighting. Snow, lightning and dust wind spawn weather effects; special lighting gives the structures one warm key light, and every Launch Race match uses it too; no reference map sets Essence-orb rain (see DEC-562). | [Map rules and conventions](../reference/08_maps_and_level_design/rules_and_conventions.md) |
| map id | data term | The stable identity of a map, its name `map_<mode>_<players>p_<nn>`; the hash of the cooked map asset is the content version of that id, never a substitute name (ADR-060, DEC-204). The content build generates the map index, the list of map ids that the achievement hooks count (DEC-563). | [Data schemas](../architecture/components/data_schemas/README.md); [Build tooling and distribution](../architecture/components/build_tooling_and_distribution.md) |
| map light | engine term | A plain record of one directional light of a map, with its colour and direction; the renderer uses it and the simulation never does. Every reference map uses exactly two directional lights (see DEC-562). | [Renderer](../architecture/components/renderer/README.md) |
| map option | data term | One of the 15 per-map settings inside the match options, in this order: no Catch-up bonus, instant Spawn Node capture, Transit Gate reinforcement count, Transit Gate Transport cap, no gun turrets, attacker reinforcement count, defender reinforcement count, defender reinforcement power, attacker reinforcement power, same-team Beam Dish links, no Beam Dish aiming, airstrike threshold, Visitor-faction position, attacker reinforcement power option and defender reinforcement power option. | [Map rules and conventions](../reference/08_maps_and_level_design/rules_and_conventions.md) |
| map thumbnail | data term | The preview image of a map, rendered with the engine by the content build from a top-down view of the map at an aspect ratio of 4:3 (DEC-563). | [Build tooling and distribution](../architecture/components/build_tooling_and_distribution.md) |
| Massacre | player concept | Achievement: the local team has killed at least 2,000 enemy Workers on the tick the match ends. The stated goal is more than 3,000 kills; the design phase restates the threshold (see DEC-047). | [Options, localisation and hooks](../reference/09_front_end_and_match_flow/options_localisation_and_hooks.md) |
| match | player concept | One played map, from the end of loading to the end-of-match sequence. It is the lifetime of the match world and of all per-match state, which is reset at every match start (DEC-011). | [Match rules](../reference/01_skirmish_rules_and_modes/README.md); [Match lifecycle and state reset](../reference/12_simulation_model/02_match_lifecycle_and_state_reset.md) |
| match camera | engine term | The player's camera in a match. Its live modes are free movement (cursor-follow panning at 250 wu/s, 1,000 wu/s with the speed modifier held, and zoom by narrowing the vertical field of view from 60° to 15°), tracking a selected actor, and aiming a structure; it is local and the simulation never reads it (DEC-024). | [Controls, camera and commands](../reference/06_controls_camera_and_commands/README.md); [View, lighting and fog](../architecture/components/renderer/view_lighting_and_fog.md) |
| match input pump | engine term | The per-frame step that turns the local player's controls into player commands and into the team command state. | [Controls, camera and commands](../reference/06_controls_camera_and_commands/README.md); [Input](../architecture/components/input.md) |
| match options | player concept | The typed settings of one match, each with an explicit default per mode (DEC-073): the lobby options (score mode, time limit, Catch-up bonus, crate drop rate, starting powers, Comeback Bonus, sudden death, crate drop mode, reinforcement interval, reinforcement count, Transport cap, turret frequency and turret cap, each in the modes that offer it) and the values that the map definition sets (its modes, player count, population caps, co-op, excluded outcomes, Transit Gate values and map options). A map value overrides the lobby default, and 0 is a value, not an absence (DEC-065). | [Match rules](../reference/01_skirmish_rules_and_modes/README.md); [Map rules and conventions](../reference/08_maps_and_level_design/rules_and_conventions.md); [Data schemas](../architecture/components/data_schemas/README.md) |
| match rules | engine term | The per-match rules object. It holds the mode, the match options, the lobby slots and the grace period, runs the mode's rules once per mode second, runs the reinforcement waves and the Comeback Bonus, keeps the scores and the HUD, and declares the winner (DEC-017). | [Match rules](../reference/01_skirmish_rules_and_modes/README.md) |
| match setup | engine term | The record of a match that is fixed before match start and identical for every participant: the map, the mode, the match options, the teams, the seed and the seasonal state (DEC-013, DEC-118). Lobby changes reach it as ordered commands (see DEC-243). | [Screen flow and match setup](../reference/09_front_end_and_match_flow/screen_flow_and_match_setup.md); [Match lifecycle and state reset](../reference/12_simulation_model/02_match_lifecycle_and_state_reset.md) |
| match world | engine term | The container of one match: teams, structures, Essence orbs, laser bolts, effects, terrain, sea, spatial grids and route graphs. It advances the simulation in update slices and resolves simulated-object handles. | [Containers and update order](../reference/12_simulation_model/04_containers_and_update_order.md) |
| mesh | engine term | A hierarchical flat-shaded mesh: a tree of mesh nodes with transforms, triangles and vertex colours, carrying named mesh sockets. Meshes are authored as glTF 2.0 and cooked into a Species runtime format (ADR-019, ADR-020). | [World renderers](../architecture/components/renderer/world_renderers.md); [Data schemas](../architecture/components/data_schemas/README.md) |
| mesh node | engine term | One node of a mesh's hierarchy: geometry plus a transform. | [Data schemas](../architecture/components/data_schemas/README.md) |
| mesh socket | engine term | A named point attached to a mesh node that code looks up to place ports, doors, beam origins and effects. The content build checks sockets against a schema per asset class (ADR-021). | [Data schemas](../architecture/components/data_schemas/README.md); [Asset pipeline and resources](../architecture/components/asset_pipeline_and_resources.md) |
| meteor | engine term | One rock of a meteor shower: it falls straight onto a point near the target and explodes with explosion radius 50 wu and damage 100. | [Creatures and hazards](../reference/02_units/README.md) |
| meteor shower | player concept | A Supply crate outcome: 5–9 meteors fall into a 420 × 420 wu square around the target, and game speed drops to 0.4× for a slow-motion phase (DEC-039). It is not filtered by team (see DEC-107). | [Supply crates and powers](../reference/04_supply_crates_powers_and_weapons/crates_and_powers.md) |
| Missile Barrage | player concept | An advanced Supply crate outcome, valid only on maps with sea: 10 barrage missiles launched from the sea strike the target, the first exactly on the point and nine within ±150 wu of it, each with explosion radius 50 wu and damage 100 (see DEC-303). | [Supply crates and powers](../reference/04_supply_crates_powers_and_weapons/crates_and_powers.md) |
| mode | player concept | One of the six match modes, in this order: Spawn Control, Zone Control, Relic Run, Siege, Launch Race and Flag Chain. The mode selects the rules that the match rules run and the lobby options offered (DEC-017, DEC-058). | [Match rules](../reference/01_skirmish_rules_and_modes/README.md) |
| mode second | player concept | The unit of the per-mode rule clocks (the match clock, the elimination countdowns, the Relic timers, the reinforcement waves and the rank checks): an explicit constant of 11 ticks, so a displayed second lasts 1.1 s (DEC-002, DEC-003). | [Match rules](../reference/01_skirmish_rules_and_modes/README.md); [Population flow](../reference/05_population_flow.md) |
| mortar turret | player concept | The turret type that lobs mortar rounds, grenades that explode on impact; it reloads in 40 ticks. | [Defences and props](../reference/03_buildings_and_world_objects/defences_and_props.md) |
| MSAA | abbreviation | Multisample anti-aliasing of the scene colour and depth targets, with Off, 2x and 4x settings (ADR-015). | [Renderer options and budgets](../architecture/components/renderer/options_and_budgets.md) |
| MSVC | abbreviation | Microsoft Visual C++, the pinned Windows compiler toolset of Species (ADR-051). | [Build tooling and distribution](../architecture/components/build_tooling_and_distribution.md) |
| music channel | engine term | The audio engine's dedicated streaming voice for music. Nothing plays music in a match; the library records the music hooks only (see DEC-049). | [Audio engine](../architecture/components/audio_engine.md); [Audio design](../reference/10_audio_design/README.md) |
| muzzle flash | engine term | A short-lived cosmetic flash at a firing point. | [Weapons and projectiles](../reference/04_supply_crates_powers_and_weapons/weapons_and_projectiles.md) |

## N

| Term | Kind | Definition | Owning document |
|---|---|---|---|
| network statistics window | engine term | A development-build window that shows network statistics, with correct units; its metric set is open (DEC-041, see DEC-208). | [Diagnostics, test and performance](../architecture/components/diagnostics_test_and_performance.md) |

A structure with no team can be captured, a Spawn Node with no team produces nothing, and a Transit Gate with no team never reinforces; the no-team colour is an opaque grey (DEC-078, DEC-464). | [Teams and player commands](../reference/12_simulation_model/06_teams_and_player_commands.md) |

## P

| Term | Kind | Definition | Owning document |
|---|---|---|---|
| pack file | engine term | A Species content archive in its own indexed, chunked and hashed format, written by the content build. An ordered mount manifest lists the base packs and then the patch packs; a later pack overrides an entry only where the manifest marks it as a patch for that pack, and profile and shipping builds read packed content only (ADR-058). | [Asset pipeline and resources](../architecture/components/asset_pipeline_and_resources.md) |
| page | engine term | One state of the front-end screen, with its own set-up, widgets and teardown; the front-end screen has 18 live pages in 38 numbered page slots. | [UI pages and screen recipes](../architecture/components/ui_framework/pages_and_screen_recipes.md); [Screen flow and match setup](../reference/09_front_end_and_match_flow/screen_flow_and_match_setup.md) |
| particle | engine term | One instance of the particle pool, of one of the 19 particle types. | [Animation and VFX](../architecture/components/animation_and_vfx/README.md) |
| particle pool | engine term | The presentation pool of particles of 19 types, simulated on the GPU and drawn as camera-facing billboards; it never feeds the simulation (ADR-010, DEC-007). | [Animation and VFX](../architecture/components/animation_and_vfx/README.md) |
| passengers | player concept | The 100 Workers that must board a Launch Vessel through its fuel depot before it can launch. | [Mode objects](../reference/03_buildings_and_world_objects/mode_objects.md) |
| pause | player concept | A sequenced command that stops the match at the next tick; it is allowed only when no remote human takes part. Game speed ramps to 0, and back to normal on resume, over a 2.1 s speed ramp (DEC-038). | [Tick timing and main loop](../reference/12_simulation_model/01_tick_timing_and_main_loop.md); [Controls, camera and commands](../reference/06_controls_camera_and_commands/README.md) |
| PCM | abbreviation | Pulse-code modulation: uncompressed sample data. Short, frequently triggered sounds are held as 16-bit PCM at 48 kHz (ADR-025). | [Audio engine](../architecture/components/audio_engine.md) |
| player command | engine term | One entry of the player command catalogue, the only way player intent reaches the simulation apart from the team command state (DEC-008). The commands of each tick are applied in a fixed order. | [Teams and player commands](../reference/12_simulation_model/06_teams_and_player_commands.md) |
| PNG | abbreviation | Portable Network Graphics, the format of screenshots, written with the system's image encoder; it is never read as game data (ADR-076). | [Diagnostics, test and performance](../architecture/components/diagnostics_test_and_performance.md) |
| population cap | player concept | The per-team limit on bodies that freezes Spawn Node and Transit Gate production: the map's population cap divided by the map's player count, with a defender cap and a shared attacker remainder in Siege. It counts the team's ungrouped actors, its bot controller, Transports, Leaders, Crawler eggs and fading corpses included, minus its Crawlers (see DEC-079, DEC-453). | [Population flow](../reference/05_population_flow.md) |
| Population Limiter | player concept | An invisible regional population limiter (search radius 500 wu, maximum population 100 by default) that takes effect only on a map that sets no population cap. On every reference map it has no effect, because each map either sets a population cap or places no limiter (see DEC-454). | [Economy and spawn objects](../reference/03_buildings_and_world_objects/economy_and_spawn_objects.md); [Population flow](../reference/05_population_flow.md) |
| port | player concept | A slot on a structure, placed at a mesh socket, that one Worker occupies to operate or capture it; ports carry per-team reservation counters. A Spawn Node and a Solar Array have 5 ports, and a turret has 4. | [Buildings and world objects](../reference/03_buildings_and_world_objects/README.md) |
| Power | player concept | A granted ability (a unit, a strike, a turret or a buff) held in a Power slot until the player places it on the map. A Power moves through four states: idle, waiting to be placed, running and stopping. | [Controls, camera and commands](../reference/06_controls_camera_and_commands/README.md) |
| power and research levels | engine term | The research table, with one level per research type, whose types double as Power kinds. Match start fixes every level: all at 3, then Strike team at 1, laser, grenade, rocket and airstrike at 2, and Worker at 4 (see DEC-115). | [Units](../reference/02_units/README.md) |
| Power slot | player concept | One place in a team's Power slots. Every pending, placed or running Power occupies one (DEC-033). | [Controls, camera and commands](../reference/06_controls_camera_and_commands/README.md) |
| power-slot message | player concept | A short message of the Power slots panel. In message order: Ready, Not available, Cancelled, Unlocked, Improved and Objectives complete; two further messages report a full set of slots: All power slots full and Comeback powers: slots full. | [Controls, camera and commands](../reference/06_controls_camera_and_commands/README.md) |
| Power slots | player concept | A team's set of 6 Power slots, 2 while it is eliminated. A Power granted while every slot is full is lost, and the All power slots full message shows (DEC-033); the power bar orders the slots and the number keys select by position (see DEC-556). | [Controls, camera and commands](../reference/06_controls_camera_and_commands/README.md) |
| power slots panel | engine term | The in-match interface of the Power slots: the slots at the screen edge, the bar of running Powers and the pop-up for the most recently received Power. The bar is clickable and shows its empty slots (DEC-083). | [Controls, camera and commands](../reference/06_controls_camera_and_commands/README.md) |
| presentation generator | engine term | A random generator for presentation only: cosmetic effects, audio variation and every other presentation draw. It is separate from the simulation generator and never feeds simulation state; every presentation consumer has its own instance (DEC-013, DEC-222). | [Randomness and integrity](../reference/12_simulation_model/07_randomness_and_integrity.md) |
| presentation generator seed | engine term | Sets the state of a presentation generator. The process-wide presentation generator is re-seeded with 1 at every match-world initialisation. | [Randomness and integrity](../reference/12_simulation_model/07_randomness_and_integrity.md) |
| presentation random fraction | engine term | A presentation draw uniform over [0, r], r included. | [Randomness and integrity](../reference/12_simulation_model/07_randomness_and_integrity.md) |
| presentation random integer | engine term | A presentation draw of a non-negative integer. | [Randomness and integrity](../reference/12_simulation_model/07_randomness_and_integrity.md) |
| presentation random signed fraction | engine term | A presentation draw uniform over [−r/2, r/2], both ends included. | [Randomness and integrity](../reference/12_simulation_model/07_randomness_and_integrity.md) |
| previous camera view | data term | The named camera view `previous_view`, which holds the camera pose from before a camera animation started (see DEC-803). | [Camera and sequences](../architecture/components/camera_and_sequences.md) |
| procedural foot | engine term | The foot of a procedural leg: the point that the leg plants on the terrain. | [Creatures and hazards](../reference/02_units/README.md); [Animation and VFX](../architecture/components/animation_and_vfx/README.md) |
| procedural leg | engine term | A procedural two-bone leg with an inverse-kinematics solver, used by the spider. Its state is presentation only, and no simulation rule reads it (DEC-007, ADR-035). | [Creatures and hazards](../reference/02_units/README.md); [Animation and VFX](../architecture/components/animation_and_vfx/README.md) |
| product name | engine term | The game-title constant, Species, used for the window title and the user-data folder. | [Platform layer](../architecture/components/platform_layer.md) |
| profile folder | engine term | The per-user data folder `%LOCALAPPDATA%\<Studio>\Species\`, which holds the settings file and the logs; nothing is written beside the executable (ADR-071). | [Platform layer](../architecture/components/platform_layer.md) |
| promotion to Leader | player concept | Turning a selected Worker into a Leader with the promote command; Leaders are created only this way. Demotion turns a selected Leader back into a Worker, and scrapping a unit is a separate action (DEC-086). | [Controls, camera and commands](../reference/06_controls_camera_and_commands/README.md) |
| PSO | abbreviation | Pipeline state object of Direct3D 12; the render pass table maps onto a catalogue of them (ADR-005). | [Renderer](../architecture/components/renderer/README.md) |

## R

| Term | Kind | Definition | Owning document |
|---|---|---|---|
| rank announcement | player concept | Once per mode second, in every mode except Siege and Flag Chain, the local player gets a position message whenever the rank of their team among the player teams changes. A team's rank is the number of teams with a strictly better score, plus 1 (DEC-074). | [Match rules](../reference/01_skirmish_rules_and_modes/README.md) |
| ready (ready-up) | player concept | The per-team flag that a human player toggles during the grace period, and in the lobby, to signal readiness. When every human team is ready the countdown runs, and withdrawing readiness restarts it (DEC-036). | [Match rules](../reference/01_skirmish_rules_and_modes/README.md); [Screen flow and match setup](../reference/09_front_end_and_match_flow/screen_flow_and_match_setup.md) |
| Ready (power-slot message) | player concept | The power-slot message shown when a Power starts. | [Controls, camera and commands](../reference/06_controls_camera_and_commands/README.md) |
| Reaper Serpent | player concept | A fast flying serpent that dives through enemies and destroys their Essence orbs; it is the strongest creature, with at most 2 alive at once. Workers that it kills leave Wisps. | [Creatures and hazards](../reference/02_units/README.md) |
| reinforcement count | player concept | The match option for the number of Workers that each owned Transit Gate releases per reinforcement wave: 1–100, default 40, in Launch Race and Flag Chain; elsewhere the map's value applies. | [Population flow](../reference/05_population_flow.md) |
| reinforcement interval | player concept | The match option for the time between reinforcement waves: 10–300 mode seconds in steps of 10, default 60, in Launch Race and Flag Chain; 60 mode seconds in every other mode. | [Population flow](../reference/05_population_flow.md) |
| reinforcement wave | player concept | A timed wave from every owned Transit Gate: once per reinforcement interval each gate releases Workers and, by mode and map, grants Transport, turret or airstrike Powers; the HUD counts down to the next wave (DEC-065). | [Population flow](../reference/05_population_flow.md) |
| Reinforcements | player concept | A basic Supply crate outcome, applied at once: 50–99 Workers of the opening team appear at the Supply crate. | [Supply crates and powers](../reference/04_supply_crates_powers_and_weapons/crates_and_powers.md) |
| Relay | player concept | A pure relay node of the spawn network: indestructible and without ports. | [Economy and spawn objects](../reference/03_buildings_and_world_objects/economy_and_spawn_objects.md) |
| Relic | player concept | The Relic Run carryable structure, created during the match: enough Workers lift and carry it, and delivered within 30 wu of an owned Relic Base it scores 1 point. | [Mode objects](../reference/03_buildings_and_world_objects/mode_objects.md) |
| Relic Base | player concept | A team-owned Relic Run zone that scores the Relics delivered into it; it is a Control Zone. | [Mode objects](../reference/03_buildings_and_world_objects/mode_objects.md) |
| Relic Run | player concept | The mode in which groups of Workers lift Relics and carry them into their own Relic Base; each delivery scores 1 point, and the highest score at time-up wins. | [Relic Run](../reference/01_skirmish_rules_and_modes/relic_run.md) |
| Relic Spawn Zone | player concept | A Relic Run zone with no team, where new Relics appear; it is a Control Zone. | [Mode objects](../reference/03_buildings_and_world_objects/mode_objects.md) |
| remote player team | engine term | The team kind of a team that is controlled from another machine. | [Teams and player commands](../reference/12_simulation_model/06_teams_and_player_commands.md) |
| render pass table | engine term | The ordered list of the passes of one match frame (sky, terrain, sea, structures, actors, laser bolts, particles, explosions, markers and UI), each with its full state; the frame graph and the PSO catalogue are built from it (ADR-004, ADR-005). | [Frame graph and passes](../architecture/components/renderer/frame_graph_and_passes.md) |
| replay | player concept | Recording the player-command history of a match and playing it back. The reference has only a hidden hook for it; the library records the hooks and the determinism they rely on (see DEC-046). | [Diagnostics, test and performance](../architecture/components/diagnostics_test_and_performance.md) |
| results screen | player concept | The end of a match: when a winner is declared, game speed ramps to 0 and is locked, and the winner and score overlay shows. There is no separate results page, and players leave through the in-match menu (see DEC-048). | [Match rules](../reference/01_skirmish_rules_and_modes/README.md); [Screen flow and match setup](../reference/09_front_end_and_match_flow/screen_flow_and_match_setup.md) |
| RGBA / RGBA8 | abbreviation | Colour channel orders; RGBA8, 8 bits per channel, is the in-memory format of every decoded image. | [Asset pipeline and resources](../architecture/components/asset_pipeline_and_resources.md) |
| RGBA8 image | engine term | A decoded image in memory, 8 bits per channel, with colour keying, pixel operations and texture upload; gameplay code builds run-time textures from it. | [Asset pipeline and resources](../architecture/components/asset_pipeline_and_resources.md) |
| RNG | abbreviation | Random number generator. The simulation generator serves all gameplay randomness and the presentation generators serve every cosmetic draw (DEC-013, DEC-242). | [Randomness and integrity](../reference/12_simulation_model/07_randomness_and_integrity.md) |
| rocket | engine term | The rocket projectile, fired by rocket turrets and by Workers under Rocket Troops. | [Weapons and projectiles](../reference/04_supply_crates_powers_and_weapons/weapons_and_projectiles.md) |
