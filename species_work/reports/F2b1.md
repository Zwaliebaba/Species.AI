- Scripts, all run with `python3 -I`:
  - `species_work/scripts/F2b1_spec.py`: the routing spec (data).
  - `species_work/scripts/F2b1_build.py <repo> <spec> <csv>`: builds the CSV and checks coverage.
  - `species_work/scripts/F2b1_peek.py`: reads a line range.
  - `species_work/scripts/F2b1_sizes.py <csv>`: package sizing.
  - `species_work/scripts/F2b1_lists.py <csv>`: the row lists below.

**How the plan was built.** Ranges come from `headings.csv`, using the same line and byte convention. `F2b1_build.py` checks every file:
- the rows cover every line from 1 to the H1 `end_line`, with no gaps;
- ranges overlap only where rows deliberately share an identical range (KEEP plus TO-DEC, TO-ADR or TO-ASSETS, or DROP-PROVENANCE plus TO-DEC on the open-questions tables);
- every DROP, DEFER and KEEP-HOOKS note starts with a reason code from `drop_topics.md`;
- no DROP row has a target or owner.

The last run reported no problems.

**Granularity.** Rows are at H2 level where one action fits. Otherwise they are at H3 level, with an `(intro)` row for the H2's own lines. Explicit line ranges are used in five places:
- the constants tables 20 §12.1 and 22 §16, split into KEEP / DEFER / DROP blocks;
- 22 §14.5, where the generated census is DP-INDEX and §14.5.1 is KEEP;
- 22 §14.8 at H4 level (DD-NUMERIC, TO-DEC and DD-TERRAIN-RUNTIME);
- 23 §13 intro to §13.5, and 23 §17 intro to §17.3.
