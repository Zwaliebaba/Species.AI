## New DEC requests and DEC corrections

1. **DEC-304 wording conflict.** DEC-304 says Spawn Surge gives "each Spawn Node of the opening team" its requests. The input states the surge timer belongs to the match world, so every active, unlocked Spawn Node of **every** team requests every tick. The document follows the input (R-ECON-045). Please correct DEC-304's specified behaviour.
2. **Transport cap of 0.** In the wave rule a Transport cap of 0 means "no limit". DEC-065 now makes a map value of 0 a real value, so a map that sets 0 would grant unlimited Transports. New Open DEC requested: whether a map Transport cap of 0 means none or no limit (default: no limit, as specified).
3. **Map values over lobby defaults (DEC-065).** Applied to the reinforcement count and Transport cap. Three reference Flag Chain maps set a count of 100 and a cap of 3; under the fixed rule their waves become 100 Workers with up to 3 Transports instead of the lobby's 40 and 2. DEC-065 says such maps are re-tuned through their values; G08 should confirm the values.
4. **Integer tick ranges vs DEC-002.** Replaying the countdowns gives uniform ranges whose lower end is one tick above DEC-002's list: later evaluations 21–30 (DEC-002: 20–30), first production timer 21–40 (20–40), Floating 301–500 (300–500), limiter recount 91–110 (90–110); DEC-002's lower ends occur only for a draw of exactly 0. The document states the replayed ranges and notes DEC-002's bounds in the tuning table. Request: align DEC-002's text.
5. **Starting-power fallback.** Under DEC-014/DEC-021 the starting-power draw is a uniform draw over the valid, non-excluded outcomes; I specified "no power is granted when no outcome qualifies" as the deterministic fallback. Confirm in DEC-021.
6. **Second-tutorial lock.** The input checks "team 0"; DEC-103 forbids fixed team ids in tutorials, so rule 1 of R-ECON-052 names "the tutorial player's team". Confirm (G11 / DEC-103).
7. **Port occupancy binding.** DEC-088 binds occupancy to the (structure, port) pair; DEC-094 and DEC-016 keep the grid-order tie. R-ECON-012 and R-ECON-013 combine them: the occupant is the first operating Worker, in grid order, among those operating that port of that structure within 5 wu. G03a should state the same.
8. **Flag Chain airstrike threshold.** The input reads "at least (flags + 1) ÷ 2 Flag posts, or more than the map's threshold when set"; whether the map threshold replaces or adds to the half-flags test is not stated. Specified as written (either condition); possible Open DEC.
9. **Grace period.** R-ECON-004 states that no match-time timer of the economy advances during the grace period (the reference clock runs at speed 0 then). C-SIM-c and G01 should confirm this against DEC-036/DEC-039 (game speed as tick scheduling).
10. **Population Limiter overpopulation halving.** Whether the halving is an integer division is not stated in the input; written as `÷` (integer). Inert on every reference map (DEC-454); low priority.

## Input for the routed DEC-011 conflict (C-SIM-a and G03a)

The economy input says that, until the new map's Source Node first advances, a stale Source Node id is resolved and requests in that window are dropped. The window is the first tick of the match. A Spawn Node requests only when its production timer (21–40 ticks) has expired, or during a Spawn Surge, so on the reference maps the stale id affects no request; on a map without a Source Node a stale id fails its kind check and nothing is requested (R-ECON-032). The document states the fixed per-match registry (R-ECON-121).
