# F2b2 — Routing plan for ORIG 26–32

## Files written

- `species_work/routing_F2b2.csv`: 600 rows over the seven documents (26 animation and VFX, 27 audio engine, 28 UI framework, 29 data formats, 30 scripting, tutorials and cut-scenes, 31 platform, build and tools, 32 debug, test and performance).
- `species_work/scripts/F2b2_heads.py`, `F2b2_peek.py`: heading and line-range readers.
- `species_work/scripts/F2b2_route.py` and `scripts/F2b2_defs/<nn>.txt`: per-document routing definitions, resolved against `headings.csv`. The script computes `bytes` from the ORIG lines in the same way as `headings.py`, and it checks coverage.
- `species_work/scripts/F2b2_check.py`: checks the column rules and sums the package sizes. `F2b2_report.py` generates the tables below.

To regenerate everything: `python3 -I scripts/F2b2_route.py headings.csv ../design scripts/F2b2_defs/<nn>.txt routing_F2b2.csv` for each document, then `python3 -I scripts/F2b2_check.py routing_F2b2.csv drop_topics.md headings.csv`.

- **Column rules:** every DROP, DEFER-DESIGN and KEEP-HOOKS note begins with a code from `drop_topics.md`, of the right family (DL, DP, DD or KH). DROP rows have empty target and owner fields. TO-DEC and DEFER-DESIGN rows are owned by `X-DEC`, TO-ADR rows by `X-ADR`, and TO-ASSETS rows by `X-AST`. Every target is relative to `design_next/`.
- **Routing level:** rows are at H2 level. Where an H2 mixes actions, its H3 children are routed instead, plus a row for the H2's own intro lines. The exception is 29 §4.1 (level files, 49 KB), which is routed at H4.
- The H1 title, the provenance banner and the contents list are `DROP-PROVENANCE` / `DP-INDEX`.

## Package split proposal

No package has more than 150 KB of input from documents 26–32. However:

- **C-UI is at the limit**: 149,987 bytes of KEEP, plus 2,108 bytes of KEEP-HOOKS (152,095 bytes in total). I propose two agents writing a `ui_framework/` folder:
  - **C-UI-a**, core and widgets: 28 §1–§5, §7–§10 and §14 (window core behaviour, standard window and button, widget set, front-end widget family, layout, rendering, navigation, localisation, constants), about 99.8 KB, plus the 4.9 hook.
  - **C-UI-b**, pages and screens: 28 §6, §11 and §13 (page graph and state machine, widget catalogue, recipes for building a screen, defects as acceptance tests), about 52.3 KB.
- **C-DAT** (126 KB plus 5.7 KB of hooks) will probably write more than 120 KB. It should plan a `data_schemas/` folder (map schema; configuration, input and strings; entity, audio, geometry and panel schemas).
- **C-VFX** (118.7 KB) and **C-AEN** (104 KB) are within the limit. Their output files may need a folder split under §4 rule 9.
- Contributions to packages that other F2 agents also feed (the coordinator sums them across all routing files): C-AST gets 13.6 KB (29 §10.1, 31 §8.7–8.8), G11 gets 49 KB (30 §3), and G06 gets 0.8 KB (30 §4.2).
