- **Requests from other packets, applied:** P6-RB requests 9 and 10; P6-RD requests 4, 5, 6 and 7 (rows at the end of the table).
- **The rule behind the declaration findings (ruling 6).** New requirement **README DAT-054** ("One declaration per type") states how the generator works. An object becomes an aggregate with its keys in camelCase. An enumeration becomes an `enum class` with its strings in PascalCase. The generator only converts case, so the keys and enumerator strings that generate identifiers are spelt in American English, and the generator rejects a word that R11 spells otherwise or a C++ keyword. An enumeration field may bind to a component's enumeration through `x-species-ref`; the sound-layer enumerations of AEN do this (DAT-015 extended). The document that lists a record type's fields (table 1-A, column "Fields") holds the generated declarations, and every other document cites them with `// generated from <schema id>: <document> §2`. The data-schema files now declare the import records, the terrain and camera records of a map, the sound records and the DSP filter kinds, and the soak records. AST, AEN, TER, CAM and DBG cite them.
- **Dependency direction (R3b-16).** README §2 has a new "Dependencies" paragraph. Data-schema code builds on the asset pipeline's run-time vocabulary (`AssetId`, `VariantId`, `ContentType`, `PackEntry`, `Sha256Digest`) and on the platform file functions. The asset pipeline's run-time interface names nothing of this folder except generated aggregates such as `MeshAsset`. The import records are DAT's, and the cookers read them in the content build tool.
