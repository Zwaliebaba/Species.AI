# R4b — Consistency: numbers and references

Reviewer R4b, Phase 5. Scope: all of `design_next/` except the generated `requirements_index/`, with `vision/species-vision-brief.md` §3 for the owner decisions O1–O28 and `.github/workflows/build.yml` read only to check what the documents say about it. `design/` was not read.

Method. Ten helper scripts (`species_work/scripts/R4b_tuning.py`, `R4b_tuning2.py`, `R4b_tuning3.py`, `R4b_tuning4.py`, `R4b_ticks.py`, `R4b_assets.py`, `R4b_assetroles.py`, `R4b_consumers.py`, `R4b_adr.py`, `R4b_adr2.py`, run with `python3 -I`, output in `species_work/scripts/R4b_out/`) did the mechanical part:

- extracted all 3,710 tuning rows, then compared every place a key is cited with a value beside it (3,937 citations in prose, formulas, tests and non-tuning tables, numeric and non-numeric forms, with unit factors for s/ticks, kHz/Hz and ms/s) against the owning row, and listed keys of different documents that share a name or a value for the same concept;
- compared every tuning row in ticks whose notes give seconds (149 rows) and every prose pair "N ticks, X s" (40 differing pairs), and listed every key whose unit is seconds (169) for a manual check of simulation timers;
- extracted every asset id cited anywhere in the library, backticked or not, including `decisions/`, `ADR/`, `glossary/`, `CONVENTIONS.md` and `assets/GameAssets.md` (the asset gate reads only `reference/` and `architecture/components/`), compared loop, one-shot, streamed and resident wording at each citation with the manifest's spec and format, and compared the manifest's `consumers` with the requirements that cite each id (the differences are wildcard citations such as `icon.power.<kind>`, so that comparison yields no finding);
- read the front matter of every ADR and compared it with the index and with every status cited in a document, including the multi-ADR status cells of the §8 tables.

Every hit reported below was then checked by hand in context. The mode list, the per-mode options, the cap formulas and the owner decisions were checked by reading.

Checked and found consistent (no finding): every one of the 464 asset-id tokens cited anywhere is in the manifest, and all 452 manifest ids are cited outside `assets/`; the ADR index and the 64 ADR files agree (45 Accepted, 18 Proposed, 1 Rejected), as do the 30 prose status citations; the six modes are in one order everywhere (glossary, R-MODE-029, R-META-030, `MatchMode`, the manifest's per-mode files, reference/07 table 2.5); the option sets and defaults of R-MODE-073/074, R-META-067, the mode files and data schema table 3.12-A agree (apart from rows 58 to 61); the map counts per mode (9, 9, 9, 8, 7, 7 = 49) agree between reference/08, R-VIS-023, the manifest and the achievements; every per-team cap figure of reference/08 tables 2.17 to 2.22 and 2.24-A follows from the DEC-079 formula, and the mode files, R-ECON-052 to R-ECON-055, R-MAP-062 and the map schema state that formula identically; the Transport-cap option (1 to 10, default 2, Launch Race and Flag Chain) agrees in reference/01, reference/05, reference/09 and the glossary; the three package pins agree in ADR-055, the ADR index, ADR-001/028/068 and BLD table 4.1-A; the clang-tidy and clang-format pins and the CI jobs agree with `build.yml` apart from row 85; R-VIS-126 (600 ticks) is already R3a's finding and is not repeated.
