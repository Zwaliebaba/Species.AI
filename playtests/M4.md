### The fuzzer

ADR-088's 10⁷ inputs per parser: `GameSharedTests/MessageFuzzTests`, built with 10,000,000 inputs per message, gave each of the 39 game messages' parsers its inputs:
- half random bodies under the message's real header;
- half the message's default encoding with a bit flipped, truncated or extended.

That is 3.9 × 10⁸ inputs in all. They ran on a Linux build of GameShared and NeuronCore under AddressSanitizer and UndefinedBehaviorSanitizer, the same sources as the Windows build with Linux stand-ins for the platform files. Every input was delivered or dropped with its reason. No input crashed, and the sanitizers reported no fault, overflow or leak. The run was on 2026-10-24, from commit 5f6a08b, in 32.5 minutes on one core, its build included. The CI suite runs the same code at 4,000 inputs per message on every build.

### The owner's link run

On the reference test machine, from a Developer PowerShell at the repository root:
1. `python Build\RunPerformance.py --link`, which builds `Release|x64`, starts the link simulator on two free loopback ports, runs the link scene for 30 minutes with a rejoin at minute 20, and records the result below. It fails when a line is missed.
2. Leave the computer awake for the run: a sleep stalls the server's ticks, and the run then measures the sleep.
