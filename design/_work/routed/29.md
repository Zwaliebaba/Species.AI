## [→ 29_data_formats_reference] 29.T Text-file tokeniser (`TextReader` family) — rules used by every text format

Classes [C] `contrib/systemiv/lib/filesys/text_stream_readers.{h,cpp}`, `contrib/systemiv/lib/unicode/unicode_text_stream_reader.{h,cpp}`:

| Class | Source | Encoding | Created when |
|---|---|---|---|
| `TextFileReader` | disk (`fopen "r"`, text mode: CRLF→LF) | 8-bit | loose file without UTF-16 BOM |
| `TextDataReader` | memory (archive entry) | 8-bit | archive entry without BOM |
| `UnicodeTextFileReader` | disk (`"rb"`) | UTF-16 LE/BE by BOM | loose file with BOM `FF FE` / `FE FF` |
| `UnicodeTextDataReader` | memory | UTF-16 LE/BE by BOM | archive entry with BOM |

Selection is done by the caller: `code/lib/resource.cpp:Resource::GetTextReader` (and `PrefsManager::Load`) first constructs the Unicode reader and falls back to the 8-bit reader when `IsUnicode()` is false [C].

### 29.T.1 Line acquisition

* 8-bit file reader: `fgets` into a buffer that starts at 128 chars and doubles until the line (up to and including `\n`) fits; lines longer than 65536 chars → fatal `AppReleaseAssert` "Text file contains line with more than 65536 characters". `ReadLine()` returns **false only when nothing could be read** (so the final line is processed even without a trailing newline) [C] `TextFileReader::ReadLine`, `TextReader::DoubleMaxLineLen`.
* 8-bit memory reader: scans to the next `\n`; if none, takes the rest and sets EOF; **returns false for the last line when the data does not end with `\n`** — callers that loop `while (reader->ReadLine())` drop that line. Files packed in archives must therefore end with a newline, whereas the same file loose on disk is parsed fully [C] `TextDataReader::ReadLine`; [I] consequence (all parsers use the `while(ReadLine())` idiom, e.g. `code/lib/language_table.cpp:ParseLanguageFile`).
* UTF-16 readers: same contracts on 16-bit units (BE: `(b0<<8)|b1`, LE: `(b1<<8)|b0`); the memory reader also returns false on the last line. The wide line is converted to a parallel narrow `char` line where every code unit > 255 becomes `'?'` and ≤ 255 is truncated to its low byte (Latin-1 preserved), index-aligned with the wide line [C] `contrib/systemiv/lib/unicode/unicode_string.cpp:CopyUnicodeToCharArray`.

### 29.T.2 Line cleaning (`CleanLine`), applied once per line, in this order

1. **Decryption** (only if the file is encrypted, §29.T.4).
2. **Comment removal**: scanning left to right, the first `#` that is not itself `<`/`>` terminates the line (replaced by NUL). There is **no quoting or escaping** — `#` can never appear in a value. Three or more consecutive `<`/`>` characters (merge-conflict marker) trigger `AppDebugAssert` (no effect in release).
3. The **first** `\n` and the **first** `\r` (searching from the start, stopping at the first NUL) are replaced by NUL.
[C] `TextReader::CleanLine`, `UnicodeTextReader::CleanLine`.

Edge case [C, derived]: because step 3 stops at the comment NUL, in `abc#comment\n` the `\n` survives after the NUL; `GetNextToken` treats the string terminator as a separator and moves *past* it (§29.T.3), so a comment glued to the last token (no separator before `#`) is returned as further tokens. Always put whitespace before `#`.

For `UnicodeTextFileReader` the narrow copy is made *before* cleaning (`CopyUnicodeToCharArray` precedes `CleanLine`), so 8-bit tokenisation (`GetNextToken`) of a loose UTF-16 file sees the raw, uncommented line, while `GetRestOfUnicodeLine`/`TokenAvailable` use the cleaned wide line; `UnicodeTextDataReader` cleans first [C] `UnicodeTextFileReader::ReadLine` vs `UnicodeTextDataReader::ReadLine`.

### 29.T.3 Tokenisation

Separator set (default, never changed by any Multiwinia parser — no call to `SetSeperatorChars` exists in `code/`) [C grep]:
* 8-bit: `" \t\n\r:,"` (space, tab, LF, CR, colon, comma);
* UTF-16 readers: `L" \f\t\n\r:,"` (adds form feed) for `TokenAvailable`/`GetNextUnicodeToken`/`GetRestOfUnicodeLine`; but `GetNextToken` (narrow) still uses the 8-bit set.

```
line        := { sep } [ token { sep { sep } token } ] { sep }
sep         := " " | "\t" | "\n" | "\r" | ":" | ","            (8-bit)   ; + "\f" (UTF-16 wide calls)
token       := char { char }      char := any non-separator, non-NUL character
```

| Call | Behaviour |
|---|---|
| `TokenAvailable()` | true iff a non-separator char exists at or after the cursor |
| `GetNextToken()` | returns NULL if cursor at NUL; skips separators; returns NULL if none left; otherwise scans to the next separator **or the NUL terminator** (strchr matches NUL), writes NUL there and advances the cursor *one past it*. Consecutive separators collapse; empty tokens are impossible; `a::b` → `a`,`b` |
| `GetRestOfLine()` / `GetRestOfUnicodeLine()` | skips separators at the cursor, returns the remainder **verbatim** (internal separators, trailing spaces kept); NULL / empty string when at end |
| `GetNextUnicodeToken()` (UTF-16 readers) | same algorithm on the wide line, returns a `UnicodeString` copy |

Consequences: colon and comma are interchangeable with whitespace in every format (`x: 1, 2` ≡ `x 1 2`); values cannot contain spaces unless the consumer reads rest-of-line; numeric parsing is done by the consumer (`atoi`, `iv_atof` → float-rounded, §22.4).

`UnicodeTextReader::SetSeperatorChars` copies the new characters over the start of the wide separator array without terminating it (old trailing separators stay active) [C] — unused by Multiwinia.

### 29.T.4 Encrypted text files ("redshirt2")

Writer [C] `contrib/systemiv/lib/filesys/text_file_writer.cpp:TextFileWriter` (8-bit) and `code/unicode/unicode_text_file_writer.cpp:UnicodeTextFileWriter` (UTF-16):

```
file        := "redshirt2" encrypted_text          ; marker written once, no newline after it
offsets[16] := 31 7 9 1 11 2 5 5 3 17 40 12 35 22 27 2
state       := idx = 0 (persists across lines and printf calls)
encrypt(c)  := if c > 32 (signed char / wchar):  idx = (idx+1) mod 16;  e = c + offsets[idx];  if e >= 128: e -= 95;  emit e
               else emit c unchanged (space, control chars; and bytes >= 128 in the 8-bit writer, which are negative)
```
Reader [C] `TextReader::CleanLine`: on the **first line**, if it starts (case-insensitively, `strnicmp`) with `redshirt2`, the file is marked encrypted and the 9 characters are removed; each later character `c > 32` is decrypted with `idx = (idx+1) mod 16; j = c − offsets[idx]; if j < 33: j += 95`. The mapping is a bijection on printable ASCII 33…127. Decryption happens before comment stripping, so `#` inside encrypted text is a real comment only after decryption.
UTF-16 reader bug: it tests `StrOffsetCmp(L"redshirt2", 9, true)`, i.e. compares characters 9…17 of the first line, so encrypted UTF-16 files are not recognised [C] `UnicodeTextReader::CleanLine`. No Multiwinia call site writes encrypted files (`Resource::GetTextFileWriter(_, _encrypt)` exists; prefs use `encrypt=false`) [C] `code/lib/preferences.cpp:Save`.

### 29.T.5 UTF-16 text writer
`UnicodeTextFileWriter` opens `"w"`, switches the CRT stream to `_O_U16TEXT` and writes BOM U+FEFF; output is UTF-16LE with `\n` translated to CRLF by the CRT; `printf(UnicodeString)` uses the string as a **format string** (a `%` in a value corrupts output) [C] `code/unicode/unicode_text_file_writer.cpp`. Mac writes UTF-16LE explicitly via CoreFoundation [B:DEAD].

## [→ 29_data_formats_reference] 29.P Preferences file (`preferences.txt`)

Owner: `code/lib/preferences.cpp:PrefsManager` (`g_prefsManager`), constructed in `code/app.cpp:App::App` with `App::GetPreferencesPath()` [C].

### 29.P.1 Grammar (as parsed by `PrefsItem::PrefsItem(UnicodeString line)` after `TextReader` cleaning)

```
file      := { line }
line      := blank | item | other
blank     := a line with no alphanumeric character before the first '#'  (kept verbatim as template text)
item      := { non_alnum } key value_sep value
key       := alnum { alnum }                      ; iswalnum — letters/digits only; '_' or '.' END the key
value_sep := any_char { wspace | '=' }           ; the char right after the key is consumed unconditionally (whatever it is),
                                                  ; then any iswspace() char or '=' is skipped
value     := rest of line (after TextReader comment stripping; trailing spaces kept)
```
Because the line first goes through the tokeniser's cleaning (§29.T.2), a value can never contain `#` (e.g. a player name with `#` is truncated on the next load); `:` and `,` inside values are preserved (rest-of-line), but leading `:`/`,` before the key are skipped.
Value typing [C] `PrefsItem::PrefsItem`:

| Condition on `value` | Type | Stored as |
|---|---|---|
| first char is `-` or a digit, and contains 0 `.` | `TypeInt` | `wtoi` = `std::wistringstream >> int` (leading integer; `"1024x768"` → 1024; unparsable → 0) |
| first char `-`/digit and exactly 1 `.` | `TypeFloat` | `wtof` (`wistringstream >> float`) |
| first char `-`/digit and ≥ 2 `.` | `TypeString` | e.g. `127.0.0.1` |
| anything else (incl. empty) | `TypeString` | `UnicodeString(value)` |

Lookup is **strictly typed**: `GetInt` on a float- or string-typed item returns the caller's default; `GetFloat` on an int item (e.g. `DarwinianScaleFactor = 2`) returns the default; `GetString` returns the narrow (`'?'`-substituted) copy [C] `PrefsManager::GetInt/GetFloat/GetString/GetUnicodeString`. Keys are case-sensitive (`std::map<UnicodeString>` ordered by `wcscmp`) [C].

### 29.P.2 Load / defaults / overrides [C] `PrefsManager::PrefsManager`, `Load`, `CreateDefaultValues`, `AddLine`

1. `Load()`: clears; opens the file as UTF-16 (`UnicodeTextFileReader`) else 8-bit; if not openable → `CreateDefaultValues()`.
2. Otherwise every line's `GetRestOfUnicodeLine()` is passed to `AddLine`. **Corruption check:** on the first line, every character before the first space or `=` must be in `L'A'…L'z'`; otherwise the whole file is discarded, defaults recreated and immediately saved.
3. `AddLine(line)`: if not blank, all `\r`/`\n` are stripped, a `PrefsItem` is parsed; a **duplicate key is ignored** (first occurrence wins, debug message "Duplicate preference item %s. Ignoring") unless the static `s_overwrite` flag is set, in which case the new value replaces the old; the line text is appended to the template list `m_fileText` (also for blanks).
4. `CreateDefaultValues()` adds, in order (PC values):
   `ServerAddress = 127.0.0.1`, `BypassNetwork = 0`, `ServerPort = 4000`, blank, `TextLanguage = unknown`, `TextSpeed = 15`, `HelpEnabled = 1`, blank, `SoundLibrary = dsound`, `SoundMixFreq = 22050` (Mac 44100), `SoundMasterVolume = 255`, `SoundChannels = 32` (slow Mac 16), `SoundHW3D = 0`, `SoundSwapStereo = 0`, `SoundMemoryUsage = 1`, `SoundBufferSize = 512`, `SoundDSP = 0`, blank, `RenderLandscapeDetail = 1`, `RenderWaterDetail = 1`, `RenderBuildingDetail = 1`, `RenderEntityDetail = 1`, `RenderCloudDetail = 1`, `RenderPixelShader = 1`, blank, `DarwinianScaleFactor = 2.00`, `ControlMouseButtons = 3` (Mac 1), `ControlMethod = 1`, `MultiwiniaControlMethod = 1`, (Linux/Mac: `RenderLandscapeMode = 2`, `ManuallyScaleTextures = 0`), then non-demo: `BootLoader = firsttime`, `UserProfile = AccessAllAreas`, `ScreenOverscan = 0`, `RenderSpecialLighting = 0`, `Difficulty = 1` (`OTHER_DIFFICULTY`). (`DEMOBUILD` variants set `StartMap`, `UserProfile = DemoUser`, `RenderSpecialLighting` [B:DEAD].)
   Then, with `s_overwrite = true`, each line of resource `default_preferences.txt` (via `g_app->m_resource`) is added, overriding the hard-coded values — but see §31.5.3: in a packaged install this file is in `main.dat`, which is not yet loaded, so it is not found [I].
5. After loading: `SetInt("MultiwiniaControlMethod", 1)` is forced ("Hack by Chris to disable old-style control"); the constructor adds `ControlMethod = 1` if `GetInt("ControlMethod")` returns −1 [C].
6. Defaults for keys absent from an existing file are **the caller's default argument** at each `Get*` site — there is no merge with the hard-coded list once a file exists. Inventory of keys and call-site defaults: `_work/drafts/P14_platform_lib_pref_keys.csv` (≈75 distinct keys, 100 key/macro spellings; regex-based, multi-line calls may be missed [I]).
7. `App::SetPreferenceOverrides()` (P01) runs immediately after construction [C] `code/app.cpp:App::App`.

### 29.P.3 Save [C] `PrefsManager::Save/SaveItem`
* Writer: `UnicodeTextFileWriter(m_filename, encrypt=false, assertOnFail=false)` → UTF-16LE with BOM, CRLF; silently returns if the file cannot be opened.
* Template pass: for each stored line in original order: blank → written verbatim (note: blank lines read from a file were stored as empty strings and are written as nothing, so blank lines collapse after the first save; hard-coded `"\n"` blanks survive); item line → the key is re-extracted (first alnum run up to the first non-alnum before `=`) and the current item is written once as `key = value` (`%ls = %d`, `%ls = %.2f`, `%ls = %ls`, each + `\n`); a line whose key is directly followed by `=` (no space) has no detectable key end and is re-emitted verbatim **without newline**, and the item is then written again at the end (duplication bug); a non-blank line without `=` makes the key scan run past the end of the string (crash risk).
* Then every item not yet written is appended in `std::map` order (`wcscmp`).
* Floats are written with **2 decimals** (`%.2f`) — precision loss on round trip.
* Values are passed through `vswprintf` as part of the format string, so `%` in a string value is interpreted.

Recommendation: replace with a strictly-typed key/value store (TOML/JSON), explicit schema with defaults in one table, atomic save.

## [→ 29_data_formats_reference] 29.L Language files and caption markup (`LANGUAGEPHRASE`)

### 29.L.1 File format [C] `code/lib/language_table.cpp:LangTable::ParseLanguageFile`
```
file   := { line }                        ; UTF-16 LE/BE with BOM, or 8-bit (english.txt is ASCII)
line   := key rest | comment-or-blank      ; '#' comments and separators per §29.T
key    := first token (no space, ':' or ',')
rest   := GetRestOfLine (leading separators removed — a value cannot start with ':' or ',')
```
* Each `\` immediately followed by `n` is replaced by **space + newline** (`"a\nb"` → `"a \nb"`); other backslashes stay.
* A trailing `\n` and, at length−2, a `\r` or `\f` are removed (indexes computed from the string length; an empty value reads index −1/−2 — every key must have a non-empty value; in an 8-bit file a key with no value makes `GetRestOfLine` return NULL and the `UnicodeString(const char*)` constructor dereferences it [I: crash]).
* **Duplicate keys: the later definition replaces the earlier** (opposite of preferences) [C].
* Raw store: `BTree<LangPhrase*>` keyed case-insensitively (`stricmp`).
* Overlay: after `language/<lang>.txt`, `App::SetLanguage` parses `strings_<lang>.txt` or else `strings_default.txt` into the same table (overrides) [C] `code/app.cpp:SetLanguage`.

### 29.L.2 Input-mode variants and final tables [C] `RebuildTables`, `RebuildTable`, `wrong_suffix`, `chomp_mode_suffix`, `specific_key_exists`

Two final tables (`HashTable<UnicodeString*>`, case-insensitive) are built: keyboard (`INPUT_MODE_KEYBOARD`, suffix `_kbd`) and gamepad (`INPUT_MODE_GAMEPAD`, suffix `_xin`). For each raw key not starting with `part_`:

| Raw key form | Entry added to table for mode M |
|---|---|
| `foo` and no `foo_<M>` exists | `foo` → caption(`foo`, M) |
| `foo` and `foo_<M>` exists | skipped (the specific one wins) |
| `foo_<M>` | `foo` → caption(`foo_<M>`, M) |
| `foo_<other>` and neither `foo` nor `foo_<M>` exists | `foo` → empty string (feature hidden in mode M) |
| `foo_<other>` otherwise | skipped |
| `part_*` | never in final tables; only usable as `[part_x]` references |

Tables are (re)built lazily on first lookup and explicitly after `SetLanguage` [C].

### 29.L.3 Caption markup (expanded at table-build time) [C] `buildCaption`, `consumeMarker`, `consumeIfMarker`, `consumeKeyMarker`, `consumeOtherMarker`, `buildPhrase`, `markerLength`
Output limit `SEPULVEDA_MAX_PHRASE_LENGTH = 1024` wide chars (truncated); key names ≤ `MAX_READ_KEY_LENGTH = 64`, final key buffer `MAX_FINAL_KEY_LENGTH = 96`.

```
text      := { char | marker }
marker    := "[IFMODE " "KEYBOARD]"         ; case-insensitive. If mode != keyboard: stop writing until matching [ELSE]/[ENDIF]
           | "[ELSE]" | "[ENDIF]"            ; nesting tracked by ifdepth / writingStopDepth
           | "[KEY" control_name "]"         ; replaced by the noun of the input currently bound to control_name
                                             ; (g_inputManager->getControlID + getBoundInputDescription); if unresolved,
                                             ; falls through to phrase reference "KEY<name>"
           | "[" [" "] phrase_key "]"        ; phrase reference: key lower-cased, looked up raw (key_<mode> first, then key),
                                             ; expanded recursively with a fresh parser state; a leading space in the marker
                                             ; emits one space before the expansion (always, even if empty)
```
Rules: `[IFMODE X]` for any X other than `KEYBOARD` while writing still increments `ifdepth` but is then consumed as a phrase reference `ifmode x`; unknown phrase references vanish silently; `[]` is consumed. **An unterminated `[`** makes `markerLength` return 0, `consumeOtherMarker` add −1 to the input offset, and the loop re-read the same `[` forever (hang during `RebuildTables`) [I: derived from code arithmetic]. There is no escape for a literal `[`.

### 29.L.4 Lookup API and fallback [C] `LookupPhrase`, `RawLookupPhrase`, `DoesPhraseExist`, `code/lib/language_table.h`
* `LANGUAGEPHRASE(k)` ≡ `g_app->m_langTable->LookupPhrase(k)`; `ISLANGUAGEPHRASE(k)`/`ISLANGUAGEPHRASE_ANY(k)` ≡ `DoesPhraseExist(k)`; `RAWLANGUAGEPHRASE(k)` ≡ `RawLookupPhrase(k)`.
* `LookupPhrase`: current table by `g_inputManager->getInputMode()`; NULL key or no table → `"ERROR (null)"`; **missing key → the key text itself** is returned (no fallback to English at phrase level; language-level fallback only at load, §31.11).
* `RawLookupPhrase(k, mode)`: `k_<mode>` then `k`, else `"ERROR (k)"`.
* The returned reference for misses points into a shared `m_notFound` member (overwritten by the next miss — not thread-safe).
* Narrow access (`(const char*)UnicodeString`) maps non-Latin-1 chars to `?`.

### 29.L.5 Word wrapping [C] `WordWrapText(UnicodeString…)` / `WordWrapText(const char*…)`
Line width in characters = `int(lineWidth / fontWidth)`. Explicit `\n` always break. Over-long lines break at the last space within the width (or exactly at the width if that char is a space), else at the last CJK character (U+3000–U+D7FF, `LastHanCharacter`), else either `_forceWrap` (hyphenate: `width−1` chars + `"-"`) or leave the line unbroken.

### 29.L.6 Unicode string type [C] `contrib/systemiv/lib/unicode/unicode_string.{h,cpp}`
`UnicodeString` owns a `wchar_t` buffer plus a parallel narrow copy (`?` for > 255); `m_linelength` = buffer size incl. NUL; `Length()` = buffer size − 1 (not `wcslen`); comparisons `wcscmp`; case ops `_wcsupr/_wcslwr` (locale-dependent); `ReplaceStringFlag(flag, s)` replaces every `*<flag>` with `s` (substitution syntax used in UI strings); `LastHanCharacter`; `Trim()` advances the buffer pointer past leading spaces (heap-corruption bug on later `delete[]` if leading spaces existed); `swprintf` via `wvsprintfW` (no float support, 1024-char limit on Win32 [I: API limit]).

## [→ 29_data_formats_reference] 29.D `Directory` binary format (network letters, metaserver data)

`contrib/systemiv/lib/tosser/directory.{h,cpp}` with `contrib/systemiv/lib/network_stream*.cpp` [C]. Used for every client/server letter and metaserver message (P15).

```
directory    := '<' name:dynstring  numData:packedint  { dirdata }×numData  numSubdirs:packedint  { directory }×numSubdirs  '>'
dirdata      := name:dynstring  type:u8  payload
payload      := type 1 INT:    i32 (LE)
              | type 2 FLOAT:  f32 (LE, raw IEEE bits)
              | type 3 CHAR:   u8
              | type 4 STRING: dynstring
              | type 5 BOOL:   u8 (0/1)
              | type 6 VOID:   len:i32 (LE, raw) bytes×len
              | type 7 FIXED:  (only under USE_FIXED; not compiled)
              | type 8 INTS:   count:packedint  i32×count
              | type 9 ULLONG: u64 (LE)
              | type 10 UNICODE: count:packedint  u16×count (UTF-16LE code units; -1 = NULL)
dynstring    := len:packedint  bytes×len           ; len = -1 → NULL string; len > 10240 (DIRECTORY_MAXSTRINGLENGTH) or < -1 → replaced by "[SAFESTRING]"
packedint    := u8 v (0..254) | 0xFF i32(LE)        ; values < 0 or >= 255 use the 5-byte form
```
* Writer emits only used `DArray` slots, in slot order (indices are not preserved: "Indexes are not important and can be forgotten") [C] `Directory::Write`.
* Reader limits: `numData` must be 0…1024 (`DIRECTORY_MAXDIRSIZE`), otherwise fail; **the subdirectory count is not validated** (the check re-tests `numData`); VOID length is unbounded; INTS count asserts (`AppAssert`, fatal) if `count×4 ≥ 10240` — all three are remote-input robustness bugs [C] `Directory::Read`, `ReadVoidData`, `ReadNumbersData`.
* Getters return safe values on missing/mistyped data: INT −1, FLOAT −1.0, CHAR `'?'`, STRING `"[SAFESTRING]"`, UNICODE `L"[SAFESTRING"` (sic, missing `]`), BOOL false, ULLONG `0xFFFFFFFFFFFFFFFF`, VOID → `"[SAFESTRING]"` pointer; `HasData(name, type)` [C].
* `CreateData(name, …)` replaces existing data of that name; DArray/LList helpers serialise as sub-directories `tID`, `Size`, `[i N]` (`[Used]`, `[Data]`); `GetDataLList(LList<int>)` reads the literal key `"indexName"` (bug → all −1) [C].
* Name lookup is linear `strcmp` (case-sensitive); sub-directory paths use `/`.
* `Directory::Write(int&)` returns a heap buffer (`ostrstream`) with a trailing NUL not counted in `length`.

## [→ 29_data_formats_reference] 29.B Binary readers, CRCs, hashes, keys

### 29.B.1 BinaryReader conventions [C] `contrib/systemiv/lib/filesys/binary_stream_readers.cpp`
All multi-byte reads are **little-endian** (`ReadS16 = b1|b2<<8`, `ReadS32 = b1|b2<<8|b3<<16|b4<<24`). EOF semantics differ by backend:

| Operation | `BinaryFileReader` (disk) | `BinaryDataReader` (archive) |
|---|---|---|
| `ReadU8/ReadS8` at end | returns `(char)EOF` = 0xFF, sets `m_eof` | same |
| `ReadS16/ReadS32` short | returns partial composite, sets `m_eof` | returns 0, sets `m_eof` (no partial read) |
| `ReadBytes(n)` | `fread`; `m_eof` only if fewer than n bytes | sets `m_eof` when the **last byte of the data** is consumed even if all n bytes were read; returns 0 immediately if already EOF |
| `Seek(SEEK_END, off)` | `fseek` | `offset = size − off` |
| `GetSize()` | Tell/Seek/Tell | same |
| `GetFileType()` | extension after last `.` | same |

Parsers that test `m_eof` after a successful final `ReadBytes` behave differently for loose and archived files [I].

### 29.B.2 `FileCRC` (map identity) [C] `contrib/systemiv/lib/math/filecrc.cpp`, `contrib/unrar/crc.cpp:CRC`
```
buffer = read bytes until m_eof: each iteration stores ReadU8() then index++, stopping after index > 100000
       => n+1 bytes for an n-byte file with n <= 100000 (the extra 0xFF comes from the EOF read);
          the first 100001 bytes of the file when n > 100000
          (in both cases index 100000 may be written one past the 100000-byte static buffer s_buffer)
crc    = CRC32 reflected, polynomial 0xEDB88320, initial value 0, NO final inversion, over buffer[0..count)
result = (int) crc ; formatted as 0x%08x in mapcrc.h
```
Equivalently `crc = ~zlib_crc32(~0 … )`-style relations do **not** hold; reimplement with init 0/no xorout. Identical for disk and archive readers (both append one 0xFF) [C].

### 29.B.3 `HashData` / authentication key hash [C] `contrib/systemiv/lib/math/hash.cpp`, `contrib/systemiv/lib/metaserver/authentication.cpp`
* `HashData(data, token, out)`: SHA-1 (unrar `hash_*`) of the ASCII string `"<data>-<token>"` (≤ 511 chars); output `"hsh"` + the five 32-bit words each printed with `%04x` (**at least** 4 hex digits, so 23–43 chars total, variable length).
* `HashData(data, out)`: SHA-1 of `data` (strlen), same output format. `HashDataVoid`: raw 5-word digest.
* Authentication keys: 31 visible characters (`AUTHENTICATION_KEYLEN 32` incl. NUL), format observed `XXXXXX-XXXXXX-XXXXXX-XXXXXX-XXX` (the open-source `Authentication_GenerateKey` always returns the fixed demo key `DEMOTP-AXYVLW-SGIZLU-DNLXPK-OJS`); keys starting with `hsh` are hashed keys (`Authentication_IsHashKey`), sent instead of the raw key using the server-supplied hash token; `Authentication_SetKey` trims trailing characters that are not `[A-Za-z-]`; `Authentication_LoadKey` reads one whitespace-delimited word (`fscanf %s`) or yields `"authkey not found"` [C]. Full validation protocol: P15.

### 29.B.4 `keygen` (Darwinia-era registration; compiled, never called) [C] `code/keygen.cpp` [B:LEGACY]

## [→ 29_data_formats_reference] 1. Shared line reader and tokeniser (`TextReader` family)

### 1.1 Purpose, classes and where they are chosen

Every text format in this document is read through one of five reader classes, all compiled into the baseline [B:FULL] [C] `targets/vs2005/Darwinia.vcproj` (entries `contrib\systemIV\lib\filesys\text_stream_readers.cpp`, `contrib\systemIV\lib\unicode\unicode_text_stream_reader.cpp`):

| Class | Source | Input | Encoding | Used when |
|---|---|---|---|---|
| `TextReader` (abstract) | `contrib/systemiv/lib/filesys/text_stream_readers.{h,cpp}` | – | – | base: cleaning + tokenising |
| `TextFileReader` | same | loose disk file, `fopen(...,"r")` (CRT text mode → CRLF read as LF) | single-byte (no transcoding; bytes ≥0x80 pass through) | disk file without a UTF-16 BOM |
| `TextDataReader` | same | in-memory block from a `.dat` archive | single-byte, raw bytes (CR kept, removed by cleaning) | archive entry without a UTF-16 BOM |
| `UnicodeTextFileReader` | `contrib/systemiv/lib/unicode/unicode_text_stream_reader.{h,cpp}` | loose disk file, `fopen(...,"rb")` | UTF-16 with BOM `FF FE` (LE) or `FE FF` (BE); 2 bytes per code unit, no surrogate handling | disk file whose first two bytes are a BOM |
| `UnicodeTextDataReader` | same | archive block | as above | archive entry beginning with a BOM |

Selection is done by `code/lib/resource.cpp:Resource::GetTextReader(name)` [C]:

1. (`USE_DARWINIA_MOD_SYSTEM` only — [B:DEAD]) `<profile>/mods/<mod>/<name>`, then (`TARGET_OS_VISTA`) `mods/<mod>/<name>`.
2. Loose file `data/<name>` (relative to the working directory): try `UnicodeTextFileReader`; if `IsUnicode()` is false (no BOM) delete it and use `TextFileReader`.
3. Archive entry `data/<name>` — `UnicodeTextDataReader`, else `TextDataReader`. Archive keys are lower-cased by `Resource::ParseArchive` and stored in a `HashTable` whose hash folds case and whose compare is `stricmp`, so the lookup is **case-insensitive** [C] `code/lib/resource.h` (`HashTable<MemMappedFile*> m_resourceFiles`), `contrib/systemiv/lib/tosser/hash_table.cpp:HashTable::HashFunc`.
4. Otherwise `NULL` and the debug log line `Failed to find text resource: <path>`.

A few callers bypass `Resource` and construct `TextFileReader`/`UnicodeTextFileReader` on an absolute or cwd-relative path directly (preferences, profile saves, `testbedconfig.txt`, `origin`, input bindings): they are listed per format. `contrib/systemiv/lib/filesys/file_system.cpp:FileSystem::GetTextReader` is compiled but `g_fileSystem` is never created by Multiwinia [C] (grep: no `new FileSystem` under `code/`) — ignore it.

`TextFileReader` and `UnicodeTextFileReader` call `FindCaseInsensitive(path)` before opening (`contrib/systemiv/lib/filesys/filesys_utils.cpp`) so loose files are matched case-insensitively on case-sensitive file systems [C]; on Win32 this is a no-op in effect [I].

### 1.2 Physical lines

* A line ends at LF (`0x0A` / `L'\n'`). The final line may lack an LF. Lines may be arbitrarily long: the buffer starts at 128 characters and doubles; a line longer than 65 536 characters triggers `AppReleaseAssert("Text file contains line with more than 65536 characters")` [C] `TextReader::DoubleMaxLineLen`, `UnicodeTextReader::DoubleMaxLineLen`.
* End of file: only `TextFileReader` processes an unterminated last line (its `ReadLine` returns `true` for a final line without LF and `false` on the following call). `TextDataReader` (archive), `UnicodeTextFileReader` and `UnicodeTextDataReader` load the unterminated last line but return `false` for it, so the `while (in->ReadLine())` loop body **never sees it** [C] `TextDataReader::ReadLine` (`eof = true` when no `\n` is found), `UnicodeTextFileReader::ReadUnicodeLine` (returns `NULL` as soon as `feof`), `UnicodeTextDataReader::ReadLine`. Rule for authors: **always end a text file with a newline** — five shipped files do not (`level_enum.txt`, `testbedconfig.txt`, `japanese.txt`, `korean.txt`, `portuguese.txt`; consequences in §2.19, §8.2, §11).
* A U+0000 code unit in a UTF-16 disk file is skipped without being stored (the slot keeps stale data) [C] `UnicodeTextFileReader::ReadUnicodeLine` (`temp != NULL` test) — never emit NUL.

### 1.3 Line cleaning (`TextReader::CleanLine`, `UnicodeTextReader::CleanLine`) — applied to every line, in this order [C]

1. **De-obfuscation.** On the first line only, if the line starts with `redshirt2` (case-insensitive, 9 chars) the file is marked encrypted and those 9 characters are removed. For every subsequent character `> 32` in an encrypted file: `i = (i+1) mod 16; c' = c − K[i]; if c' < 33 then c' += 95` with `K = {31,7,9,1,11,2,5,5,3,17,40,12,35,22,27,2}` and `i` starting at 0 and persisting across lines. Characters `≤ 32` (space, tab, CR, LF) are untouched. The writer side is `TextFileWriter(..., encrypt=true)` / `UnicodeTextFileWriter` (`c' = c + K[i]; if c' ≥ 128 then c' −= 95`) [C] `code/unicode/unicode_text_file_writer.cpp:UnicodeTextFileWriter::printf`. No shipped file under `data/` is encrypted (survey: no file starts with `redshirt2`) [C] `X1a_text_survey.py`; encryption is used only for runtime-written profile saves (§13).
2. **Comment removal.** Scan left to right; the first `#` and everything after it is deleted. There is **no escape and no quoting**: a `#` inside what looks like a string still starts a comment. While scanning, runs of `<` / `>` are counted and three adjacent angle brackets trip `AppDebugAssert` (merge-conflict detector; debug builds only — [B:DEBUG]).
3. **Line-end removal.** Truncate at the first `\n`, then truncate at the first `\r`. Consequence: a stray CR in the middle of a line silently discards the rest of that line.

Edge case (UTF-16 disk files): `UnicodeTextFileReader::ReadLine` converts the wide line to the narrow mirror buffer (`UnicodeString::CopyUnicodeToCharArray`, every code unit > 255 becomes `?`) **before** `CleanLine` runs on the wide buffer, so the narrow mirror still contains the comment text; `UnicodeTextDataReader::ReadLine` cleans first and converts afterwards [C]. Tokenising of the first token is done on the narrow mirror (`TextReader::GetNextToken` is not virtual) while `TokenAvailable`/`GetNextUnicodeToken`/`GetRestOfUnicodeLine` are overridden and use the wide buffer. Both buffers have identical indices (1 code unit ↔ 1 byte), so the rest-of-line read from the wide buffer is correct; but a first token with a comment glued to it (`key#note`) is returned as `key#note` from the narrow mirror (with a separator before `#` it is unaffected) [C]. A line that is entirely a comment is correctly skipped because `TokenAvailable` looks at the cleaned wide buffer [C].

### 1.4 Tokens

* Separator set (default): space, TAB, LF, CR, `:` and `,` — `" \t\n\r:,"` for the narrow readers; the Unicode readers additionally treat form-feed `\f` as a separator (`L" \f\t\n\r:,"`) [C] `DEFAULT_SEPERATOR_CHARS` in both `.cpp` files. `SetSeperatorChars` (max 15 characters) can replace the set, but no caller in `code/` or `contrib/systemiv/lib` uses it (grep) — every format in this document uses the default set [C].
* `GetNextToken()`: skip separators; if end of line → `NULL`; else return the maximal run of non-separators and overwrite the following separator with NUL. `:` and `,` are therefore exactly equivalent to whitespace — `BuildingOnline :mine,90` is the three tokens `BuildingOnline`, `mine`, `90`.
* `GetRestOfLine()`: skip separators, return the remainder of the line **verbatim** (internal separators, trailing spaces and tabs preserved — there is no right-trim) or `NULL` at end of line. Because of the leading skip, a "rest of line" value can never begin with space, tab, `:` or `,`.
* `TokenAvailable()`: true iff a non-separator character remains on the line.
* There is **no quoting, no escaping and no line continuation** at this level. Individual formats add their own conventions (the language table's `\n`, §8).
* Case: the reader never changes case. Keyword comparisons are done by each parser (mostly `stricmp`, i.e. ASCII case-insensitive; exceptions flagged **(cs)**).

### 1.5 Formal summary

```
file          := [ 'redshirt2' ] { line }                 ; header only on the very first line (case-insensitive)
line          := { char - LF } ( LF | EOF )
cleaned_line  := prefix of line before the first '#', then before the first LF, then before the first CR
separator     := ' ' | TAB | LF | CR | ':' | ',' [ | FF  (UTF-16 readers only) ]
token         := 1*( char - separator )
token_line    := { separator } [ token { 1*separator token } ] { separator }
rest_of_line  := everything after the leading separators, verbatim
```

#### 2.4.3 Menu scanner (second, independent parser) [C] `code/game_menu.cpp:GameMenu::AddMap`, `GameMenu::CreateMapList`

The main menu builds its map list by reading **every** `data/levels/mp_*` file with extension `txt` (loose files and archive entries; `.mwm` files from `<profile>/maps/` only under `LOCATION_EDITOR`), tokenising each line with the default separators and testing the first token with case-sensitive `strcmp` against `Name`, `GameTypes`, `NumPlayers`, `Author`, `Description`, `PlayTime`, `Difficulty`, `CoopMode`, `ForceCoop`, `OfficialLevel`, stopping at the first `MultiwiniaOptions_EndDefinition`. It does **not** check that it is inside the options block — a file without the block is scanned to the end. It then computes the map CRC (`MapData::CalculeMapId`, see 31 MapCRC) and sorts each game-type list by `NumPlayers`, then difficulty. Consequence for authors: keep the options block first and spell keywords exactly.

### 2.8 `Lights` block [C] `LevelFile::ParseLights`, `WriteLights`

```

```

`m_front = (x, y, z, 0)` then `Light::Normalise()` (infinitely distant directional light); `m_colour = (r, g, b, 0)` — colour components are unclamped multipliers (shipped values reach 2.00). ## [→ 29_data_formats_reference] 4. `data/multiwinia.txt` — game types and their parameters [B:FULL]

### 4.1 Purpose, files, parser

Defines the Multiwinia game types (in **file order**, which *is* the game-type index used by code, maps, network and UI) and each type's lobby parameters. Loaded once by `Multiwinia::LoadBlueprints` through `Resource::GetTextReader`; a missing file is `AppReleaseAssert("Couldn't load multiwinia.txt")` (fatal). `data/multiwinia-testbed.txt` replaces it only under `TESTBED_ENABLED` [B:DEAD] [C] `code/multiwinia.cpp:Multiwinia::LoadBlueprints`.

### 4.2 Grammar

```
mw_file   := { blank | gametype }
gametype  := 'GAMETYPE' NAME EOL { param } 'END' EOL        ; NO blank or comment-only line between GAMETYPE and END
param     := PARAMNAME MIN MAX DEFAULT CHANGE EOL            ; WORD F32 F32 F32 INT — MISSING ⇒ CRASH
```

* The top-level keyword is only debug-asserted to be `GAMETYPE` (`stricmp`); in release **any** first token starts a game type [C].
* Inside a block the parser does `ReadLine(); GetNextToken()` with no `TokenAvailable` check, so a blank or comment-only line inside a block passes `NULL` to `stricmp(param,"END")` (crash). `END` is case-insensitive.
* `NAME`, `PARAMNAME`: `strcpy` into `char[256]`; phrase ids are derived as `multiwinia_gametype_<lower(NAME)>` and `multiwinia_param_<lower(PARAMNAME)>` [C] `MultiwiniaGameBlueprint::MultiwiniaGameBlueprint`, `MultiwiniaGameParameter::MultiwiniaGameParameter`.

## [→ 29_data_formats_reference] 6. Preferences (`preferences.txt`, `data/default_preferences.txt`, `user_input_preferences.txt`) [B:FULL]

### 6.1 Files and life cycle [C] `code/lib/preferences.cpp:PrefsManager`, `code/app.cpp:App::App`, `App::GetPreferencesPath`

|---|---|---|---|---|

Life cycle: `App::App` parses `init.dat`, then constructs `g_prefsManager = new PrefsManager(GetPreferencesPath())` [C]. `Load()` reads the file; if it does not exist (or fails the first-line check below) it calls `CreateDefaultValues()` — in the latter case it also saves immediately. Because the manager is created before `main.dat` is parsed, a packaged install finds `default_preferences.txt` only if it is a loose file [I, from archive order; P14 §31.5.3].

### 6.2 Line grammar (reader side)

Each physical line is first cleaned by the `TextReader` (§1: `#` comment, CR/LF removal) and then reduced with `GetRestOfUnicodeLine()` (leading space/TAB/`:`/`,` stripped) before `PrefsManager::AddLine` sees it [C] `PrefsManager::Load`.

```
prefs_file := { line }
line       := empty_line | item_line
empty_line := text with no alphanumeric character before an optional '#'      ; IsLineEmpty
item_line  := { non_alnum } KEY SEPCHAR { WS | '=' } VALUE
KEY        := 1*ALNUM                         ; iswalnum (locale-dependent; ASCII letters/digits in practice); case-SENSITIVE
SEPCHAR    := exactly one character (normally ' ' or '='), overwritten and skipped
VALUE      := rest of the line, verbatim (trailing blanks kept)
```

Value typing (`PrefsItem::PrefsItem`) [C]:

| Condition on VALUE | Stored type | Conversion |
|---|---|---|
| first char is `-` or a digit, and VALUE contains no `.` | `TypeInt` | `wistringstream >> int` (leading number; junk after it ignored; failure → 0) |
| first char is `-` or a digit, exactly one `.` | `TypeFloat` | `wistringstream >> float` |
| first char is `-` or a digit, two or more `.` | `TypeString` | e.g. `127.0.0.1` |
| anything else | `TypeString` | verbatim |

Lookup is **type-strict**: `GetInt` on a float item, `GetFloat` on an int item, or `GetString` on a number returns the caller's default [C] `PrefsManager::GetInt/GetFloat/GetString`. Example: `DarwinianScaleFactor = 2` is an int and `GetFloat("DarwinianScaleFactor", …)` ignores it — always write floats with a decimal point. Duplicate keys: the first occurrence wins while loading a file ("Duplicate preference item %s. Ignoring"); lines added while `s_overwrite` is set (the `default_preferences.txt` pass) replace the existing item [C] `PrefsManager::AddLine`.

Edge cases [C]: (a) the **first line** of an existing file is validated — every character before the first space or `=` must lie in `'A'…'z'` (ASCII 65–122, so digits fail); otherwise the whole file is discarded, defaults are recreated and saved ("Unicode file fuck up check"); (b) a key that runs to the end of the line (no separator) makes the value pointer start one past the terminator (out-of-bounds read); (c) the value-skip loop's `value == L'\0'` test compares a pointer, not a character (harmless because `iswspace('\0')` is false).

### 6.3 Writer (`PrefsManager::Save`) [C]

1. All items' `m_hasBeenWritten` flags are cleared; the file is truncated and a UTF-16 BOM written.
2. For each remembered input line (`m_fileText`, in load order): an *empty* line is written verbatim **without adding a newline** — so blank lines and comments read from disk (already reduced to empty strings by the reader) vanish; only the literal `"\n"` lines added by `CreateDefaultValues` survive. For an item line the key is re-extracted by scanning to the first `=`: it starts at the first alphanumeric and ends at the **last non-alphanumeric character before `=`**; the item is written as `KEY = VALUE\n` (`%ls = %d`, `%ls = %.2f`, `%ls = %ls`).
3. Items not yet written are appended in `std::map` order (`wcscmp`, ordinal).

Hazards for implementers (all [C], reproduce only if byte-compatible output is required): a template line of the form `Key=1` (no character between key and `=`) is copied verbatim without a newline, glueing it to the next line and losing the following key on the next load; a template line containing no `=` makes the scan run past the end of the string; `Key  = 1` (two spaces) yields the key `"Key "` and creates a bogus empty item; floats are rounded to 2 decimals; a `%` inside a copied line is interpreted as a format specifier.

### 7.3 Spec grammar (driver chain) [C] `code/main.cpp:InitialiseInputManager`, each `code/lib/input/inputdriver_*.cpp:parseInputSpecification`

The token list is offered to the drivers in registration order; the first that returns a success state wins, otherwise the error of the driver that got furthest is reported. Order: `Conjoin`, `Chord`, `Invert`, `Idle`, `W32` (key/mouse), `XInput` (only if `XINPUT1_3.dll` loads), `Prefs`, `Value`, `Alias`. This order makes `&&` bind loosest, then `++`, then `not`.

```
spec        := conj
conj        := part { '&&' part }                      ; ≥1 '&&' required for this driver; ≤1 part may be non-BOOL
part        := chord | unary                           ; each part is re-parsed by the whole chain
chord       := leafnc '++' leafnc { '++' leafnc }      ; expands to N conjunctions: part i "down", others "pressed"; BOOL only
unary       := ('not' | '!') unary | leaf              ; 'not' case-insensitive; operand must be BOOL
leaf        := 'key' KEYNAME BCOND
             | 'mouse' MBUTTON BCOND
             | 'mouse' ('axes' | 'wheel') ACOND
             | 'XInput' XBUTTON ( BCOND | 'repeat' )
             | 'XInput' XANALOG ACOND [ 'with' 'sensitivity' N ]      ; N integer 1…200, default 100
             | 'XInput' XDIR ( BCOND | 'repeat' )                     ; sensitivity fixed at 100
             | ('idle' | 'Idle' …) ( 'atleast' | 'reaches' ) SECONDS  ; driver word case-insensitive; SECONDS integer > 0
             | 'idle' 'no' 'longer'                                  ; 'longer' case-insensitive
             | 'pref' [ 'not' | '!' ] PREFKEY | 'pref' '!'PREFKEY     ; key must EXIST in g_prefsManager at parse time
             | 'value' ( 'Pecan' | 'Hummingbird' )
             | 'alias' CONTROL
leafnc      := a leaf without its trailing condition word (the chord driver appends it)
BCOND       := 'down' | 'up' | 'pressed'
ACOND       := 'release' | 'position' | 'move' | 'zero' | 'read'
MBUTTON     := 'left' | 'right' | 'middle' | 'any'
XBUTTON     := 'leftbumper' | 'rightbumper' | 'dpadleft' | 'dpadright' | 'dpadup' | 'dpaddown' | 'a' | 'b' | 'x' | 'y'
             | 'start' | 'back' | 'plug' | 'lefttriggerb' | 'righttriggerb'           (type BOOL)
             | 'leftthumbstick' | 'rightthumbstick'                                  (type 2D|BOOL: click with BCOND)
XANALOG     := 'lefttrigger' | 'righttrigger'                                        (type 1D)
             | 'leftthumbstick' | 'rightthumbstick'                                  (type 2D|BOOL: axes with ACOND)
XDIR        := 'leftthumbstickleft' | 'leftthumbstickright' | 'leftthumbstickup' | 'leftthumbstickdown'
             | 'rightthumbstickleft' | 'rightthumbstickright' | 'rightthumbstickup' | 'rightthumbstickdown'
KEYNAME     := case-insensitive entry of getKeyNames()[0…KEY_TILDE=223] or 'any' (KEY_ANY=255): BACKSPACE TAB ENTER
               SHIFT CONTROL ALT PAUSE CAPSLOCK ESC SPACE PGUP PGDN END HOME LEFT UP RIGHT DOWN INSERT DEL 0…9 A…Z
               0_PAD…9_PAD ASTERISK PLUS_PAD MINUS_PAD DEL_PAD SLASH_PAD F1…F12 NUMLOCK SCRLOCK COLON EQUALS COMMA
               MINUS STOP SLASH AT OPENBRACE BACKSLASH CLOSEBRACE QUOTE TILDE, plus 'Unknown' (index 109)
```

Case sensitivity: driver words `key`, `mouse`, `XInput`, `pref`, `value`, `alias`, mouse/XInput control names, condition words, `with`, `sensitivity`, `atleast`, `reaches`, `no` are **case-sensitive** (`std::string ==`); `idle`, `not`, `longer`, key names and control names are case-insensitive [C] `W32InputDriver::acceptDriver`, `XInputDriver::acceptDriver/getControlID`, `IdleInputDriver::acceptDriver/getConditionID`, `InputDriver::getDefaultConditionID`, `W32InputDriver::getKeyId`, `ControlBindings::getControlID`.

Condition typing: `getDefaultConditionID(name, type)` scans the 8-entry table {`down`,`up`,`pressed`: BOOL; `release`,`position`,`move`,`zero`,`read`: ANALOG} for a name whose type matches the control's type. **An unknown or type-mismatched condition word does not fail**: the scan stops on the NULL terminator (index 8 < `NumInputConditions` 10) and returns `COND_DOWN` with the spec type set to 0 [C] `code/lib/input/inputdriver.cpp:InputDriver::getDefaultConditionID`. Examples in shipped files: `XInput lefttrigger repeat`, `XInput righttrigger repeat` (analog + `repeat`) parse as "down". Key names containing a space (`unknown 0`…) can never be written because specs are whitespace-split; `META` (index 224 > `KEY_TILDE`) is unreachable [C].

Parser states (`InputParserState`, `code/lib/input/inputdriver.h`): `STATE_ERROR`, `STATE_WANT_DRIVER`, `STATE_WANT_CONTROL`, `STATE_WANT_COND`, `STATE_WANT_MODIFIER`, `STATE_WANT_OPTIONAL`, `STATE_BAD_EXTRA`, then `STATE_DONE`/`STATE_OVERSTEP`/`STATE_CONJ_ERROR` (success = `PARSE_SUCCESS(state)`); a trailing surplus token yields `STATE_OVERSTEP` for single-word drivers (`alias`, `pref`, `value`) [C] respective drivers. Semantics of each condition and driver at run time: [→ 06] P10 §1.3–§1.6.

### 8.2 Line grammar

```
lang_file   := { blank | phrase_line }
phrase_line := KEY [ SEP TEXT ]
KEY         := first token, narrow separator set " \t\n\r:,"; looked up case-INSENSITIVELY
SEP         := 1*( ' ' | TAB | ':' | ',' | FF(UTF-16 only) )
TEXT        := rest of line (GetRestOfUnicodeLine), after §1 cleaning — a '#' anywhere ends the text
```

Rules [C] `ParseLanguageFile`:

1. Duplicate KEY (case-insensitive): **last definition wins** (old phrase deleted). Shipped duplicates: `buildingname_grenadeturret`, `multiwinia_help_title_crates` (all full files), plus `multiwinia_help_breakformation`, `multiwinia_help_clearinfo` in Italian.
2. Escape: the two characters `\n` become **space + newline** (`" \n"`). No other escape exists; any other backslash sequence (e.g. `\N` in German) stays literal; there is no way to write `#`, a leading space/`:`/`,`, or a literal `[` … `]` pair (§8.3).
3. Post-processing: if the last character is a newline it is removed; if the character before last is CR or FF it is replaced by NUL. An empty TEXT (key alone on the line) reads index −1 (UB; occurs once in French, German and Russian).
4. Encoding: UTF-16 files are decoded unit-by-unit (no surrogate pairs); single-byte files are Latin-1 (§1.6). Narrow mirrors (used by legacy `char*` callers) turn code units > 255 into `?`.
5. Unterminated last line: dropped for UTF-16 and archive files (§1.2) — `multiwinia_exclamation` is lost from `japanese.txt` and `korean.txt`, `multiwinia_option_5_5_1` from `portuguese.txt` [C] survey.

### 8.3 Inline markup (expanded once per input mode when the tables are built) [C] `LangTable::RebuildTable`, `buildCaption`, `consumeMarker`, `consumeIfMarker`, `consumeKeyMarker`, `consumeOtherMarker`, `markerLength`

```
text      := { char | marker }
marker    := '[IFMODE KEYBOARD]' | '[ELSE]' | '[ENDIF]'        ; nestable conditional; mode word compared case-insensitively
           | '[KEY' CONTROLNAME ']'                           ; e.g. [KEYCAMERAFORWARDS]
           | '[' PHRASEKEY ']' | '[ ' PHRASEKEY ']'            ; inline another phrase (leading space variant emits a space)
```

* `[IFMODE KEYBOARD]` … `[ELSE]` … `[ENDIF]`: text between is written only in keyboard mode / only in gamepad mode. Only the word `KEYBOARD` is understood; `[IFMODE GAMEPAD]` increments the nesting depth but falls through to the phrase-reference rule (consumed, writes nothing). No shipped phrase uses IFMODE [C] survey.
* `[KEY<name>]`: `<name>` (1…63 chars) is looked up with `InputManager::getControlID` (case-insensitive) and replaced by the bound input's description noun (`getBoundInputDescription`). An unknown control or unbound control falls through to the phrase-reference rule and is removed. English uses 87 such markers [C].
* `[<key>]`: `<key>` (1…63 chars, lower-cased) is replaced by the mode-specific raw phrase (`<key>_kbd`/`<key>_xin` preferred, else `<key>`), recursively expanded; an unknown key is removed. **Any `[…]` pair is therefore markup**: `multiwinia_notpermitted  [Not permitted]` (English) expands to an empty string [C] by code path; the id is not referenced anywhere in `code/` (grep), so there is no visible effect [C].
* Output is capped at `SEPULVEDA_MAX_PHRASE_LENGTH` = 1024 code units; marker contents ≥ 64 code units are removed unexpanded.
* Hazard: an unterminated `[` makes `markerLength` return 0 and `consumeOtherMarker` move the read position back by one, so `buildCaption` **never terminates** [C]. No shipped phrase has one [C] survey.
* Hazard: `consumeMarker`/`consume*Marker` copy the partially built caption through freshly allocated, uninitialised buffers (`UnicodeString::Resize` copies only `min(old,new)` units of an empty source); correct output depends on heap block reuse [I]. A re-implementation should simply append the expansion to the output buffer.

### 8.4 Mode-specific keys and lookup [C] `RebuildTable`, `LookupPhrase`, `RawLookupPhrase`, `DoesPhraseExist`

* Suffixes: `<key>_kbd` (keyboard/mouse) and `<key>_xin` (Xbox controller). Two hash tables are built, one per `InputMode` (`INPUT_MODE_KEYBOARD`, `INPUT_MODE_GAMEPAD`). For mode M the table key is the id without suffix; a suffixed variant for M wins over the plain id; an id existing only with the *other* suffix yields an empty string in M. Ids starting with `part_` are excluded from the tables (usable only inside markers). Shipped: 120 `_kbd` and 75 `_xin` ids in each full file, no `part_` ids [C] survey.
* `LANGUAGEPHRASE(id)` → `LookupPhrase`: current-mode table; **a missing id returns the id string itself** (no fallback to English). `RawLookupPhrase` returns `ERROR (<id>)`. `ISLANGUAGEPHRASE(id)` tests the current-mode table [C]. With a partial language (Japanese, Korean, Portuguese) most UI text therefore shows raw ids [C] by code; [U] whether a retail edition shipped complete files for these languages (resolve: inspect the retail `language.dat`).
* Phrase-id conventions derived by code (non-exhaustive list of generators): `multiwinia_gametype_<type>`, `multiwinia_param_<param>`, `buildingname_<Type>`, `entityname_<Type>`, `researchname_<Type>`, `cratename_<Name>`, `multiwinia_credits_<n>` (n = 1, 2, … until the first missing id), `bootloader_credits_<n>` [C] respective `GetNameTranslated`/`GetTypeNameTranslated`, `code/UI/GameMenuWindow.cpp:ReadCredits`.

### 8.5 Runtime placeholders inside TEXT

`*<letter>` is replaced at display time by `UnicodeString::ReplaceStringFlag(letter, value)` (every occurrence of `*` followed by that letter) [C] `contrib/systemiv/lib/unicode/unicode_string.cpp:UnicodeString::ReplaceStringFlag`. Letters substituted somewhere in `code/`: `F`, `G`, `H`, `P`, `R`, `S`, `T`, `U`, `X` (most common `*T` = team/player name or text, `*S` = seconds); English also contains `*K`, `*A` (leaderboard strings with no live substitution found) and the whole-phrase macro `*BETATESTERS` (§5) [C] grep. Phrases are never used as printf format strings (grep), so `%` is literal.

## [→ 29_data_formats_reference] 14. Re-implementation guidance (format layer of the new game)

* Keep **one** tokeniser (§1) for all legacy-compatible text formats, but fix its traps: process an unterminated last line in every reader, accept UTF-8 (with or without BOM) in addition to UTF-16, add a quoting rule for free-text values, and never return a NULL token to a parser — every block parser must check token availability and report `file:line: expected <field>` instead of crashing.
* Make block parsers **table-driven** (keyword → field descriptor with type, default, range), so that the menu scanner and the level loader share one definition (the original has two divergent parsers, §2.4.3).
* Separate shipped content from save data: no `redshirt2` obfuscation; versioned headers on every runtime-written file; preferences written atomically with typed values and full float precision.
* Treat every name used as an identity (`GAMETYPE` names, building/entity/research type names, phrase ids, control names) as a stable *id* distinct from display text, and validate cross-references at load time (mount names, building link ids, objective location names).
* For determinism, parse numeric simulation fields with an explicit, platform-independent decimal parser and round to the simulation's numeric type (the original's F32 rounding, §Conventions).

## [→ 29_data_formats_reference] 29.B1 Shared text-file conventions (`TextReader`)

Every text format in this draft (`.shp`, `.anim`, `gestures.txt`, gesture demos, `effects.txt`, `stats.txt`, `sounds.txt`) is read through the SystemIV `TextReader` family [C] `contrib/systemiv/lib/filesys/text_stream_readers.cpp:TextReader::CleanLine`, `TextReader::GetNextToken`, `TextFileReader::ReadLine`, `TextDataReader::ReadLine`; `contrib/systemiv/lib/unicode/unicode_text_stream_reader.cpp:UnicodeTextFileReader::UnicodeTextFileReader`, `UnicodeTextReader::CleanLine`. Live in [B:FULL] (all files `vcproj_build=all` in `manifest.csv`).

**Reader selection** [C] `code/lib/resource.cpp:Resource::GetTextReader`: for a resource name `N` the loose file `data/N` is tried first, then the archive entry `data/N` (§29.B16). In both cases a UTF-16 reader is constructed first; if the first two bytes are `FF FE` (UTF-16LE) or `FE FF` (UTF-16BE) the file is Unicode, otherwise it is re-opened as an 8-bit reader. All text files in this draft's scope are 8-bit ASCII with CRLF line ends (sole exception: `data/shapes/primaryupgradeport.shp`, LF-only) [C] `file(1)` survey.

**Line processing** (`CleanLine`, applied to every physical line):
1. *Obfuscation check* (first line only): if the line starts with `redshirt2` (case-insensitive) the reader strips those 9 characters and decrypts this and every following line (§29.B2).
2. *Merge-conflict guard*: three or more adjacent `<`/`>` characters trigger `AppDebugAssert` ([B:DEBUG] only).
3. *Comment strip*: the first `#` and everything after it is removed (no escape; `#` cannot appear in any value).
4. The first `\n` and the first `\r` are replaced by NUL (so CRLF and LF files both work).

**Line length**: buffer starts at 128 chars and doubles; doubling from 65 536 raises `AppReleaseAssert("Text file contains line with more than 65536 characters")` → maximum line length 65 536 bytes [C] `TextReader::DoubleMaxLineLen`. Longest line in scope: `data/gestures.txt` 2 767 chars [C].

**Tokenisation** (`GetNextToken`): separator set `" \t\n\r:,"` (space, tab, LF, CR, colon, comma) unless a parser calls `SetSeperatorChars` (none in this scope). A token is a maximal run of non-separators; leading separators are skipped; returns `NULL` at end of line. Consequences used by every grammar below: `Positions: 8`, `Positions 8` and `Positions,8` are identical; `0,1,2` is three tokens; **no value may contain a space, tab, colon, comma or `#`** (file/sample/marker/event names included). `TokenAvailable()` is true iff a non-separator remains on the line. `GetRestOfLine()` returns the remainder after skipping separators (not used by the formats here).

**Number parsing**: C `atoi`/`atof` (C locale, `.` decimal point, no error detection — junk parses as 0, `atof(NULL)` crashes) except where noted; `iv_atof(s) = iv_trunc_low_nibble(atof(s))` is used where the value feeds the deterministic simulation (`.shp` geometry, `stats.txt`) [C] `contrib/systemiv/lib/math/math_stubs.cpp:iv_atof`.

**End-of-file quirk** [C] `TextDataReader::ReadLine`: when reading from an archive, the call that copies the *last* line returns `false` if that line is not terminated by `\n`; every `while (ReadLine())` loop in this draft therefore silently drops an unterminated final line in packaged builds, while the loose-file reader (`TextFileReader`) returns it. All shipped files in scope end with CRLF [C] survey, so the quirk is latent. **Rule for authors: always end text files with a newline.**

**Blank lines**: whether a blank or comment-only line is legal depends on the parser loop: loops that start with `if (!TokenAvailable()) continue;` skip them; loops of the form `ReadLine(); tok = GetNextToken(); while (stricmp(tok, "END"))` crash on them (`stricmp(NULL, …)`). Each grammar below states which applies.

## [→ 29_data_formats_reference] 29.B2 "redshirt2" obfuscated text

Purpose: light obfuscation of text files written into the user profile in non-debug builds (saved `game.txt` / mission files) [C] `code/level_file.cpp:LevelFile::SaveMissionFile`, `code/global_world.cpp:GlobalWorld::SaveGame` (writer `new TextFileWriter(path, true)` unless `TARGET_DEBUG`). No file under `data/` is obfuscated [C] grep for `redshirt2` in `data/` = 0 hits. Any text resource *may* be obfuscated because detection is automatic in `TextReader::CleanLine`.

Encoding [C] `contrib/systemiv/lib/filesys/text_file_writer.cpp:TextFileWriter::TextFileWriter`, `TextFileWriter::printf`; decoding `text_stream_readers.cpp:TextReader::CleanLine`:

| Item | Value |
|---|---|
| Magic | ASCII `redshirt2` written at file start **without** a newline (the first plaintext line follows on the same physical line) |
| Key table `s_offsets[16]` | 31, 7, 9, 1, 11, 2, 5, 5, 3, 17, 40, 12, 35, 22, 27, 2 |
| Counter | `k` starts at 0 for the file and persists across lines; it is advanced **before** use and only for encoded characters: `k = (k+1) mod 16` |
| Encoded characters | bytes with signed value > 32 (i.e. 33..127); space, tab, CR, LF and bytes ≥ 128 pass through unchanged and do not advance `k` |
| Encode | `e = p + s_offsets[k]; if (e >= 128) e -= 95` |
| Decode | `p = e - s_offsets[k]; if (p < 33) p += 95` |

Because the first offset used is `s_offsets[1] = 7`, a re-implementation must pre-increment. Minimal example: the plaintext line `WIDTH 800` is stored as the physical line `redshirt2^RE_J =53` (the space passes through and does not advance `k`). The scheme is a printable-range Vigenère; it offers no security. A new game should use a real format (e.g. a binary save with a version header) and need not keep this. A Unicode writer variant exists (`code/unicode/unicode_text_file_writer.cpp:UnicodeTextFileWriter::UnicodeTextFileWriter`) and the UTF-16 reader recognises `L"redshirt2"` [C] `contrib/systemiv/lib/unicode/unicode_text_stream_reader.cpp:UnicodeTextReader::CleanLine`.

## [→ 29_data_formats_reference] 29.B3 `.shp` — hierarchical flat-shaded mesh ("shape")

**Purpose.** All 3-D models (buildings, units, props) are rigid hierarchies of *fragments* (sub-meshes with their own local transform, which code may animate) plus named *markers* (attachment frames). Text format, case-insensitive keywords [C] `code/lib/shape.cpp:Shape::Load`, `ShapeFragment::ShapeFragment(TextReader*,char const*)`, `ShapeFragment::Parse*Block`, `ShapeMarker::ShapeMarker(TextReader*,char const*)`. There is **no binary variant**: the only loader is this text parser and the exporter writes text [C] (no other `Shape` constructor reads data).

**Files.** `data/shapes/*.shp` — 139 files, 441 fragments, 425 markers in total; max 20 fragments and 38 markers per file; max marker depth 7; max 10 632 triangles, 6 245 vertices/positions and 121 colours in one fragment; 39 files use the strip encoding, 98 the triangle-list encoding, none mixes both, and 2 contain markers only (`battlecannonbase.shp` 8 markers, `portal.shp` 5 markers — their markers hang off `SceneRoot`) [C] survey `X1b_shp_survey.py` (per-shape table in `OUT/_work/drafts/P12_shapes.csv`). 138 files are CRLF, `primaryupgradeport.shp` is LF-only. Loaded as `data/shapes/<lower-cased name>` (loose, then archive `main.dat`) [C] `code/lib/resource.cpp:Resource::GetShapeCopy`, `DoesShapeExist`.

### Grammar (EBNF over *lines* after §29.B1 cleaning; `NAME`, `INT`, `F` are single tokens)

```ebnf
shp_file        = { top_line } ;
top_line        = fragment_def | marker_def | other_line ;          (* other_line: any line whose first token is
                                                                       neither FRAGMENT nor MARKER is ignored; blank ok *)
fragment_def    = "Fragment" NAME EOL , { frag_line } , geometry_end ;
frag_line       = "ParentName" NAME EOL
                | "up"    F F F EOL | "front" F F F EOL | "pos" F F F EOL
                | "Positions" INT EOL , { id_line_pos }              (* exactly INT records, see below *)
                | "Normals"   INT EOL , { id_line_vec }
                | "Colours"   INT EOL , { id_line_col }
                | "Vertices"  INT EOL , { id_line_vtx }
                | ignored_line ;                                     (* e.g. "right x y z", blank, unknown keyword *)
geometry_end    = strips_block | triangles_block ;                    (* parsing of the fragment STOPS here *)
id_line_pos     = INT F F F EOL ;          (* id, x, y, z *)
id_line_vec     = INT F F F EOL ;          (* id, nx, ny, nz *)
id_line_col     = INT INT INT INT EOL ;    (* id, r, g, b  (0..255) *)
id_line_vtx     = INT INT INT EOL ;        (* id, positionId, colourId *)
strips_block    = "Strips" INT EOL , strip , { strip } ;              (* INT strips, ids 0..INT-1 in order *)
strip           = "Strip" INT EOL , [ "Material" NAME EOL ] , "Verts" INT EOL , vref_lines ;
vref_lines      = { vref_line } ;          (* lines of tokens "v<INT>"; total token count = Verts *)
triangles_block = "Triangles" INT EOL , { tri_line } ;               (* exactly INT physical lines *)
tri_line        = INT INT INT EOL ;        (* vertex indices a b c, conventionally "a,b,c" *)
marker_def      = "Marker" NAME EOL , { marker_line } , ( "MarkerEnd" EOL | EOF ) ;
marker_line     = "ParentName" NAME | "Depth" INT | "front" F F F | "up" F F F | "pos" F F F | ignored_line ;
```

Record-block rules [C] `ParsePositionBlock`, `ParseNormalBlock`, `ParseColourBlock`, `ParseVertexBlock`:
- Lines whose first token does not start with a decimal digit are skipped inside id blocks (blank/comment lines allowed).
- Ids must be `0, 1, 2, …` consecutively. A wrong id in **Positions** silently abandons the block (positions stay empty; the fragment then has no geometry and a bounding radius from 0 points); in Normals/Colours/Vertices it is only a debug assert (release writes the record at the wrong index).
- EOF inside a block is a debug assert; release continues with garbage.
- **Triangles** are read as exactly T `ReadLine` calls with no skipping: a blank or comment line inside crashes (`atoi(NULL)`). All shipped triangle blocks are dense [C] survey.
- **Strips**: in `ParseAllStripBlocks` lines not starting with `Strip` are skipped; after `Strip k` the *next physical line* must be `Material …` or `Verts n` (the `Material` name is read and discarded); `n > 2` asserted; vertex tokens must start with `v` (debug assert) and `index < Vertices` (debug assert).
- A fragment without a `Strips`/`Triangles` line never terminates: the fragment loop does not recognise `Fragment`/`Marker`, so it swallows the rest of the file. (Not present in shipped data [C] survey: fragments = geometry blocks = 441.)
- `Normals` are parsed but **always discarded** — `GenerateNormals` replaces them with one face normal per triangle. Every shipped file has `Normals: 0` [C] survey.
- `right` lines (15 occurrences in `fieldgun_shell.shp`, `garbagecollector.shp`, `gunturret.shp`) and `# N triangles, M strips, ratio R` comments are ignored legacy exporter output [C] survey + parser.

### Derived data computed at load [C] `ShapeFragment::RegisterPositions`, `GenerateNormals`
- Synthetic root fragment `SceneRoot` (identity transform, no geometry) holds all fragments whose parent is `SceneRoot`; markers are attached to their parent fragment and their `m_parents` chain is filled by walking up to `SceneRoot`.
- Bounding sphere per fragment: centre = AABB centre of its positions; radius = max distance to centre (`iv_sqrt`). A vertical-cylinder alternative is computed but never enabled (`m_useCylinder` stays false).
- Face normals: `n = normalise((b−a) × (c−b))` per triangle (flat shading); rendering emits the same normal at all three corners.
- `m_positionsInWS` scratch array is sized by **Vertices** but indexed by position id in accurate hit tests [C] `ShapeFragment::RayHit`, `SphereHit` → heap overrun when Positions > Vertices; shipped cases: `carryweights.shp` (two fragments, 100 positions / 50 vertices) and `sporegenerator.shp` (43/42) [C] survey. A re-implementation should size it by Positions.

### Transform semantics [C] `ShapeMarker::GetWorldMatrix`, `ShapeFragment::Render`
`Matrix34` stores rows `r,u,f,pos` (row-vector convention). A fragment's world matrix = `frag.T × parent.T × … × root.T × objectTransform`; a marker's = `marker.T × parents[Depth-1].T × … × parents[0].T × objectTransform`. Code may set per-fragment `m_angVel`/`m_vel` for prediction, or overwrite `m_transform` on shapes obtained with `GetShapeCopy(name, animating=true)` [C] `Resource::GetShapeCopy`.

## [→ 29_data_formats_reference] 29.B4 `.max` sources and the shape tool chain (`tools/ShapeExporter`, `tools/3DGeometry`)

**`.max` files.** `data/shapes/source/*.max` — 133 files, 12 246 016 bytes total; Microsoft OLE2 *Compound File Binary* containers (`D0 CF 11 E0 A1 B1 1A E1`, "Composite Document File V2") = Autodesk 3ds Max scene files [C] magic bytes. Never read by the game; excluded from packaging by the `shapes/source` line of `tools/multiwinia_exclusions.txt` and by the extension filter of `main.dat` [C] `tools/build_multiwinia_data.bat`. 110 have a same-named `.shp` (case-insensitive); 23 `.max` have no `.shp` of that name (e.g. `AnthillNew`, `BattleCannon`, `GlobalWorld`, `LaserTroop`, `SpiderLegLower` — several correspond to renamed shapes such as `spider_leg_lower.shp`, `laser_troop.shp`, `flying_egg.shp`) and 29 `.shp` have no `.max` (e.g. `armyant2/3`, `carry*`, `clonelab`, `portal`, `pulsebomb`, `wallbuster`, `trunkport_mp`) [C] name comparison. Treat as Introversion art sources (IP register).

**ShapeExporter** (3ds Max scene-export plug-in, DLL; `ShapeExporter.dsp`/`ShapeExporterDLL.dsp`, MSVC 6) [C] `tools/ShapeExporter/ShapeExporter.cpp`, `ShapeExporter.h`, `DllEntry.cpp`:
- Registers extension `shp`, description "Futurewar Shape Format v1.0", version 100; class id `0x3288038e, 0x40eff553`.
- `DoExport`: creates root fragment `"scene root"` (spaces are stripped → `sceneroot`), walks the Max node tree from the scene root's children with depth 1; nodes whose name starts with `marker` (case-insensitive) become markers with `Depth` = recursion depth, all other geometry nodes become fragments (non-geometry, target, zero-face nodes skipped; children of a marker are not visited).
- Coordinate conversion (Max Z-up → game Y-up): every point `(x,y,z)` → `(x, z, −y)`. Local transform = `nodeTM × inverse(parentTM)` decomposed into rows `r,f(=Max row 1),u(=Max row 2),pos`; **fragment** `front` is stored **negated** `(−f.x, −f.z, f.y)` (which makes `r = u × f` hold for an un-rotated node), **marker** `front` is stored un-negated `(f.x, f.z, −f.y)` [C]; i.e. a marker's `front` points along the Max helper's local +Y while a fragment's points along −Y [I interpretation]. Both normalised.
- Positions de-duplicated within distance 0.001 (squared 1e-6); colours from Max vertex colours (×255, truncated) de-duplicated exactly, else one colour from the material diffuse ×255, else the node wire colour; vertices = unique (position, colour) pairs; faces written as a triangle list (`Triangles`), normals not exported (`Normals: 0`). `nvtristrip.h` is included but unused in this version → the 39 strip-format shipped shapes came from an older exporter [I].
- **Stale vs engine**: calls a 3-argument `ShapeFragment(name, parent, false)` constructor that no longer exists in `code/lib/shape.h` (2 arguments), and relies on the broken `WriteToFile` formats (§29.B3) → the exporter does not build against this tree as-is [C]. `[B:DEAD]` for the game.

**3DGeometry** [C] `tools/3DGeometry/main.cpp`, `3DGeometry.dsp`: an Allegro/AllegroGL test harness (camera fly-through with WASD/QE, grid, `DrawLine`, `DrawSphere`, `DrawTriPlane`) used to visualise ray–sphere / sphere–triangle intersection maths from `code/lib/math_utils` with hard-coded test vectors. Not a format and not a converter; [B:DEAD].

No example is given for `.max` (proprietary Autodesk binary); the exporter's output contract is the `.shp` grammar of §29.B3.

**Recommended new-engine stance** [I]: replace `.shp` with a modern interchange (glTF 2.0 with node hierarchy, per-vertex colour, no UVs, empties for markers); keep the semantics "fragment = node with local TRS, marker = named empty", the `(x,z,−y)` axis conversion only if importing old art.

|---|---|---|

### Byte layout accepted by the loader (little-endian)

| Offset | Size | Field | Loader behaviour |
|---|---|---|---|
| 0 | 2 | `bfType` | must be `0x4D42` "BM" (debug assert only) |
| 2 | 4 | `bfSize` | read, ignored |
| 6 | 2+2 | reserved | ignored |
| 10 | 4 | `bfOffBits` | **not used for seeking**; used only to derive the palette size |
| 14 | 4 | `biSize` | 40 → Windows header; 12 → OS/2 header; anything else (e.g. V4 108 / V5 124) → debug assert, release continues with an uninitialised header (garbage/crash) |
| 18.. (Win) | 4,4,2,2,4,4,4,4,4,4 | width, height, planes, bitCount, compression, sizeImage, xppm, yppm, clrUsed, clrImportant | only width, height (as **unsigned** — negative/top-down heights are unsupported), bitCount, compression used; `clrUsed` ignored |
| 18.. (OS/2) | 2,2,2,2 | width, height, planes, bitCount | compression = 0 |
| 54 (Win) / 26 (OS/2) | `ncol`×4 / ×3 | palette, B,G,R(,reserved) | `ncol = (bfOffBits−54)/4` (Win) or `(bfOffBits−26)/3` (OS/2); no clamp to 256 (overflow if larger); palette alpha = 255 |
| immediately after the palette | — | pixel rows, **bottom-up**, file row 0 → `m_lines[0]` (the bottom row; matches GL texture origin) | read sequentially; any gap between palette and `bfOffBits` would be decoded as pixels |

Pixel row decoding:

| bitCount | Per pixel | Row padding consumed? | Notes |
|---|---|---|---|
| 4 | nibble index; **high nibble = left pixel** | **no** | rows must be a multiple of 4 bytes (width multiple of 8) or the image shears; odd widths write one pixel past the row |
| 8 | byte index | **no** | width must be a multiple of 4 |
| 24 | B,G,R; alpha := 255 | yes (`(4 − 3w) & 3` bytes) | |
| 32 | B,G,R,A (alpha used as-is) | n/a | the only way to ship a real alpha channel |
| other (1, 16) | — | — | debug assert; release leaves pixels uninitialised |

`biCompression` must be `BI_RGB` (0) — debug assert only. **RLE4/RLE8 are not decoded**: in release `textures/shaman_background.bmp` (RLE8, 512×512, used by `code/shaman_interface.cpp:ShamanInterface::RenderBackground`) would be read as raw indices, running past the data (`BinaryDataReader::ReadU8` returns 0xFF at EOF) → corrupt image [C] parser + survey. Whether a player can reach the Shaman interface in Multiwinia is owned by P09/P05 ([U] here).

Extension rule: `BitmapRGBA::Initialise(reader, type)` asserts `type == "bmp"` (debug only) and always calls `LoadBmp` — `.jpg`, `.tex`, `.dds` (named in the archive `dir` filters for Xbox/legacy) cannot be decoded on PC [C].

### Texture pipeline rules (what a texture *name* means)
[C] `code/lib/resource.cpp:Resource::GetTextureWithFlags`, `GetTexture`, `GetTextureWithAlpha`, `ProcessBmp`, `GetBitmap`, `DoesTextureExist`; `code/lib/bitmap.cpp:ConvertToTexture`.
1. A texture name is a path **relative to `data/` including the extension** (e.g. `sprites/darwinian.bmp`, `terrain/water_default.bmp`). Code builds most names with literal `.bmp` or `"." TEXTURE_EXTENSION`, where `TEXTURE_EXTENSION` is `#define`d unconditionally as `"bmp"` [C] `code/lib/universal_include.h:TEXTURE_EXTENSION`; 33 uses (help images, thumbnails, mode images). [I] The macro exists so an Xbox build could switch to `tex` (DXT `.tex` files are produced only by the Xbox branch of the data script via `convert_bmp_to_tex.cmd`, which is absent from the tree).
2. Lookup order: (a) texture cache `m_textures` keyed by the **exact name string** (case-sensitive `hash_map<std::string>`); (b) registered bitmap store `m_bitmaps` (run-time generated images such as `water_lightmap`, case-insensitive); (c) file: name lower-cased → `GetBinaryReader` → loose `data/<name>` then archive (§29.B16). Missing → `AppReleaseAssert("Failed to load texture %s")` (fatal) — callers that may miss guard with `DoesTextureExist` (e.g. thumbnails fall back to `thumbnails/default.bmp`, `code/UI/MapImageButton.h:MapImageButton::Render`).
3. **Flags are not part of the cache key**: the first request for a name decides mask/alpha/mipmap processing for all later requests [C].
4. Flags: `GetTexture(name, mipmapping=true, masked=true, compressed=false)` → `WithMipmaps|WithMask`. **Default is masked**, so every BMP requested through the default overload is colour-keyed.
5. `WithMask` → `ConvertPinkToTransparent`: pixels exactly equal to RGBA (255,0,255,**255**) become (128,128,128,0) — the colour key. 24-bit and paletted files always have alpha 255 so the key works; a 32-bit pixel with RGB magenta and alpha ≠ 255 is not keyed.
6. `WithAlpha` (`GetTextureWithAlpha`, 9 call sites) → `ConvertColourToAlpha`: alpha := **green** channel, RGB := white (luminance-style masks authored as greyscale). The header comment says "luminance"; code uses green only (docs-vs-code below).
7. Upload: RGBA8; GL path requires power-of-two only when `GL_ARB_texture_non_power_of_two` is missing or pref `ManuallyScaleTextures` ≠ 0, square when `GL_ARB_texture_rectangle` is missing; D3D path always power-of-two. Resizing rounds **up** to the next power of two (bilinear blit) and the power-of-two rule overrides max-size down-scaling; wrap CLAMP, MAG LINEAR, MIN LINEAR_MIPMAP_LINEAR (even when not mip-mapped) [C] — full algorithm in P12 §25.2. Non-power-of-two assets shipped: 11 in `animations/`, 27 in `icons/`, 49 in `mwhelp/`, 21 in `textures/`, 9 in `terrain/` (`waves_*` 400×10), all 57 `thumbnails/` (400×300) [C] survey.
8. `GetBitmap(name)` (CPU access, used by ramps, animation panel sizes, fonts) caches the decoded bitmap under `name`; a later `GetTexture` on the same name finds it in the bitmap store and **modifies it in place** (pink→transparent) [C].

### PNG
No PNG reader. `WritePng`/`SavePng` (libpng, 8-bit RGB, rows flipped to top-down, `Z_BEST_SPEED`) are used for screenshots `screenshotN.png` [C] `code/lib/poster_maker.cpp:PosterMaker::SavePoster` and the Vista game-explorer thumbnail [B:DEAD, `TARGET_OS_VISTA`] `code/app.cpp:App::SaveRichHeader`. `SavePng` ignores its `_saveAlpha` argument [C]. `WriteBmp` writes 24-bit Windows BMPs (2835 px/m).

### Minimal valid example
A 2×2 24-bit BMP (70 bytes): `42 4D 46 00 00 00 00 00 00 00 36 00 00 00` · `28 00 00 00 02 00 00 00 02 00 00 00 01 00 18 00 00 00 00 00 10 00 00 00 13 0B 00 00 13 0B 00 00 00 00 00 00 00 00 00 00` · bottom row `FF 00 FF  00 00 FF  00 00` (pink key, red, 2 pad bytes) · top row `00 FF 00  FF 00 00  00 00` (green, blue). ## [→ 29_data_formats_reference] 29.B6 Terrain colour ramps (`data/terrain/landscape_*`, `water_*`, `waves_*`)

**Purpose.** Three per-level BMP look-up images colour the landscape, the flat sea texture and the animated wave mesh. A level names them in its `Landscape_StartDefinition` block with `landColourFile`, `wavesColourFile`, `waterColourFile` (single token each, file name only, resolved as `terrain/<name>`); defaults `landscape_default.bmp`, `waves_default.bmp`, `water_default.bmp` [C] `code/level_file.cpp:LevelFile::ParseLandscapeData` (keywords at L789–L799), `LevelFile` constructors (L1409–L1411). When the Christmas mod is active the three are forced to `landscape_icecaps.bmp`, `waves_earth.bmp`, `water_icecaps.bmp` [C] `code/landscape_renderer.cpp:LandscapeRenderer::LandscapeRenderer`, `code/water.cpp:Water::Water`, `Water::Render` (`Location::ChristmasModEnabled`).

**Files and pixel formats** [C] survey: 23 `landscape_*.bmp` 64×64 24-bit; 4 `water_*.bmp` 128×128 8-bit paletted; 9 `waves_*.bmp` 400×10 24-bit. No ramp uses the pink key. The code scales look-ups by the bitmap's actual width/height, so other sizes are legal.

### Landscape ramp — 2-D look-up (slope × height)
[C] `code/landscape_renderer.cpp:LandscapeRenderer::GetLandscapeColour`, `BuildColourArray`; loaded with `Resource::GetBitmap` (CPU only, no texture).

| Axis | Bitmap coordinate | Driven by | Mapping |
|---|---|---|---|
| x (column) | `x = int(u · width)`, clamped 0..width−1 | triangle slope: `gradient = normal.y` (1 flat … 0 vertical) | `u = (1 − gradient)^0.4` → **left column = flat, right column = vertical**; the 0.4 exponent devotes most columns to gentle slopes |
| y (row of `m_lines`, row 0 = first row stored in the file = **bottom row of the picture as viewed**) | `y = int(v · height)`, clamped | triangle centre height `h` (sea level 0) | `v = 1 − h/highest + jitter`, `highest` = max height-map value; jitter = `sfrand(0.45/(max(h,0)+2))` (uniform ±0.1125 at sea level, shrinking with height; RNG reseeded per triangle from its x,z) → **top row of the picture = sea level, bottom row = highest peak of this map** |

So an artist paints the ramp with the sea-level beach at the top, peaks at the bottom, flat ground on the left and cliffs on the right. Colour is per triangle (flat-shaded, written to the provoking vertex) and alpha is forced 0 in "negative" render mode. Burn-patch darkening and the full algorithm are in P11 §23.11.

### Water texture — tiled RGB(A) texture
[C] `code/water.cpp:Water::Render`, `Water::RenderFlatWaterTiles`. Requested as `GetTexture("terrain/<waterColourFile>", mipmaps=true, masked=true)`, bound on texture unit 0 with `GL_REPEAT` wrap, LINEAR / LINEAR_MIPMAP_LINEAR filters, `GL_MODULATE`. It is mapped onto the flat sea quad grid at y = −9.0 covering `[−sizeX/2, 1.5·sizeX] × [−sizeZ/2, 1.5·sizeZ]` (twice the land extent) with texture coordinates running from `t/30` to `t/30 + 30` on both axes, `t = g_gameTimer.GetAccurateTime()` seconds → the image **repeats 30 times across the sea plane and scrolls diagonally by 1/30 of a tile per second** (one full tile every 30 s). Unit 1 multiplies by the generated shore mask `water_lightmap`. The pixel content is therefore an ordinary seamlessly-tiling colour texture (no axis semantics).

### Waves ramp — 1-D colour table
[C] `code/water.cpp:Water::Water` (table build), `Water::UpdateDynamicWater`, `code/water.h:Water::GetColour`.
- Only **row y = 1** of the bitmap is read (the second row from the bottom of the picture as viewed): `table[x] = pixel(x, 1)`, alpha := 255 (0 in negative mode), `numColours = width` (400 for all shipped files). The other 9 rows are ignored.
- Per animated-water vertex: `brightness = (h_prev1 + h_prev2 + h_this) · 4.0 · (1 − depth) + shoreNoise`, where `h` are wave heights, `depth` ∈ [0,1] the shore-mask depth (1 = open sea), `shoreNoise = ((1−depth) + sfrand(1−depth)·0.25)·250`; the two vertices of a strip pair mix 0.7/0.3; `index = Round(brightness)` clamped to [0, width−1] → `colour = table[index]`.
- Hence **x = 0 is calm open water; increasing x is brighter, wave-crest and shoreline foam** (open sea at rest maps to index 0; the shoreline adds up to ~250) [I: interpretation of the formula; arithmetic C].

### Minimal valid examples
- `landscape_example.bmp`: 64×64 24-bit; columns 0–40 green→brown, columns 41–63 grey rock; top rows sand, bottom rows snow.
- `waves_example.bmp`: 400×2 24-bit; row 1 (top row as viewed in a 2-row image) gradient from dark blue (x=0) to white (x=399); row 0 unused.
- `water_example.bmp`: any 128×128 seamlessly tiling texture.

- 9 landscape ramps are not referenced by any level (`beach`, `containment`, `field`, `icecaps_peaked`, `marble2`, `mine2`, `ridges`, `volcanic`, `volcanicplain`) [C] P11 grep; `waves_*` usage is P11's to tabulate.

### Grammar
```ebnf
anim_file   = { header_line | object | ignored_line } ;          (* blank lines skipped *)
header_line = ( "WIDTH" INT | "HEIGHT" INT | "START" F | "STOP" F ) EOL ;
object      = "BEGIN" "Object" EOL , { keyframe | ignored_line } , "END" EOL ;
keyframe    = "BEGIN" "Keyframe" EOL , { kf_field | ignored_line } , "END" EOL ;
kf_field    = ( "TIMEINDEX" F | "IMAGENAME" NAME | "XPOS" F | "YPOS" F | "COLOUR" INT
              | "SCALE" F | "ANGLE" F | "FLIPHORIZ" INT | "ALPHA" INT ) EOL ;
```
Keywords case-insensitive (`stricmp`); unknown keywords ignored at every level; header lines may appear anywhere outside objects (last wins). Hazards: a `BEGIN` line without a second token, or a keyframe field without a value, crashes (`stricmp/atof(NULL)`); `IMAGENAME` is copied into a 256-byte buffer unchecked. An `END` at top level is ignored.

### Field table
| Field | Type | Units | Default | Range in shipped data | Semantics |

### Playback semantics (route also to 26) [C] `CalculateObjectProperties`, `CalculateRampUpAndDown`
For each object (drawn in file order, so later objects are on top) at time `t`:
1. `left` = keyframe with the greatest time ≤ t (first in file order on ties); `right` = keyframe with the smallest time ≥ t.
2. Neither → not drawn. Only `right` → **not drawn** (the object does not exist before its first key). Only `left` → hold `left`. Same keyframe, or `|right.t − left.t| < 0.01` → `left`.
3. Otherwise `lin = (t − left.t)/(right.t − left.t)`; `ramp = ease(lin)` with `ease(f) = 2f²` for f < 0.5, `1 − 2(1−f)²` otherwise (smooth in/out; documented in `docs/ImplementationNotes/RampUpAndDown.gif` [I]). **XPOS, YPOS, SCALE use `ramp`; ANGLE and ALPHA use `lin`** (ALPHA truncated to int); IMAGENAME, COLOUR, FLIPHORIZ step (taken from `left`).
4. Draw a textured quad, blend state left from `RenderBackground` (`SRC_ALPHA, ONE_MINUS_SRC_ALPHA`), clipped to the panel rectangle (`Renderer::Clip`).

## [→ 29_data_formats_reference] 29.B12 `data/sounds.txt` — sound-event blueprints (full grammar)

**Purpose.** Binds every (sound source, event name) to zero or more sound instances with playback parameters, and defines sample groups. Parser [C] `code/sound/soundsystem.cpp:SoundSystem::LoadBlueprints`, `ParseSoundEvent`, `ParseSoundEffect`, `ParseSampleGroup`, `NewSampleGroup`, `GetSampleGroup`; `code/sound/sound_parameter.cpp:SoundParameter::Read`, `GetParameterType`, `GetLinkType`, `GetUpdateType`; writer `SaveBlueprints`, `WriteSoundEvent`, `WriteSampleGroup`, `SoundParameter::Write` ([B:DEBUG] sound editor). Runtime semantics of every field: P16 §10.1–10.8 (route 10). Validated against the shipped file by `OUT/_work/scripts/X1b_sounds_grammar.py` (this agent's independent state-machine; P16's `P16_parse_sounds.py` produced `P16_sound_events.csv`).

### Grammar
```ebnf
sounds_file    = { blank_or_comment | source_block | samplegroup | ignored_top } ;
source_block   = source_kind TYPENAME EOL , { blank_or_comment | event_block } , "END" EOL ;
source_kind    = "ENTITY" | "BUILDING" | "OTHER" ;
event_block    = "EVENT" EVENTNAME EOL , { event_field } , "END" EOL ;      (* NO blank/comment lines inside *)
event_field    = "SOUNDNAME"     NAME EOL
               | "SOURCETYPE"    INT EOL          (* 0 Sample, 1 SampleGroupRandom *)
               | "POSITIONTYPE"  INT EOL          (* 0 Type2D, 1 Type3DStationary, 2 Type3DAttachedToObject, 3 TypeInEditor *)
               | "INSTANCETYPE"  INT EOL          (* 0 Polyphonic, 1 MonophonicRandom, 2 MonophonicNearest *)
               | "LOOPTYPE"      INT EOL          (* 0 SinglePlay, 1 Looped, 2 LoopedADSR *)
               | "TEAMMATCHTYPE" INT EOL          (* 0 AllTeams, 1 MyTeamOnly, 2 EnemyTeamOnly *)
               | "PRIORITY"      INT EOL          (* parsed and discarded *)
               | "MINDISTANCE"   F EOL            (* world units *)
               | param_field_name param_spec EOL
               | effect_block ;
param_field_name = "VOLUME" | "FREQUENCY" | "ATTACK" | "SUSTAIN" | "RELEASE" | "LOOPDELAY" ;
effect_block   = "EFFECT" EFFECTNAME EOL , { PARAMLABEL param_spec EOL } , "END" EOL ;   (* ≤ 13 params, positional *)
param_spec     = "PARAMETER" ( fixed | ranged | linked ) [ update_type ] ;
fixed          = "TypeFixedValue"   F ;                     (* value *)
ranged         = "TypeRangedRandom" F F F ;                 (* lower upper smooth *)
linked         = "TypeLinked"       F F F F F LINKNAME ;    (* inLower outLower inUpper outUpper smooth link *)
LINKNAME       = "Nothing" | "HeightAboveGround" | "Xpos" | "Ypos" | "Zpos" | "Velocity" | "CameraDistance" ;
update_type    = "UpdateConstantly" | "UpdateOncePerLoop" ;  (* absent → UpdateConstantly *)
samplegroup    = "SAMPLEGROUP" GROUPNAME EOL , { ANYWORD SAMPLENAME EOL } , "END" EOL ;  (* NO blank lines inside *)
ignored_top    = any other first token EOL ;                 (* e.g. a stray "END" at top level *)
```
Lexical rules: §29.B1 (all keywords and enumerator names case-insensitive via `stricmp`; `#` comments allowed only where blank lines are allowed).

Parser-structure facts [C]:
- **Blank/comment lines**: allowed at top level and between `EVENT` blocks inside a source block (that loop tests `TokenAvailable`); **forbidden inside `EVENT`, `EFFECT` and `SAMPLEGROUP` bodies** (`ReadLine(); GetNextToken(); stricmp(...)` → NULL crash). The shipped file obeys this (0 hazards) [C] survey.
- Inside a source block any non-`END` line is treated as an `EVENT` header (debug-assert only) and its second token becomes the event name.
- Source `TYPENAME` resolution (case-insensitive): `ENTITY` → `Entity::GetTypeId` over the 27 names `InvalidType, LaserTroop, Engineer, Virii, Squadie, Egg, SporeGenerator, Lander, Tripod, Centipede, SpaceInvader, Spider, Darwinian, Officer, ArmyAnt, Armour, SoulDestroyer, TriffidEgg, AI, Shaman, Harvester, Nuke, Tentacle, Meteor, Tank, SpaceShip, DropShip`; `BUILDING` → `Building::GetTypeId` over the 75 names of `Building::GetTypeName` (`Invalid` … `SmokeMarker`, P06); `OTHER` → `SoundSourceBlueprint::GetSoundSoundType` over `Laser, Grenade, Rocket, AirStrikeBomb, Spirit, Sepulveda, Gesture, Ambience, Music, Interface, CratePowerup, MultiwiniaInterface`. An unknown name returns −1 and is stored at index −1 (debug assert only → memory corruption in release). A **duplicate** source block for the same type replaces the earlier one (debug assert only) — not present in shipped data.
- Object name for the instance's event identifier = the TYPENAME token as written (≤127 chars; `"sample group"` for groups); identifier = `"<TYPENAME> <EVENTNAME>"` [C] `SoundInstance::SetEventName`.
- `SOUNDNAME` is lower-cased in place and its **last `.extension` stripped** (`RemoveExtension`) before storing (≤255 chars). With `SOURCETYPE 0` it names a sample file stem; with `SOURCETYPE 1` a `SAMPLEGROUP` name (looked up case-insensitively at play time; first match wins).
- Unknown event field → debug assert, then the line is skipped in release.
- `SoundParameter::Read`: if the type name is unknown, `m_type = −1` and no values are read; after the type-specific values, *if any token remains* it is taken as the update type (unknown → −1). Extra tokens beyond that are ignored. `Recalculate()` is called immediately.
- `EFFECT EFFECTNAME`: matched case-insensitively against `effects.txt` names (unknown → debug assert, type −1 → crash when used). Each following line: first token = label (ignored), rest = `param_spec`; parameter *k* binds to blueprint parameter *k* by position (shipped: every block lists exactly the blueprint's parameter count in blueprint order) [C] survey.
- `SAMPLEGROUP`: first token of each member line is ignored (shipped files always write `SAMPLE`); member name lower-cased and extension-stripped. Group names are stored as written (≤255). **Duplicate group names are allowed** and both kept; look-ups return the first: shipped `officercreate` is defined twice (identical) [C] survey + `GetSampleGroup`.

| Field | Type | Default (`SoundInstance` ctor) | Valid values | Shipped usage (296 EVENT blocks) |

| Convention | Rule |
|---|---|
| Source form | plain-text HLSL compiled **at run time** with `D3DXCompileShader` (no precompiled blobs, flags 0, no macros) |
| Entry points | `vs_main` in every vertex shader, `ps_main` in every pixel shader |
| Profiles | the device's best: `D3DXGetVertexShaderProfile(device)` / `D3DXGetPixelShaderProfile(device)` |
| Extensions | `.vs` vertex, `.ps` pixel, `.ps3` pixel variant requiring a `ps_3_x` profile (chosen when the profile string's 4th char > '2'; falls back to `.ps` if creation fails) [C] `water_reflection.cpp` |
| Includes | `#include "x"` resolved by `MyD3DXInclude` as resource `shaders/x` (loose or archive); only `globals.h` is included (by the three `deform*.ps`) and defines `DEFORM_PRECISION 10` |
| Pairing | a `Shader` object = one `.vs` + one `.ps` path; failure of either compile is debug-asserted; `Shader::Create` raises `AppReleaseAssert("Shader create error…")` if either object could not be created |
| Constants | set by name through the D3DX constant tables of both stages (`SetFloat`, `SetUniform`, `SetMatrix`, `SetBool`, `SetInt`) |

## [→ 29_data_formats_reference] 29.B16 `.dat` archives (RAR)

**Container.** A `.dat` file is a standard **RAR 4.x archive** (signature `52 61 72 21 1A 07 00` "Rar!"), produced by `tools/Rar.exe` and read by the bundled UnRAR 3.30 beta 1 source (`contrib/unrar/version.h:RARVER_MAJOR/RARVER_MINOR/RARVER_BETA`: 3.30 β1, 14 Nov 2003; built as the `unrar` sub-project; supports unpack methods 1.5, 2.0/2.6 and 2.9) [C] `contrib/unrar/unrar.cpp:UncompressedArchive::UncompressedArchive`, `contrib/unrar/extract.cpp:CmdExtract::ExtractArchive` (modified to unpack into memory via `AllocNewFile` + `DataIO.SetUnpackToMemory`), `contrib/unrar/unpack.cpp:Unpack::DoUnpack`. The repository's `animator.dat` is an example: archive flags 0x0008 (solid), file headers unpack version 29, method 0x35 (best), names `data\animations\…` [C] RAR header walk. No runtime `.dat` is committed to the tree.

**Encryption / obfuscation.** None: every `ParseArchive` call passes `password = NULL`, and the build script never uses `-p`/`-hp` [C] `code/app.cpp:App::App`, `App::Initialise`, `App::LoadSounds`, `tools/build_multiwinia_data.bat`. (UnRAR's password support is compiled in but unused.) Text files inside may in principle be "redshirt2"-obfuscated (§29.B2) — none are.

**How archives are built** [C] `tools/build_multiwinia_data.bat`, `tools/build_language_dat.bat` (full step list in P14 §31.6):

| Archive | RAR command | Entry names | Content rule |
|---|---|---|---|
| `init.dat` | `rar a -m5 -s -idp init.dat @list` | `data\…` | `tools/init.list` (14 shaders, `sprites/darwinian.bmp`, `textures/ivlogo.bmp`) |
| `language.dat` | `rar a -m5 -s -idp` | `data\…` | `*.bmp *.dds *.tex *.txt` from the selected `*language.list` |
| `main.dat` | `rar a -m5 -s -idp` | `data\…` | all `data/` minus `completeExclusions`, minus any path containing `sounds/`, filtered to `*.tex *.bmp *.jpg *.shp *.txt *.vs *.ps *.ps3 *.h *.anim` (Xbox adds `*.wmv`) — so `.max`, `.psp`, `.grd`, `.ogg` never enter it |
| `menusounds.dat` | `rar a -m2 -s -idp` | `data/…` | `tools/menu_sounds.txt` |
| `sounds.dat` | `rar a -m2 -s -idp` | `data/…` | `tools/sounds.txt` |
| `sounds2.dat` | `rar a -m2 -s -idp` | `data/…` | every `.ogg` of `listAll` (i.e. not in `completeExclusions`) |
| `patch.dat`, `branding.dat` | not built in tree | | loaded if present |
| `ambx.dat` | `build_ambx_dat` (script absent) | | shipped by `tools/InstallerScript_retail_crashreporter_euro.iss` but **never parsed** by the code [C] grep |

Switches [I, RAR CLI]: `a` add, `-m5` best / `-m2` fast (Ogg already compressed), `-s` solid, `-idp` no percentage display, `@file` list file.

**How the runtime opens them** [C] `code/lib/resource.cpp:Resource::ParseArchive`, `GetUncompressedFile`, `GetTextReader`, `GetBinaryReader`, `GetShapeCopy`, `ListResources`; `contrib/unrar/unrar.cpp:MemMappedFile::MemMappedFile`; `contrib/systemiv/lib/tosser/hash_table.cpp:HashTable::HashFunc`, `GetIndex`.
1. Load order: `init.dat` (in `App::App`, before preferences), then `language.dat`, `main.dat`, `patch.dat`, `menusounds.dat`, `branding.dat` (`App::Initialise`), then `sounds.dat`, `sounds2.dat` (`App::LoadSounds`) [C] `code/app.cpp:App::App` L217, `App::Initialise` L334–L340, `App::LoadSounds` L502–L503. A missing file is skipped silently; an exception during extraction drops that archive.
2. The **entire archive is decompressed into RAM** (`UncompressedArchive`, at most `MAX_FILES = 16384` entries; excess entries make `AllocNewFile` return NULL → crash in the modified extractor). Each entry becomes a `MemMappedFile {name, data, size}`; `\` → `/`; the name is `strlwr`-ed; **zero-size entries (and directory entries) are dropped** (and leaked).
3. Entries go into one global `HashTable<MemMappedFile*>`; an entry whose name already exists replaces the old one → **later archives override earlier ones** (effective precedence sounds2 > sounds > branding > menusounds > patch > main > language > init).
4. The table's hash masks the ASCII case bit (`& 0xDF`) and compares with `stricmp` → **archive look-ups are case-insensitive** regardless of the caller's spelling.
5. Every resource request for `N` (relative to `data/`) tries, in order: the loose file `data/N` (relative to the working directory; on Win32 `fopen` is case-insensitive; on other OSes `FindCaseInsensitive` walks the directory tree), then the archive key `data/N`. **Loose files always win over archives** — patching/modding by dropping files into `data/` works; the Darwinia mod-directory step (`<profile>/mods/<mod>/N`) is compiled out (`USE_DARWINIA_MOD_SYSTEM` undefined) [C].
6. `ListResources(dir, filter)` merges the loose directory listing with archive entries whose directory part equals `data/<dir>` (case-insensitive) and whose file part matches the wildcard filter (`*`, `?`; `Resource::WildCmp` is **case-sensitive**, archive names are lower case) [C]. Entries are inserted with `OrderedInsert` (`contrib/systemiv/lib/filesys/file_system.cpp:OrderedInsert`), which keeps case-sensitive `strcmp` order and skips exact duplicates **except against the last element** → a loose file and its archive twin can both appear (always when their case differs, e.g. loose `mp_koth_2P_1.txt` vs archive `mp_koth_2p_1.txt`) [C].

**Minimal valid archive (for tests).** `rar a -m5 -s test.dat data\stats.txt` → loaded by `ParseArchive("test.dat", NULL)` it serves resource `stats.txt` unless a loose `data/stats.txt` exists.

**New-engine note [I].** RAR is a proprietary format (creating RAR archives needs the licensed `rar` tool; UnRAR source has a licence forbidding RAR-compatible archivers). Replace with a zip/PAK-style archive or a custom indexed pack, keeping the semantics: ordered mount list, last-mounted wins, loose-file override, case-insensitive keys, forward-slash names relative to `data/`.
