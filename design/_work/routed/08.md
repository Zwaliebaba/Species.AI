## [→ 08_levels_and_level_design] 8.2 How a level is loaded

```mermaid
sequenceDiagram
  participant Net as ClientToServer
  participant Main as main loop (RunTheGame)
  participant LS as loading-screen work queue
  participant Loc as Location
  participant LF as LevelFile
  Net->>Main: NET_DARWINIA_START_GAME → m_requestedLocationId=999, m_gameMode=GameModeMultiwinia, m_requestedMission="null"
  Note over Net: map name arrives earlier as game option GAMEOPTION_MAPNAME → g_app->m_requestedMap
  Main->>LS: EnterLocation → Add(DoEnterLocation)
  LS->>Loc: new Location(); (if PERMITTED_MAPS) IsMapPermitted(CalculeCRC(map))
  LS->>Loc: Init(mission, map)
  Loc->>LF: LoadLevel → new LevelFile(mission, map, ext=="txt")
  LF->>LF: UpdateDifficultyFromPreferences (forces m_difficultyLevel = 0)
  alt text map
    LF->>LF: if mission != "null": ParseMissionFile
    LF->>LF: ParseMapFile("levels/"+map, else <profile>/maps/+map)
  else .mwm
    LF->>LF: ParseMWMFile(<profile>/maps/+map)
  end
  LF->>LF: GenerateAutomaticObjectives
  Loc->>Loc: AppSeedRandom(1); InitLights; InitLandscape (§23); new Water; teams/colours; InitBuildings; grids; new Clouds; routing systems
```

## [→ 08_levels_and_level_design] 8.5 Saving (editor and Darwinia save games)

`LevelFile::Save()`: if mission name does not contain "null" → `SaveMissionFile`; if map name does not contain "null" → map written to `levels/<map>` through the resource writer under `TARGET_DEBUG`, else to `<profile>/maps/<map>` [C]. ## [→ 08_levels_and_level_design] 8.6 MapFile (`.mwm` custom map container)

[C] `code/mapfile.{h,cpp}`. On-disk layout:
```
int32 little-endian   uncompressedLength        (WriteNetworkValue<int>; little-endian on PC)
bytes                 zlib compress2(level 9) of Directory::Write() output
```
The `Directory` (tosser key/value tree, serialisation owned by P15/X1a) is named `"NewMap"` and holds:

| Key | Type | Content |
|---|---|---|
| `MapData` | void (bytes) | the full map text as written by `LevelFile::Save(TextWriter*)` → `SaveMapFile` |
| `MapLandscapeTexture` / `MapWavesTexture` / `MapWaterTexture` / `MapThumbnail` | void | raw `RGBAColour` pixels, `w·h·4` bytes, BitmapRGBA row order |
| `<texKey>Filename` | string | resource name to register the bitmap under (e.g. `terrain/landscape_x.bmp`) |
| `TextureHeight<n>`, `TextureWidth<n>` | int | dimensions; n = 1-based index over the textures actually stored, in the order landscape, waves, water, thumbnail |

Save (`MapFile::Save`, [B:EDITOR]): file name = map name with the last 4 chars replaced by `.mwm` (done with an overlapping `sprintf` into the same buffer — undefined behaviour [I]); a terrain texture is embedded only if `Resource::GetUncompressedFile(terrain/<name>)` fails (i.e. it is not a stock file); the thumbnail is embedded if `m_thumbnailFilename != "default.bmp"` (read from `<profile>/maps/`). Load (`MapFile::MapFile(path, loadTextures)`): reads the length, inflates, copies `MapData`; with `loadTextures` registers each embedded bitmap via `Resource::AddBitmap(filename)` so the landscape/water code finds it under its normal name. `ParseMWMFile` always loads textures. Robustness: the reader passes the full file length (not length−4) to `uncompress` and reads 4 bytes past the end [I]; no checksum.

## [→ 08_levels_and_level_design] 8.7 MapCRC (map identity)

What is checksummed [C] `code/level_file.cpp:LevelFile::CalculeCRC`, `contrib/systemiv/lib/math/filecrc.cpp:FileCRC`, `ReadFileData`, `contrib/unrar/crc.cpp:CRC`:
- the raw bytes of resource `levels/<filename>` as read by `BinaryReader::ReadU8` until EOF, **plus one trailing 0xFF byte** (the EOF read is stored before the loop notices EOF), capped at 100 001 bytes (static 100 000-byte buffer — a file > 100 000 bytes would overflow it by one byte [I]; the largest shipped level is 46 085 bytes);
- CRC-32, reflected polynomial 0xEDB88320, **initial value 0, no final XOR** (unrar's `CRC(0, buf, len)`); returned as `int`; −1 if the file cannot be opened (menu then flags the map as custom: `MapData::m_customMap`).
- Verified: recomputing all 87 `data/levels/*.txt` with this definition reproduces every `MAPID_*` constant in `code/mapcrc.h` exactly [C] (`scripts/P11_mapcrc.py`, 87/87 OK).

`code/mapcrc.h` is generated by `tools/MapCRC/main.cpp:GenerateMapCRCs` (lists `*.txt`, macro name = file name minus `.txt`, `.`/`-`/space → `_`, upper-cased, `#define MAPID_<NAME> 0x%08x`) — "Auto-generated … DO NOT MODIFY" [C].

Why [C]: a content-derived ID for maps used by (1) `MapData::m_mapId` (menu map list; `App::GetMapID(gameMode, crc)` → index), (2) the metaserver game listing (`NET_METASERVER_MAPCRC`; clients resolve the name with `GameMenu::GetMapName(mode, crc)`) `code/network/server.cpp`, `code/UI/GameMenuWindow.cpp`, (3) demo gating — `DemoLimitations::m_allowedMapCRCs`, default `{MP_KOTH_2P_1, MP_KOTH_4P_1, MP_CTS_2P_1, MP_KOTH_3P_1, MP_ROCKETRIOT_3P_1}` or a list from the metaserver (`NET_METASERVER_DEMOMAPS`) `code/network/demo_limitations.cpp`, (4) compile-time `PERMITTED_MAPS` whitelists of non-FULL targets (`code/lib/universal_include.h`, checked in `DoEnterLocation` and the menu), (5) hard-coded tutorial/quick-start map picks (`MAPID_MP_KOTH_2P_1`, `MAPID_MP_KOTH_3P_1` in `code/UI/GameMenuWindow.cpp`). The game itself is started by **file name** (`GAMEOPTION_MAPNAME`), and nothing compares map CRCs between peers before simulation [I] (grep shows no CRC exchange in the start-game path) — a modified local map file would desync rather than be rejected (see §D.4).

### E1.2 Is any editor functionality reachable in FULL? — **No** [C chain]

1. The Multiwinia main-menu entry `MultiwiniaEditorButton` (caption `taskmanager_mapeditor` = "Map Editor"; `m_inactive` in demo → click goes to `PageBuyMeNow`) is created only under `#ifdef LOCATION_EDITOR` in `code/UI/GameMenuWindow.cpp` [C].
2. The only other opener of `MultiwiniaWindow` is `MultiwiniaButton` in the Darwinia-era `MainMenuWindow` (`code/interface/mainmenus.cpp`), which is only registered by the Esc handler inside `GlobalWorldGameLoop` (`code/main.cpp`); that loop sets `g_app->m_atMainMenu = true` and then breaks on its first check `if (g_app->m_atMainMenu) break;` → never runs its body [C].
3. Every other setter of `m_requestToggleEditing = true` is gated: `DebugKeyBindings::EditorButton` (`LOCATION_EDITOR`, and its menu button additionally needs `modsEnabled`, which is hard-wired false without `USE_DARWINIA_MOD_SYSTEM`), `code/interface/mods_window.cpp` (`USE_DARWINIA_MOD_SYSTEM`) [C].

5. Consequently FULL players cannot create, edit, list or host custom `.mwm` maps (the `.mwm` listing in `code/game_menu.cpp` and the network custom-map request are also `LOCATION_EDITOR`-only) [C].

Design stance for the new game: treat the editor as a first-class capability recovered from code (it is complete enough to author every Multiwinia map feature listed in E4), but note it never shipped.

### E2.4 Per-mode behaviour [C] `LocationEditor::AdvanceMode*`

**ModeNone** — on `SelectLocation`: building hit → `RequestMode(ModeBuilding)`; else instant unit → `ModeInstantUnit`; else camera mount → `ModeCameraMount`; else land tile under mouse → `ModeLandTile`; else flatten area → **`ModeLandTile`** (sic, not LandFlat). The clicked object is not selected (selection reset by `RequestMode`); a second click selects it.

**ModeLandTile** (tiles = `levelFile->m_landscape.m_tiles`):
```text
newSel = TileSelect ? IsPosInLandTile(mouse3D) : -1
if no selection and newSel != -1:
    select newSel; m_tool = ToolMove; m_newLandscape = tile origin; waitingForRelease = true
    open LandscapeTileEditWindow "editor_landscapetile" (w = landscape window w, h = 150, x = its x, y = its y - 150 - 10)
if selection:
    if TileDrop and m_newLandscape != tile origin:
        if m_moveBuildingsWithLandscape: every building with tile.pos <= b.pos.xz <= tile.pos+size moves by delta
        tile origin = m_newLandscape; Landscape::Init(levelFile landscape); rebuild Water
    if TileSelect:
        if newSel == selection: grab = mouse3D - tile origin           (start drag)
        else: deselect; tool None; close "editor_landscapetile" and "editor_guidegrid"
    elif TileDrag: m_newLandscape = mouse3D - grab                     (preview only; ints)
```

**ModeLandFlat** (areas = `m_flattenAreas`): select on `TileSelect` → window `"Flatten Area"` (`LandscapeFlattenAreaEditWindow`, w = landscape window w, h = 100, x = 0, y above). With selection: `TileSelect` on same area → grab offset from centre; on another/none → `m_selectionId = newSel` and close the window (so selecting a different area leaves it selected without a window — quirk); `TileDrag` → centre.xz = mouse − grab **live** (no regeneration until *Generate*).

**ModeBuilding**:
```text
if "editor_buildingid" window exists and cursor in it: return
newSel = TileSelect ? DoesRayHitBuilding(cursor ray) : -1
if no selection and newSel != -1:
    select; open BuildingEditWindow "editor_buildingid" (w = create window w, h = 140, above it); waitingForRelease
    if building is TypeTree: open TreeWindow "editor_treeditor" (h = 230) above that
elif selection:
    if TileSelect:
        newSel == -1        -> close "editor_buildingid", deselect
        m_tool == ToolLink  -> building.SetBuildingLink(newSel); m_tool = ToolNone
        (clicking another building otherwise does nothing — must click empty ground first)
    elif TileDrag (newSel is -1 on drag frames):
        ToolMove   -> building.m_pos = mouse3D (y = terrain height)
        ToolRotate -> building.m_front.RotateAroundY(cursor dX × 0.01 rad/pixel)
```
In editor mode `Location::GetBuilding(id)` resolves against `levelFile->GetBuilding(id)` [C] `code/location.cpp:Location::GetBuilding`, so all edits act on the level-file objects that `LevelFile::Save` writes.

**ModeLight**: if `m_selectionId` is a valid index into `location->m_lights` and `TileDrag` → front vector rotated about Y by `dX × 0.05 rad/pixel`, `Light::SetFront` [C]. Selection is made only from the Lights window.

**ModeInstantUnit**: select on `TileSelect` hit → `InstantUnitEditWindow "editor_instantuniteditor"` (h = 160, above create window); with selection: `TileSelect` not on the selected unit → deselect + close; `TileDrag` with `ToolMove` → `posX/posZ = mouse3D.xz`.

**ModeCameraMount**: on `TileSelect`, only if window `"editor_cameraanim"` exists and its `m_newNodeArmed`: hit mount → append `CamAnimNode{mountName = strdup(mount name)}` to animation `m_selectionId`, disarm, rebuild that window. Since nothing creates `"editor_cameraanim"` (§E4.10), this path is unreachable even in an EDITOR build [C].

### E2.5 Editor rendering [C] `LocationEditor::Render` (called after `Location::Render` from `code/renderer.cpp` when `m_editing`)

Order:
1. Object lighting on; every level-file building `Render(0.0)`; lighting off. `Create()` builds controls first and calls `DarwiniaWindow::Create()` last. `m_guideGridPower = tile.GuideGridGetPower()`; `gridW = m_w − 80` (220), `gridH = m_h − 100` (230); `pixelsPerSample = min(gridW, gridH) / numColumns` (0 if power is 0).

| Control | Pos | Type | Target / action | Step | Range |
|---|---|---|---|---|---|

| `editor_resolution` | (100,25) w 150 | VC int, callback = generate | `m_guideGridPower` (log₂ resolution) | 1 | [0, 5] |

| `editor_maxheight` | (100,65) | VC float | `m_maxHeight` (write multiplier), default 1.0 | 0.01 | [0, 1] |
| `editor_guidegrid` | (10,90, gridW, gridH) | `GuideGrid` canvas (EclButton) | paint, below | | |
| `editor_freehand` / `editor_flatten` / `editor_binary` | x = gridW+15 = 235, y = 90/107/124, w 60 | tool buttons | `m_tool` = Freehand (default) / Flatten / Binary; active tool drawn pressed | | |

Canvas rendering: each sample a grey quad (value 0–255 → grey), blue `(0,0,0.8)` lines through sample centres, white border, and yellow outlines (intensity = brush effect) for samples under the brush, additive.

Painting algorithm (runs inside `Render`, i.e. once per rendered frame) [C] `GuideGrid::HandleMouseInput`, `GetToolEffect`:
```text
m = (cursor - canvasOrigin) / pixelsPerSample                       # in samples
effect(x,z) = 1                     if toolSize == 1 and floor(m) == (x,z)
            = 0                     if |(x+0.5, z+0.5) - m| > toolSize/2
            = 1 - d / (toolSize/2)  otherwise
active if (LMB held [EclipseLMousePressed] or RMB pressed this frame [EclipseRMousePressed = mouse right down])
          and cursor inside the canvas
for each sample with effect > 0:
  Freehand: new = cur + toolSize*effect (LMB) | cur - toolSize*effect (RMB)
  Flatten:  new = cur - toolSize*effect if cur > 20 else cur + toolSize*effect   # pulls toward 20
  Binary:   new = 255 (LMB) | 0 (RMB)
  new = clamp(new, 0, 255) * m_maxHeight → stored (unsigned char)
```
Notes: left-button painting is continuous and frame-rate dependent; right-button only applies one step per click (edge-bound); `m_maxHeight < 1` rescales every touched sample on every application. Painting changes terrain only after *Generate*. How the guide grid shapes the tile: 23 (P11 `LandscapeTile`).

### 1.2 File pairing [C]
- **Multiwinia maps are single files.** Every Multiwinia start sets the mission to `"null"` (`code/network/clienttoserver.cpp` `NET_DARWINIA_START_GAME` handler: `strcpy(g_app->m_requestedMission, "null")`; also `code/interface/multiwinia_window.cpp` Play/Edit buttons). `LevelFile::LevelFile` parses a mission file only when the name is not `"null"`, then `ParseMapFile` — so an `mp_*` file carries both "map" blocks (options, landscape, tiles, flatten areas, lights, static buildings) and the "mission" blocks the map parser also accepts (camera mounts/animations, instant units, primary objectives) [C] `code/level_file.cpp:LevelFile::LevelFile`, `ParseMapFile(TextReader*)`.
- **Darwinia levels are pairs** `map_<location>.txt` + `mission_<location>_<name>.txt`; the pairing is by location name (Darwinia global world `Locations` table `id avail mapFile missionFile`, and `GlobalWorld::LoadGame` lists `mission_<location>*.txt`) [C] `code/global_world.cpp:GlobalWorld::LoadGame`, `ParseLocations`. 11 maps have ≥1 mission; `map_launchpad` pairs with `mission_launchpad.txt` (no `_name` suffix).

### 1.3 Two on-disk section layouts of `mp_*` files [C] data, [I] origin

### 1.4 How the menu finds maps [C] `code/game_menu.cpp:GameMenu::CreateMapList`, `AddMap`

1. `Resource::ListResources("levels/", "mp_*", false)` — lists `data/levels/` on disk plus pre-loaded archive entries whose directory part equals `data/levels/` exactly; **non-recursive**, so `levels/old/` is never listed [C] `code/lib/resource.cpp:ListResources`. Results are merged with `OrderedInsert` (strcmp ascending, duplicates dropped; its loop stops at `Size()-1`, so a name sorting after every entry but the last is appended at the end — order is "nearly alphabetical") [C] `contrib/systemiv/lib/filesys/file_system.cpp:OrderedInsert`.
2. Only `.txt` files are opened (`GetExtensionPart == "txt"`); `AddMap` reads lines until `MultiwiniaOptions_EndDefinition` with **case-sensitive** key matching (`strcmp`) for `Name`, `GameTypes`, `NumPlayers`, `Author`, `Description`, `PlayTime`, `Difficulty`, `CoopMode`, `ForceCoop`, `OfficialLevel` [C].
3. `GameTypes`: **every** token that exactly equals a blueprint name (`Domination`, `KingOfTheHill`, `CaptureTheStatue`, `Assault`, `RocketRiot`, `Blitzkrieg`, `TankBattle` — order of `GAMETYPE` blocks in `data/multiwinia.txt`) adds the map to `m_maps[mode]`. (In contrast `LevelFile::ParseMultiwiniaOptions` keeps only the **first** token.) A file with no matching token is discarded with "Warning: Discarded map %s because it didn't contain a game type" [C].
4. `MapData::CalculeMapId()` = `LevelFile::CalculeCRC(fileName)`; −1 (file unreadable as a resource) marks `m_customMap` [C] `code/UI/MapData.cpp`.
5. `AddMap` returns `m_officialMap`; the count of official maps goes to `AchievementTracker::SetNumLevels` [C].
6. Per mode, a stable bubble sort orders maps by `NumPlayers` ascending, then difficulty rank (substring `basic`=1, `inter`=2, `advan`=3, absent=0) [C]. Resulting retail order: §9.1.
7. Under `LOCATION_EDITOR` only, `<profile>/maps/*.mwm` custom maps are added the same way [B:EDITOR] [C].

Downstream identity uses [C]: `App::GetMapID(mode, crc)` → index into `m_maps[mode]`; `GameMenu::GetMapName(mode, crc|file)` → string id `<stem>_name` (`GetMapNameId` strips `.txt`, appends `_name`; `GetMapDescriptionId` appends `_description`) — looked up in the language table, whose `HashTable` hashes with the case bit masked (`& 0xDF`) and compares with `stricmp`, so `mp_assault_3p_1_name` finds the key `mp_assault_3P_1_name` [C] `contrib/systemiv/lib/tosser/hash_table.cpp:HashFunc`, `GetIndex`. The level's own `Name` option is shown only for custom maps (`m_customMap`) [C] `code/UI/LevelSelectButton.h:Render`. `PlayTime` is shown as `"0:%02d"` (hours:minutes) and copied into the mode's time option on selection; 0 → blueprint default [C] `LevelSelectButton::MouseUp/Render`.

Thumbnail lookup [C] `code/UI/MapImageButton.h:Render`, `code/UI/GameMenuWindow.cpp:PreloadThumbnails`: `thumbnails/<file stem>.` + `TEXTURE_EXTENSION` (`"bmp"`), passed through `strlwr`; if `DoesTextureExist` fails, `thumbnails/default.bmp`. Archive entry names are lower-cased when `.dat` archives are indexed (`strlwr(file->m_filename)` in `code/lib/resource.cpp`), so mixed-case thumbnail files resolve [I]. The `LevelFile::m_thumbnailFilename` field (default `"default.bmp"`) is used only by the `.mwm` writer [C] `code/mapfile.cpp`.
