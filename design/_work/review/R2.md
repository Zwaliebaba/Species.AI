Overall, both documents are very accurate. I checked almost every constant, probability, timer and formula I sampled, and they match the code; many match to the tick (I re-ran float countdowns and the grenade throw table, and the results agree exactly). The defects are concentrated in a few interaction rules.

**Three most serious findings**

1. **The Shockwave damage band in 02 §2.7 is wrong, and it contradicts 04 §6.11.** 02:313 and the table at 02:315–326 say the ring grows from 35, the band is 20 wide and a stationary target is hit ≈5 times (ring "35→60/85/65/…/135"). The code decrements `m_life` before computing the radius, and it only considers entities with XZ distance < r. So the first ring is at 39, the band is effectively 10 wide, and a target is hit 2–3 times (grenade 39→59, rocket 39→63, bomb 39→83, nuke/meteor 39→131) [`code/worldobject/weapons.cpp:890`, `:896`, `:899`, `:910`]. 04 §6.11 has this right. Doc 26 (26:888) repeats the wrong ring values and cites 04 for them.
2. **Conversions bypass every immunity, and the documents imply otherwise.**
   - 02 §4.10 (02:860) says `Darwinian::IsInvincible` is "queried by weapons". Its only reference is inside a commented-out block in `Laser::Advance` [`code/worldobject/weapons.cpp:724`], so it has no live caller.
   - The subversion-laser branch converts any enemy Darwinian it hits without calling `ChangeHealth` [`weapons.cpp:732`]. Shielded (booster) Darwinians and Darwinians inside an Armour are therefore not protected. The SpamInfection 50 % conversion [`code/worldobject/spam.cpp:526`] and the Randomiser behave the same way.
   - Every creature contact attack uses the default `DamageTypeUnresistable`, so the Personal Shield never blocks them either [`code/worldobject/virii.cpp:440`, `armyant.cpp:322`, `centipede.cpp:399`, `souldestroyer.cpp:258`, `spider.cpp:555`, `tentacle.cpp:381`]. 04 §5.8 (04:707) and §5.31 (04:943) list only Infection, Dark Forest, PulseWave, drowning and plague, so the list is incomplete.
3. **The rocket range in 04 §6.6 is stated as certain, but it depends on slice order.** 04:1148/1150 says "8 moves always happen ⇒ ≈ 95 wu" (turret: 11 moves ≈ 149). Effects are advanced per slot range per slice [`code/lib/slice_darray.cpp:59–73`, `code/location.cpp:1349–1350`]. A rocket put into a slot that has not yet been processed this tick (for example one appended at the end, which the last slice always reaches) is advanced in its creation tick. That gives 9 moves ≈ 113 wu (turret 12 moves ≈ 167). The same caveat applies to the "Rocketwinians fall short beyond ≈ 95" counter-play statement (04:871, 04:960).
