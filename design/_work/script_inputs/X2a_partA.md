# X2a_asset_catalogue_visual — Visual asset catalogue (textures, sprites, shapes, animations, terrain ramps, icons, thumbnails, help images, shaders, fonts)
Scope: every file in `data/textures/**` (incl. `unicode/`, `plusmenu/`), `data/sprites/**`, `data/shapes/**` (`.shp` and `source/*.max`), `data/animations/**` (`.bmp` + `.anim`), `data/terrain/**`, `data/icons/**`, `data/thumbnails/**`, `data/mwhelp/**`, `data/shaders/**`, `data/sepulveda/*.bmp` — 799 files. Font bitmaps live in `data/textures/unicode/` (live) and `data/textures/*font*.bmp` (legacy). Build baseline: see build_matrix.md (`Release|Win32` OpenGL + `TARGET_PC_FULLGAME`; secondary `ReleaseDirect3D`).

Reused and re-verified material: `OUT/_work/drafts/P12_render_core.md` §24.5, §24.7, §25.1–25.3 (decoder, upload, resource manager), `P12_shapes.csv` (superseded by `X2a_shapes.csv`, which uses a parser that follows `code/lib/shape.cpp` token-for-token). Generated tables: `OUT/_work/drafts/X2a_textures.csv` (527 rows: every bitmap, `.anim`, shader and `.psp`), `OUT/_work/drafts/X2a_shapes.csv` (272 rows: every `.shp` and `.max`), `OUT/_work/drafts/X2a_refs.csv` (every resolved reference: asset, kind, site `path:Symbol:Lline`, build, `#if` condition, reachability note, load flags, nearby GL state), `OUT/_work/drafts/X2a_missing.csv` (names requested that have no file). Script: `OUT/_work/scripts/X2a_catalogue.py` (run `python3 -I X2a_catalogue.py <SRC> <OUT/_work> <scratch>`).

## [→ 25_textures_and_assets] 25.0 Method and provenance

### How every file was characterised [C]
| Property | How obtained | Code it mirrors |
|---|---|---|
| Width, height, bit depth, header size, compression, palette | BMP file header + info header parsed exactly as the engine does (palette count = `(bfOffBits−54)/4` for 40-byte headers, `(bfOffBits−26)/3` for 12-byte OS/2 headers) | `code/lib/bitmap.cpp:BitmapRGBA::LoadBmp`, `ReadWinBMPInfoHeader`, `ReadOS2BMPInfoHeader`, `ReadBMPPalette` |
| Loader-compatibility problems | flagged when the engine would mis-decode: header ≠ 40/12 bytes, compression ≠ `BI_RGB`, bit depth ∉ {4,8,24,32}, negative (top-down) height, 4-bit width not a multiple of 8 or 8-bit width not a multiple of 4 (row padding is skipped only by `Read24BitLine`), pixel data not immediately after the palette (the loader never seeks to `bfOffBits`) | `Read4BitLine`, `Read8BitLine`, `Read24BitLine`, `Read32BitLine` |
| Alpha | 32-bit files: min/max of the A byte and % of fully transparent / partial pixels. Other depths have no alpha (loader sets A = 255) | `Read32BitLine` (BGRA), palette `a = 255` |
| Colour-key usage | count of exact (255,0,255) pixels — these become (128,128,128,0) only when the texture is requested with the mask flag | `BitmapRGBA::ConvertPinkToTransparent`, `Resource::ProcessBmp` |
| "Black background" | % of pure black pixels (art meant for additive `GL_SRC_ALPHA, GL_ONE` blending, where black is invisible) — descriptive only [I] | — |
| Power of two | both axes; non-power-of-two (NPOT) files are rescaled at upload whenever power-of-two is required (always under D3D) | `BitmapRGBA::ConvertToTexture` |
| `.shp` structure | tokenised with the `TextReader` separator set `" \t\n\r:,"`; fragments, parents, positions/colours/vertices counts, triangles (strip → triangle conversion dropping degenerate triangles, as the engine does), markers with parent and `Depth`, hierarchy/duplicate/marker-depth checks | `code/lib/shape.cpp:Shape::Load`, `ShapeFragment::ShapeFragment(TextReader*,…)`, `ParseStripBlock`, `ParseTriangleBlock`, `ShapeMarker::ShapeMarker(TextReader*,…)`; `contrib/systemiv/lib/filesys/text_stream_readers.cpp:DEFAULT_SEPERATOR_CHARS` |
| `.anim` | `WIDTH/HEIGHT/START/STOP`, object and keyframe counts, `IMAGENAME` values | `code/animatedpanel.cpp:AnimatedPanel` reader (`IMAGENAME` → `m_imageName`) |
| Packed archive | re-implementation of `tools/build_multiwinia_data.bat` + `tools/listfiles.pl` (exclusion globs case-insensitive, `**/` short excludes, directory pruning, `main.dat` extension filter `tex bmp jpg shp txt vs ps ps3 h anim`, `tools/init.list`, `tools/language.list` and the per-language `tools/*language.list`) | §25.3 |

## [→ 25_textures_and_assets] 25.1 Key findings

- **799 files in scope**: 667 BMP bitmaps, 139 `.shp` meshes, 133 `.max` sources, 6 `.anim` panel scripts, 13 HLSL shader files + 1 HLSL include, 1 Paint Shop Pro file (`data/icons/banner_template.psp`). Every BMP has a 40-byte `BITMAPINFOHEADER`; all are `BI_RGB` except **`data/textures/shaman_background.bmp` (RLE8, compression 1)**, which the loader cannot decode (debug assert; garbage in release) — it is used only by the legacy ShamanInterface [C].
- No shipped palettised bitmap violates the loader's row-padding limitation (4-bit widths are multiples of 8, 8-bit widths multiples of 4) and no file has a top-down height [C].
- **Usage in a baseline Multiwinia match**: 544 of the 666 non-source files are referenced [B:FULL] (per-directory counts in §25.4). The other 122: 71 unused (54 never named anywhere, 16 named only in non-compiled/commented code or never-loaded data, 1 `.psp` source), 23 reachable only on legacy paths [B:LEGACY], 17 only in the Direct3D build [B:D3D] (the 14 shaders and 3 deform tables), 10 only in debug/cheat builds [B:DEBUG], 1 only in the editor [B:EDITOR] (`data/shapes/camera.shp`) — every one enumerated in §25.9. All 133 `.max` files are authoring sources that the game never reads.
- **"Referenced [B:FULL]" means compiled and callable, not necessarily seen**: 52 of the 544 are consumed only by building classes that no live Multiwinia map places (shown as "MP-map placements 0" in the Consumer column, counts from `OUT/_work/drafts/P06_level_building_usage.csv`). Some are created at run time — Capture-the-Statue statues `carry*.shp` [C] (`code/multiwinia.cpp` calls `Building::CreateBuilding(Building::TypeStatue)`), crates' `icons/target.bmp`, triffids and master spawn points [I]; the rest are Darwinia-only buildings (`blueprint*`, `bridge*`, `cave`, `chesspiece`, `clonelab`, `constructionyard*`, `controltower*`, `factory`, `feedingtube`, `fenceswitch`, `generator`, `goddish`, `incubator`, `library`, `mine*`, `powerstation`, `*upgradeport`/`upgrade_port`, `receiverlink`, `refinery`, `researchitem`, `spirit*`, `tracklink`, `wheel`, `fuelpipe`, `textures/beam.bmp`, `textures/fuel.bmp`) whose assets are practically unreachable [I] (U5).
- **NPOT is common**: all 57 thumbnails (400×300), 49 of 51 help images, 27 icons, 23 textures, 11 animation bitmaps, 9 waves ramps (400×10, CPU-only), the 3 Latin-1 font atlases (512×448). These are rescaled up to the next power of two at upload whenever power-of-two textures are required — always in the D3D build (`code/lib/bitmap.cpp:BitmapRGBA::ConvertToTexture`) [C].
- **Three transparency mechanisms** coexist: magenta (255,0,255) colour key (default `GetTexture` mask flag — 16 files actually contain key pixels), green-channel-as-alpha (`GetTextureWithAlpha` — 4 textures), and true 32-bit BGRA alpha (49 files with a non-trivial alpha channel); most glow/beam art instead relies on additive blending over a black background (§25.12).
- **The texture cache ignores load flags**: seven textures are requested with conflicting flags, so the first requester decides mip-mapping, masking or green-to-alpha conversion for every later user — including `data/icons/marker_colour.bmp`, which is requested both with green-to-alpha (`MarkerSystem::RenderColourCircle`) and as a normal masked texture (`TaskManagerInterfaceMultiwinia::RenderRecentRunTask`) (§25.2.4).
- **Packaging differs from the tree**: 160 in-scope files (133 `.max` + 27 others) are not packed into any archive by the retail script (all `.max`, legacy fonts, Xbox/Ambrosia/MSN branding, plusmenu, `mwhelp/360_controller.bmp`, TankBattle/benchmark thumbnails, `mp_cts_3p_3` map + thumbnail, and every unicode atlas not listed by a language list — notably all three currency atlases `*.20a0.20af.bmp`, which therefore never reach players) (§25.3).
- **Missing files that compiled FULL code requests**: `icons/compass_empty.bmp` is bound by the live `MarkerSystem::RenderCompass` when a marker direction is exactly (0,0) — that `GetTexture` would hit the fatal `AppReleaseAssert("Failed to load texture …")` [C code path; whether an archive supplies the file is U]. All other missing names sit on legacy/dead paths or behind `DoesTextureExist` (§25.8).
- **Shapes**: 139 meshes, 441 fragments, 150 820 triangles, 425 markers; 98 use explicit triangle lists, 39 triangle strips, 2 contain markers only and no fragment (`data/shapes/battlecannonbase.shp`, `data/shapes/portal.shp`). Maximum hierarchy depth 6; one file (`data/shapes/carrycube.shp`) has a duplicate fragment name (`Box04`). 113 shapes are used in FULL, 4 only on legacy paths (`globalworld_inner/middle/outer.shp`, `temple1.shp`), 1 only in the editor (`camera.shp`), 21 are unused (§25.9).

## [→ 25_textures_and_assets] 25.2 Texture loading pipeline (verified against code; extends P12 §25.1–25.3)

P12 documents the decoder, upload and cache; the points below were re-verified for this catalogue and add what the asset inventory needs.

### 25.2.1 Request → texture, step by step [C] `code/lib/resource.cpp:Resource::GetTextureWithFlags`, `ProcessBmp`; `code/lib/bitmap.cpp`
1. Cache lookup in `m_textures` (a `hash_map<std::string, TextureInfo*>`) keyed by the **exact string passed** (not lower-cased, flags not part of the key).
2. Else lookup in the registered-bitmap store `m_bitmaps` (run-time bitmaps, and any bitmap previously fetched with `GetBitmap`); `ProcessBmp` mutates that stored bitmap in place.
3. Else read the file: name copied and lower-cased → `GetBinaryReader` → loose `data/<name>` first, then the in-RAM archive entry `data/<name>` (archive entries are lower-cased at `ParseArchive`).
4. `ProcessBmp(flags)`: if `WithMask` (0x2) `ConvertPinkToTransparent` (exact (255,0,255) → (128,128,128,0)); if `WithAlpha` (0x4) `ConvertColourToAlpha` (A := G, RGB := 255); upload with or without mip-maps; `WithCompression` (0x8) is passed through only in the D3D build and **no call site requests it** [C grep].
5. Not found → `AppReleaseAssert(false, "Failed to load texture %s")` — fatal.
6. `TextureInfo{id, width, height}` keeps the **source** size, so `GetTextureInfo` (used by the font atlas code) reports pre-rescale dimensions.

`GetTexture(name, mip=true, mask=true, compressed=false)`; `GetTextureWithAlpha(name)` = `WithAlpha|WithMipmaps` (no mask). `DoesTextureExist` checks cache, bitmap store, then file existence (does not load). `GetBitmap(name)` returns the decoded CPU bitmap (bitmap store first, else decodes the file and **stores it in `m_bitmaps` under the name as given**) — used for terrain ramps (`LandscapeRenderer`, `Water`), icon size queries (`ControlHelpSystem`, `MultiwiniaHelp`), animation images (`AnimatedPanelRenderer`) and map saving (`MapFile::SaveTexture`).

### 25.2.2 Decoding constraints that the asset set must respect [C] `code/lib/bitmap.cpp:BitmapRGBA::LoadBmp`
| Constraint | Consequence | Shipped files violating it |
|---|---|---|
| Only BMP (`Initialise` asserts the extension; `TEXTURE_EXTENSION` = "bmp") | PNG is write-only (screenshots) | none |
| Info header 40 (Windows) or 12 (OS/2) bytes; V4/V5 headers hit `AppDebugAssert(0)` and leave the header uninitialised in release | export as classic BITMAPINFOHEADER | none (all 667 have 40) |
| `BI_RGB` only (debug assert) | RLE decodes as garbage in release | `data/textures/shaman_background.bmp` (RLE8; legacy consumer) |
| 4/8-bit rows read without skipping padding | widths must be multiples of 8 (4-bit) / 4 (8-bit) | none |
| Pixel data assumed to follow the palette immediately (no seek to `bfOffBits`) | gaps between palette and pixels corrupt the image | none |
| Rows stored bottom-up and kept in that order (`m_lines[0]` = bottom row) | matches GL texture origin; UI code uses `glTexCoord2i(0,1)` at the top-left vertex | — |
| Palette alpha forced to 255; 24-bit alpha 255; 32-bit = BGRA | only 32-bit files carry alpha | — |

### 25.2.3 Upload, power-of-two and size rules [C] `code/lib/bitmap.cpp:BitmapRGBA::ConvertToTexture`, `code/lib/math_utils.cpp:RequirePowerOfTwoTextures`, `nearestPowerOfTwo`
- GL build: power-of-two required iff `GL_ARB_texture_non_power_of_two` is absent **or** preference `ManuallyScaleTextures` ≠ 0; square required iff `GL_ARB_texture_rectangle` is absent. D3D build: power-of-two always, square never.
- If required, new size = next power of two ≥ each **original** dimension (overrides the max-size downscale computed just before); the image is resampled with bilinear `Blit` and uploaded at that size. A 400×300 thumbnail therefore becomes 512×512 (×2.18 texels); `data/mwhelp/mode_*.bmp` 300×200 → 512×256.
- Wrap S/T = `GL_CLAMP`, MAG = `GL_LINEAR`, MIN = `GL_LINEAR_MIPMAP_LINEAR` are written into every new texture object; mip chains are built with `gluBuild2DMipmaps` (RGBA8) when requested, otherwise level 0 only (`glTexImage2D`, internal format 4). Callers of non-mip-mapped textures reset MIN to LINEAR/NEAREST at draw time, with the exceptions `textures/laser.bmp` in `Location::RenderWeapons` and `code/worldobject/weapons.cpp:Laser::Render` (both request mip=false and set no MIN filter); because the cache ignores flags, whichever request comes first decides (25.2.4).
- Off-main-thread requests are marshalled to the render thread (`ConvertToTextureAsync` → loading-screen job).

### 25.2.4 Order-dependent results: textures requested with conflicting flags [C] `X2a_refs.csv`

### 25.2.5 Re-upload / context loss [C] `Resource::FlushOpenGlState`, `RegenerateOpenGlState`
All GL textures are deleted and forgotten on flush; registered bitmaps in `m_bitmaps` survive, so run-time textures (§25.10) are rebuilt from their stored bitmaps on next request; file textures are re-read (loose files override archives — the only "hot reload"). Fonts are rebuilt immediately (`BuildUnicodeArray`).

## [→ 25_textures_and_assets] 25.3 Resource archives and their packing

### 25.3.1 Archives opened at start-up [C] `code/app.cpp:App::App`, `App::Initialise`, `App::LoadSounds`; `code/lib/resource.cpp:Resource::ParseArchive`
Order: `init.dat` → `language.dat` → `main.dat` → `patch.dat` → `menusounds.dat` → `branding.dat` → `sounds.dat` → `sounds2.dat`. Each RAR archive is fully decompressed into RAM; entry names are lower-cased; an entry in a later archive replaces an earlier one; a missing archive is silently skipped. Loose files under `data/` always win over archive entries (`GetBinaryReader`, `GetTextReader`, `GetShapeCopy`, `DoesShapeExist`).

### 25.3.2 What the retail packaging script puts where [C] `tools/build_multiwinia_data.bat`, `tools/listfiles.pl`, `tools/copyfiles.pl`
| Archive | Built from | Visual assets it receives |
|---|---|---|
| `init.dat` | `tools/init.list` (copied, then `textures/xboxlivearcade.bmp` deleted on PC) | all 14 `data/shaders/*`, `data/sprites/darwinian.bmp`, `data/textures/ivlogo.bmp` — the loading screen needs these before `main.dat` is parsed (`code/loading_screen.cpp:LoadingScreen::RenderIVLogo`, `RenderFrame`) |
