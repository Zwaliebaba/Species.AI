# Adoption ledger: 00 reference overview

> Status: Final · Owner: area A0 · Reference: [00_reference_overview](../../reference/00_reference_overview.md) · Species design: [00 vision, pillars and core loops](../00_vision_pillars_and_core_loops.md) · Rules: `prompts/species-design-phase.md` §5.3

18 sections, 112 requirements. A section row covers every requirement under its heading; an exception row (scope: one `R-` id) overrides it. Verdicts: `adopt`, `adopt-skirmish`, `adapt` (names the Species requirements that replace it), `drop` (gives the reason).

**Effective verdicts:** adopt 1, adopt-skirmish 60, adapt 51, drop 0, pending 0 (18 section rows, 24 exception rows).

**How to read this file.** Almost every requirement of the reference overview restates a rule that another reference document owns (CONVENTIONS §3). Where a requirement of [the Species design](../00_vision_pillars_and_core_loops.md) commits the world game to the restated rule, the restatement is `adapt` with that requirement, and the owning document's verdict supplies the numbers. Every other restatement binds the skirmish summary only (`adopt-skirmish`): what the world game does with the underlying rule is the verdict of the owning document's ledger, and code and tests cite the owner's id. Where an owning area's verdict comes to differ from a row here, that area sends A0 the row change as a cross-area request. Rows adapted to PIL-003 keep binding the skirmish in their clauses for Spawn Control or for every mode; their clauses for another mode wait until that mode is scheduled.
