# Owner decisions

> Status: Decision register (owner decisions) · Related: [decision register](README.md) · [vision brief](../../vision/species-vision-brief.md) §3

Only the owner takes or changes these decisions, at an owner gate. O1–O30 are copied from the vision brief §3 (2026-10-17 and 2026-10-18); the decisions taken during the design phase follow, numbered on from the last one, each with its date, the question and the options offered. Agents may recommend a change to a decision; only the owner makes it.

| # | Topic | Decision | Consequence the design must carry |
|---|---|---|---|
| O1 | Scale | Start with **2–16 human players** per world plus AI settlements, still playable solo. If Species succeeds, grow to **50–200+ per world**. | The architecture must allow growth without a rewrite: a region-partitioned world, interest-managed replication from day one, and world state in a database rather than a single save file. |
| O2 | AFK attacks | A settlement **can be attacked while its owner is AFK**. The deputy defends with the same simulation as a live battle. | Protection rules are mandatory: a cap on what a settlement can lose while AFK, a shield period after an attack, a cost to attacking, and a defender's advantage. |
| O3 | Simulation fidelity | **Battles always run as the full crowd simulation.** The day-to-day economy of settlements nobody is watching runs on an **abstract model**. | The abstract model needs a stated accuracy and is calibrated against the full simulation. The switch between the two must not create exploits. |
| O4 | Downtime | **The world freezes** while its server is not running: the host has closed the client (integrated stage) or a dedicated server is down for maintenance. | No catch-up simulation. World time is server uptime. |
| O5 | Hosting | **Community-hosted dedicated servers first; official hosting later**, for the 50–200+ tier only, once Species has proven itself. | A headless server build that community operators can run; official hosting is a later stage, not a launch dependency. |
| O6 | Check-in | **The game client only in v1.** The server exposes an authenticated interface for settlement status and deputy orders, so a web or mobile companion can be added later without server changes. | Settlement status and orders are a server API, not client-only logic. |
| O7 | Races | **Symmetric** in v1: one rule set; races differ in looks, colour and AI personality. Asymmetric traits come later. | The data model must allow per-race modifiers later. |
| O8 | Skirmish | **Keep a skirmish mode**: a short, match-based crowd battle on a small map, separate from the persistent world. One mode at first. | It is the first playable and the combat balance test bed, and it runs on the same netcode as the world.; first playable and combat test bed amended by O55 |
| O9 | Look and feel | The look and feel of the reference library **does not change**. | Keep the style: flat-shaded low-poly, additive glow on black, the darkening layer, crowds of small figures. All art is newly authored, with new character silhouettes, textures, UI layout and logo, so Species is not a copy. A strategic zoom level for the big world is designed in the same style. |
| O10 | Server path | The server starts **integrated in the client** and moves to **dedicated servers** over time. | One server codebase. The integrated server runs in-process behind the same transport interface as a dedicated one, and the client never touches server state directly. |
| O11 | Research and training | Designed **later**. | The stat and modifier system, and the unit-specialisation hooks, are designed now, so research and training plug in without rework. |
| O12 | Vocabulary | Name collisions resolved while the reference library was built (2026-10-17): **Command Console, Convert Turret, Transit Gate, Essence Grove, energy grid, Beam Dish, Solar Array, Relic Spawn Zone**. | The Species vocabulary in `Design/CONVENTIONS.md` §8 is authoritative. |
| O13 | Reference tuning values | The reference tuning values **may be adopted as Species starting values** (2026-10-17). | A legal check is required before commercial release. The design phase retunes freely; adopted values need no "provisional" flag for reasons of origin. |
| O14 | Population cap and player slots | Every open slot is played: empty slots are filled with bots by default, leavers are taken over by bots, and the host may close slots; the per-team cap is the map cap ÷ open slots (DEC-079). | Skirmish lobbies need slot open/close and bot fill. For the world game, the design phase decides how this maps to settlements. |
| O15 | Collector orbs | Collectors gather any team's Essence orbs; delivery respects the population cap (DEC-080). | — |
| O16 | Catch-up bonus | Proportional catch-up curve, with Rogue and Visitor factions excluded (DEC-081). | — |
| O17 | Mode second | 11 ticks for the first playable; A/B playtest of 10 vs 11 ticks before launch (DEC-003). | — |
| O18 | Hostile crate outcomes | Hazards team-blind; every outcome respects the map's exclusion list; Brood ownership decided in playtest (DEC-107, DEC-121). | — |
| O19 | Map values | Absent = lobby default, 0 = none, unlimited is explicit (DEC-120). | Typed map schema. |
| O20 | First playable | Spawn Control, 2 players, core Supply crate pool. | Matches the GameAssets.md priorities.; amended by O55 (the world MVP is the first playable) |
| O21 | Build rules and dependencies | **`AGENTS.md` governs how code is written and built**: MSBuild solution (`.slnx`), toolset v145, `/std:c++latest`, Debug and Release only, x64 only, no CMake, no package manager beyond NuGet restore, and no third-party code except a **Microsoft allow-list: the DirectX Agility SDK, the GameInput redistributable and WinPixEventRuntime**. Shaders are compiled by `FXCompile` with the Windows SDK's compiler into byte arrays inside the executable. | The engine ADRs and components follow it: no vcpkg, no CMake presets, no build flavours beyond Debug and Release, no third-party libraries in the executable (compression, codecs, test framework, texture tools); the dedicated server is a Windows build until a later ADR decides another host.; extended by O44 (MsQuic added to the allow-list) |
| O22 | ADR home | Architecture decision records live in **`Design/ADR/` as `ADR-NNN-<slug>.md`** (three-digit ids, MADR 4 content). The design library becomes **`Design/`** at the cutover. | The baseline ADRs (ADR-001 to ADR-077) keep their numbers; new ADRs continue from the highest id. |
| O23 | Code naming in the design | The C++ sketches, type, file and macro names in the design follow the `AGENTS.md` naming rules now: PascalCase types, functions, namespaces and files, `_camelCase` parameters, `m_` members, `UPPER_CASE` constants, American spelling in identifiers, namespace `Engine` for engine code and `Species` for game code. Prose stays British English. | Every component sketch is rewritten; CONVENTIONS §8 follows `AGENTS.md`. |
| O24 | AGENTS.md scope | `AGENTS.md` states the repository's current status and which document decides what. **R18 onwards stays reserved** for conformance rules that the Species design phase derives from the Species design. | The design phase proposes R18+ rules (candidates: presentation never writes simulation state; the determinism rules of the simulation core; tuning values in data, never in code). |
| O25 | Shader files | `AGENTS.md` §2 gains the compute stage suffix `CS`; a permutation is its own file `<Shader><Permutation><Stage>.hlsl`; a shader's shared code lives in one `<Shader>.hlsli` in the same `Shader/` folder. | The renderer and VFX specifications name their shaders this way. |
| O26 | Development-tool dependencies | C++ development tools (the content build tool and its importers) live under `Tools/` in a **separate solution**, which may use pinned third-party code (for example a BC7 texture encoder), each recorded in an ADR with its licence. The game's solution stays at the Windows SDK, the MSVC standard library and the three allow-listed packages. | ADR-017, ADR-055 and ADR-059 follow it.; superseded in part by O29 (one solution) |
| O27 | CI additions | `build.yml` gains a guarded NuGet restore step and a guarded design-check job (`Tools/DesignCheck/CheckDesign.py Design`). Fuzz projects and an `ENGINE_DEVELOPMENT` macro rule are **not** added to `AGENTS.md`. | `Tools/DesignCheck/` holds the checker and the pinned `package.json` the job uses. |
| O28 | Generated schema code | The schema code generator's output is **committed source**: a developer runs it when a schema changes, it writes `AGENTS.md`-style `.h` files into the owning project folder, and CI regenerates them and fails on any difference. | No game or engine project needs a tool project to build (ADR-062, `AGENTS.md` §2). |
| O29 | Tool projects in the one solution | The C++ development tools are **projects of the one solution** at the repository root, under `Tools/<Project>/` in a `Tools` solution folder, instead of a separate solution: they build with the same `$(SolutionDir)` paths and may reference the engine projects they share code with (the schema and record code, the cookers). No game or engine project references a tool project or a tool-only package. Owner, 2026-10-18. | CI builds the tools on every run; R14 is checked per project by `Build/CheckProjectFiles.py`; AGENTS.md §2 and R14, ADR-054 (amendment) and the build tooling component follow. |
| O30 | Tool dependencies come from NuGet | A tool project's third-party dependency is **restored by NuGet** for that project only; nothing is downloaded by the build from another source and no third-party binary is committed. Owner, 2026-10-18. | A tool with no NuGet package is not a dependency: the Khronos glTF Validator is not used by the content build, which validates the glTF it imports itself (ADR-019 amendment); `AGENTS.md` §2 stands as written. |
| O31 | Pillar 6 | **Add a sixth pillar, "Always a way back"**, with claims: no settlement becomes unassailable, a late joiner finds a place and a path to matter, and a lost battle is a setback, never the end; a conflict can move a claim (an area outside a settlement's core). Gate A, 2026-10-18; options: add it with claims (chosen), keep five pillars, keep five and rely on world-lifetime resets. | Rules out conquest by absorption and permanent knock-outs; B2, B5 and B6 carry the claim rules (PIL-015, PIL-120). |
| O32 | Name of the peoples | **A people of Species is a Cladan** (plural: the Cladans); the word "clade" is not used. Gate A, 2026-10-18; offered: clade (recommended), race, kin; the owner chose Cladan, then the use "a people is a Cladan" over "clade with Cladan members" and "plural only". | Identifier `Cladan`, string-id prefix `cladan.`; replaces the vision's "race" everywhere; onboarding teaches the word (PIL-091). |
| O33 | Attacks between stewards | **A steward may attack any settlement outside its protection**; an unprovoked attack (no grievance or claim on record) costs twice the attack cost and is named as unprovoked; attacks between stewards are a world setting, **off by default in integrated worlds and on by default on dedicated servers**. Gate A, 2026-10-18; options: this (chosen), only with a cause on record, no attacks between stewards in v1, any settlement with no surcharge. | B5 and B6 specify the attack cost, the unprovoked surcharge and the setting (PIL-063). |
| O34 | Removal of a settlement | **A battle never removes a settlement.** A settlement without presence for 21 days becomes dormant: it leaves the map with its stores and structures and returns at a free site when its steward comes back. Gate A, 2026-10-18; options: this (chosen), never at all, by battle when unprotected. | The 21 days is a tuning value; B1, B6 and C2 specify dormancy and the return (PIL-078, PIL-080). |
| O35 | A stage-1 world while its host is away | **O4 and O10 stand as written.** An always-on integrated world keeps running while the host's client stays open with its presentation suspended; closing the client freezes it; a world that is not always-on runs at the session pace. Gate A, 2026-10-18; options: this (chosen; the proposer's), a background headless server process after the game closes (the challenger's), the session pace only in stage 1. | Resolves A0-F01; the two world paces hold (PIL-077, PIL-100 to PIL-104); D1 specifies the suspended-presentation mode.; amended for the MVP by O54 |
| O36 | Pillars | **The six pillars are confirmed as drafted**: 1 Living crowds; 2 A world that runs while you are away; 3 Conflict with a cause; 4 Delegation you can trust; 5 The reference style, a distinct game; 6 Always a way back. Gate A, 2026-10-18. | Every later area names the pillar each significant choice serves (PIL-016). |
| O37 | Core loops and vocabulary | **The core loops at three timescales (a battle; settlement growth; the world, claims and relations) and the new vocabulary are confirmed as drafted**, including steward (for "owner") and respite (for "shield"), with O32 applied. Gate A, 2026-10-18. | The terms are registered in CONVENTIONS §8 and the glossary (A0 Finalise). |
| O38 | AI settlements and late joiners | **A world has 6 + 0.25 × steward capacity native AI settlements** (10 at 16, 56 at 200), a site margin of 0.25 × capacity for **stand-in AI settlements** that step back, dormant with their stores, when stewards join, and a **keeper** that holds every steward at two or more contacts. Wave A (A1), 2026-10-18; options: this (chosen), natives only without stand-ins or keeper, a fixed AI count set by the host. | B7 runs the stand-ins; A2's full-occupancy load is unchanged (WLD-121 to WLD-126). |
| O39 | World lifetime | **Integrated worlds are unlimited; dedicated and hosted worlds last 84 world days by default**, which the host may lengthen before the final notice. **No eras in v1**; B5 evaluates eras with renown for stage 2. Wave A (A1), 2026-10-18; options: this (chosen; the proposer's), the same plus eras in v1 (the challenger's), unlimited everywhere. | A1-M6 closed as decided; the 84 days is a tuning value (WLD-220 to WLD-223).; amended for the MVP by O53 |
| O40 | Stage-2 capacity | **A community dedicated world holds up to 16 stewards**, as an integrated one: one load profile for stages 1 and 2. Wave A (A1), 2026-10-18; options: up to 16 (chosen), up to 50, host-configurable up to 200. | Larger worlds wait for stage 3 and A2's dedicated budget. |
| O41 | Dedicated-server operating system | **A Windows dedicated server in stage 2, with a portable core**: the server and simulation libraries reach the operating system only through the platform layer, use fixed-width types and total orders, and store or send nothing in a Windows-only format, so a server for another operating system replaces the platform layer only. Whether and when there is one is a later ADR. Gate B, 2026-10-18; options: this (chosen), a second operating system in stage 2 as an `AGENTS.md` change (7 to 11 engineer-weeks), a deferral to stage 3. | A2-F05 closed; O21 stands; D1 specifies the Windows server (DEC-220). |
| O42 | World store | **Species' own journaled record store**, in plain C++ over the platform layer's files: a write-ahead journal, torn-write detection and restore at start-up, portable and with no R14 exception; not the in-box ESE, not an embedded database library. Gate B, 2026-10-18; options: ESE (recommended for a Windows-only server), this (chosen), an embedded database library as an R14 exception. | D4 builds it (3 to 4 engineer-weeks with its tests) and its confirmation includes torn-write and power-loss tests; a hosted world may put a server database behind the same store interface by a later ADR. |
| O43 | Scale budgets | **The budgets are provisional with ranges**: population limit L = 600 per settlement (450 to 700), battle side cap S = 600 (200 to 600), region body budget 4L + 2S = 3,600, region step 12.5 ms, and A1's world sizes; the first task of the simulation-core milestone measures the costs and fixes them before content is tuned. Gate B, 2026-10-18; options: this (chosen), a one-week measurement before confirming. | ADR-080 states them as provisional; B1, B4 and B6 design within the ranges. |
| O44 | Transport | **MsQuic, Schannel build, carries client–server traffic**: reliable streams for commands and blobs, QUIC datagrams for state updates, TLS 1.3; R14's allow-list gains a fourth Microsoft package, `Microsoft.Native.Quic.MsQuic.Schannel` (MIT; `msquic.dll` installed beside the executable). Gate B, 2026-10-18; options: this (chosen; the owner's proposal), Species' own transport on Schannel DTLS 1.2 (A2's), a one-week comparison first. | Extends O21; `AGENTS.md` R14 and ADR-055 are amended and a new ADR records the package; ADR-088 is revised on it. |
| O45 | Identity, listing and relay | **The R14-clean baseline for the first world-game milestone**: a player identity key in the CNG key store, a port mapping through the in-box UPnP NAT API, IPv6 and a manual address; no relay, so a host behind carrier-grade NAT is unreachable, and no identity across servers. A provider is chosen later with the storefront. Gate B, 2026-10-18; options: this (chosen), the Steamworks SDK, Epic Online Services, an own relay and listing service. | ADR-088 items 1 and 4; DEC-248 and DEC-249 stay D5's. |
| O46 | Battle caps | **2 battles per region and max(8, ⌈10 % of settlements⌉) per world** (8 at 16, 26 at 200). Gate B, 2026-10-18; options: this (chosen; A2's), A1's max(4, 10 %). | Amends WLD-285's world cap; up to 4.6 ms more per tick at 16. |
| O47 | Overload lever | **Approved**: after 10 s over the 50 ms tick budget, settlements watched only as a neighbour (never a steward's own, never a side of a battle) fall to abstract fidelity with a stand-in presentation until the wall time is below 80 % of the budget. Gate B, 2026-10-18; options: this (chosen), no lever, so that an overload slows world time. | ADR-085 item 9 comes into force; PIL-057 and WLD-244 are amended; C3 and the renderer specify the stand-in presentation. |
| O48 | Host sizes | **Stage 3 on 16 vCPU and 4 GB; stage 2 recommended 4 vCPU, minimum 2 vCPU; the integrated server within 1 reference core and 2 workers.** Gate B, 2026-10-18; options: this (chosen), 8 vCPU at stage 3. | ADR-080 and ADR-085 item 8; D1 publishes the stage-2 host requirements. |
| O49 | Storefront and publisher | **Deferred to before the first external build**: ADR-072 and ADR-073 stay Proposed with their defaults (the install directory and a signed archive; Artifact Signing with an OV certificate as the fallback), and the identity provider of O45 is revisited with the storefront. Gate B, 2026-10-18; options for the storefront: this (chosen), a Steam depot without the Steamworks SDK, the Microsoft Store MSIX with direct download, direct download only; for the publisher: this (chosen), the owner as an individual, an existing company. | Nothing is signed or distributed externally until they are decided. |
| O50 | Success and first audience | **Success is a game the owner enjoys playing, first solo against AI settlements and then with friends; Species scales up only after that.** The first audience is one steward in a world of AI settlements, ahead of the groups of friends that the pillars document names first (PIL-031). Owner, 2026-10-18, after wave A: "a game which I like to play with some friends", and, with no group yet, "it should also be fun with one player to start with". | The MVP is judged by solo play first ([MVP scope](../implementation/mvp_scope.md)); the tiers of O1 stay the target, and the MVP keeps only the seams that keep them reachable (MVP-090 to MVP-099). |
| O51 | Design phase | **The design phase stops after wave A, and the next work is the MVP.** Areas B1 to E3 and the whole-design review are not run; A0 and A1 stay Final; A2 stays Draft, with gate B recorded (O41 to O49) but not yet applied to the solution strategy or to ADR-079 to ADR-088; the area briefs stay in `species_design_work/`. Owner, 2026-10-18; options: pause the design and build an MVP whose evidence feeds the later areas (chosen), run waves B to E first. | The [MVP scope](../implementation/mvp_scope.md) governs what is built next and states as its own provisional rules what the unwritten areas would have specified; where it narrows or defers a Final requirement it says so; the design phase resumes only by an owner decision.; A2 finalised on 2026-10-19 at the owner's request: gate B applied, the solution strategy Final, ADR-089 records MsQuic |
| O52 | MVP build path and look | **The MVP is built in the real C++23 and Direct3D 12 codebase under `AGENTS.md`, nothing throwaway, and it looks good from its first playable milestone**: generated low-poly terrain, a few structures, and Workers that are seen walking, carrying and fighting; no placeholder dots. Owner, 2026-10-18; options: real code with a minimal look (chosen, with the owner's addition that the terrain, the structures and the walking people must be nice to watch), real code with placeholder visuals, a throwaway prototype first. | The MVP scope sets the visual bar and the asset list (MVP-080 to MVP-089); every asset is newly authored (O9). |
| O53 | Arc of a solo world | **A world is a run with renown**: it lasts a set number of world days; its settlements earn renown by defences held, grievances eased, claims settled and structures raised, never by stores taken; and an epilogue shows the standing and each settlement's history when the run ends. Owner, 2026-10-18; options: a run with renown (chosen), an open-ended sandbox, objectives per world. | Amends O39 for the MVP: its world has a lifetime although it is integrated; PIL-125's renown and epilogue move from stage 2 into the MVP (MVP-060 to MVP-064). |
| O54 | World clock in the MVP | **Staged**: first the world runs only while the steward plays, to test whether an hour of play is fun; then a headless server process keeps the world running after the client closes, to test whether coming back to the deputy's away report is fun. Owner, 2026-10-18; options: staged (chosen), always-on from the start, only while playing. | Amends O35 for the MVP: the background headless server (the A0 challenger's option) replaces a client left open with its presentation suspended; O4 holds, and the world freezes whenever that process is not running (MVP-070 to MVP-079). |
| O55 | Skirmish | **Skirmish is deferred**: the world MVP is the first playable, with a battle sandbox inside the world as its first milestone; skirmish follows the MVP. Owner, 2026-10-18; options: defer it (chosen), skirmish first as O20 states, both in the MVP. | Amends O8 (skirmish as the first playable and the combat test bed) and O20; skirmish stays a mode of Species, and its `adopt-skirmish` rows stay as they are. |
| O56 | Fonts | **Species draws its text from two newly drawn bitmap fonts**, a title face and a body face, which the owner draws in the condensed style of the reference look; the reference game's own fonts are not used (O9 stands). Text rendering uses authored glyph atlases by default; DirectWrite with a glyph cache stays the recorded upgrade for when localisation beyond the Latin script or player-entered text arrives. Owner, 2026-10-19; options for the fonts: draw two new ones (chosen), the two reference bitmap fonts as private placeholders, the reference fonts as the real fonts with an exception to O9; for the text stack: bitmap by default with DirectWrite as the upgrade (chosen), bitmap for the MVP only, bitmap for good. | ADR-034 is amended to the authored-atlas option; the UI framework's font requirements and the font rows of the asset manifest follow; no licensed typeface is needed for the MVP. |
| O57 | Names of the MVP's resource and structures | **The one resource that Workers gather is Crystal; the two new structures are the dwelling and the storehouse.** Owner, 2026-10-19; options for the resource: Crystal (chosen), Ore, Amber; for the structures: dwelling and storehouse (chosen), lodge and stockpile, hut and store. | CONVENTIONS §8.15 and the glossary register the three terms; the MVP scope uses them (MVP-030, MVP-034); the asset ids keep their names. |
| O58 | Reference test machine | **The owner's own PC is the reference test machine** (DEC-971, option A): it is pinned at the MVP's milestone M1, when the performance job first runs, and its processor, memory, graphics adapter, driver, display mode and OS build are recorded with each result. Owner, 2026-10-19; options: the owner's PC (chosen), a named minimum-specification machine, budgets per hardware tier with a machine each. | DEC-971 is Resolved; DBG-209 and MVP-085 name the machine; a minimum-specification tier is decided before the first external build. |
| O59 | Fog in worlds larger than one region | **The fog end is a fixed distance from the camera, not the world's extent**, so distant terrain fades to black at every world size: the value that one region gives today (6,120 wu) holds for every world, and the MVP's valley looks unchanged. Owner, 2026-10-19; options: from the camera (chosen), from the world size as the reference rule states, decide later. | RND-222 and RND-211 carry amendments; the far plane of the settlement view needs no change; the strategic view's fog and planes stay DEC-247's. |
