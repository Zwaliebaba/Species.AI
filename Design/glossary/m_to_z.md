# Glossary M–Z

> Status: Reference · Glossary · Related: [Glossary index](README.md), [Glossary A–L](a_to_l.md), [Conventions](../CONVENTIONS.md)

This file defines the Species terms that start with the letters M to Z. [README.md](README.md) explains how to read an entry; Species identifiers and string-id prefixes for each term are in [CONVENTIONS.md §8](../CONVENTIONS.md#8-naming).

## M

| Term | Kind | Definition | Owning document |
|---|---|---|---|
| main loop | engine term | The loop that runs a participant's frames. In a match, each iteration of the in-match loop pumps input, takes command frames, runs the update slices of the ticks that are due and renders the frame; the front end and the loading view run loops of their own. | [Tick timing and main loop](../reference/12_simulation_model/01_tick_timing_and_main_loop.md) |
| Manning | engine term | The Worker state of operating a port: on arrival at a port the Worker turns to face the port's front, stops and mans it. The Workers that fill a team's ports at match start begin in this state. Also called the operating-port state. | [Worker](../reference/02_units/worker.md) |
| manual source | engine term | A time source of the platform clock that advances only when a test advances it. | [Platform layer](../architecture/components/platform_layer.md) |
| map | player concept | One playable level: a map definition that sets the terrain, structures, starting forces and match options for its modes and its player count. Maps are named `map_<mode>_<players>p_<nn>`; the reference map set has 49 maps, and every Species map is authored new (see DEC-063). | [Maps and level design](../reference/08_maps_and_level_design/README.md); [Map rules and conventions](../reference/08_maps_and_level_design/rules_and_conventions.md) |
| map catalogue | engine term | The list of playable maps, built once at start-up from the headers of the map definitions that lie directly in the maps folder of every mounted content set, without loading the rest of any map. | [Map rules and conventions](../reference/08_maps_and_level_design/rules_and_conventions.md) |
| map definition | data term | The authored content of one map, in blocks: the terrain definition, terrain tiles, terrain flatten areas, map lights, structures, routes, start positions with their camera views, camera animations, starting forces and match options. The content build validates it against its schema (ADR-059), and it is identified by its map id. | [Data schemas](../architecture/components/data_schemas/README.md); [Map rules and conventions](../reference/08_maps_and_level_design/rules_and_conventions.md) |
| map editor | engine term | The in-game map editor, with its map editor window, hub page and map file picker. The reference has no reachable map editor; the library records its hooks: what a map can express and an editor edits, the entry and exit flow and custom-map handling (see DEC-045). | [Map editor hooks](../reference/08_maps_and_level_design/map_editor_hooks.md) |
| map effect | data term | One of the five effect flags that a map definition can set, in this order: snow, lightning, dust wind, Essence-orb rain and special lighting. Snow, lightning and dust wind spawn weather effects; special lighting gives the structures one warm key light, and every Launch Race match uses it too; no reference map sets Essence-orb rain (see DEC-562). | [Map rules and conventions](../reference/08_maps_and_level_design/rules_and_conventions.md) |
| map header | data term | The first block of a map definition, the match options: it is readable without the rest of the map, so that the map catalogue reads only the header. | [Map rules and conventions](../reference/08_maps_and_level_design/rules_and_conventions.md) |
| map id | data term | The stable identity of a map, its name `map_<mode>_<players>p_<nn>`; the hash of the cooked map asset is the content version of that id, never a substitute name (ADR-060, DEC-204). The content build generates the map index, the list of map ids that the achievement hooks count (DEC-563). | [Data schemas](../architecture/components/data_schemas/README.md); [Build tooling and distribution](../architecture/components/build_tooling_and_distribution/README.md) |
| map-identity listing | data term | The content-build report of every map's identity, its map id with the SHA-256 hash of its cooked map, compared with the listing of the previous build. | [Build tooling and distribution](../architecture/components/build_tooling_and_distribution/README.md) |
| map light | engine term | A plain record of one directional light of a map, with its colour and direction; the renderer uses it and the simulation never does. Every reference map uses exactly two directional lights (see DEC-562). | [Renderer](../architecture/components/renderer/README.md) |
| map option | data term | One of the 15 per-map settings inside the match options, in this order: no Catch-up bonus, instant Spawn Node capture, Transit Gate reinforcement count, Transit Gate Transport cap, no gun turrets, attacker reinforcement count, defender reinforcement count, defender reinforcement power, attacker reinforcement power, same-team Beam Dish links, no Beam Dish aiming, airstrike threshold, Visitor-faction position, attacker reinforcement power option and defender reinforcement power option. | [Map rules and conventions](../reference/08_maps_and_level_design/rules_and_conventions.md) |
| map thumbnail | data term | The preview image of a map, rendered with the engine by the content build from a top-down view of the map at an aspect ratio of 4:3 (DEC-563). | [Build tooling and distribution](../architecture/components/build_tooling_and_distribution/README.md) |
| Massacre | player concept | Achievement: the local team has killed at least 2,000 enemy Workers on the tick the match ends. The stated goal is more than 3,000 kills; the design phase restates the threshold (see DEC-047). | [Options, localisation and hooks](../reference/09_front_end_and_match_flow/options_localisation_and_hooks.md) |
| match | player concept | One played map, from the end of loading to the end-of-match sequence. It is the lifetime of the match world and of all per-match state, which is reset at every match start (DEC-011). | [Match rules](../reference/01_skirmish_rules_and_modes/README.md); [Match lifecycle and state reset](../reference/12_simulation_model/02_match_lifecycle_and_state_reset.md) |
| match bank | engine term | The sample bank of every other resident sound of a match, with its stream heads: it loads during each match load, within a 192 MiB budget, and is released when the match world is torn down. | [Audio engine](../architecture/components/audio_engine/README.md) |
| match camera | engine term | The player's camera in a match. Its live modes are free movement (cursor-follow panning at 250 wu/s, 1,000 wu/s with the speed modifier held, and zoom by narrowing the vertical field of view from 60° to 15°), tracking a selected actor, and aiming a structure; it is local and the simulation never reads it (DEC-024). | [Player camera](../reference/06_controls_camera_and_commands/camera.md); [View, lighting and fog](../architecture/components/renderer/view_lighting_and_fog.md) |
| match-clock minute | player concept | 60 mode seconds of the match clock: the unit of the time-limit options and of the clock's whole-minute ticks. | [Match rules](../reference/01_skirmish_rules_and_modes/README.md) |
| match input pump | engine term | The per-frame step that turns the local player's controls into player commands and into the team command state. | [Actions and bindings](../reference/06_controls_camera_and_commands/actions_and_bindings.md); [Input](../architecture/components/input/README.md) |
| match options | player concept | The typed settings of one match, each with an explicit default per mode (DEC-073): the lobby options (score mode, time limit, Catch-up bonus, crate drop period, starting powers, Comeback Bonus, sudden death, crate placement, reinforcement interval, reinforcement count, Transport cap, turret frequency and turret cap, each in the modes that offer it) and the values that the map definition sets (its modes, player count, population caps, co-op, excluded outcomes, Transit Gate values and map options). A map value overrides the lobby default, and 0 is a value, not an absence (DEC-065). | [Match rules](../reference/01_skirmish_rules_and_modes/README.md); [Map rules and conventions](../reference/08_maps_and_level_design/rules_and_conventions.md); [Data schemas](../architecture/components/data_schemas/README.md) |
| match rules | engine term | The per-match rules object. It holds the mode, the match options, the lobby slots and the grace period, runs the mode's rules once per mode second, runs the reinforcement waves and the Comeback Bonus, keeps the scores and the HUD, and declares the winner (DEC-017). | [Match rules](../reference/01_skirmish_rules_and_modes/README.md) |
| match setup | engine term | The record of a match that is fixed before match start and identical for every participant: the map, the mode, the match options, the teams, the seed and the seasonal state (DEC-013, DEC-118). Lobby changes reach it as ordered commands (see DEC-243). | [Screen flow and match setup](../reference/09_front_end_and_match_flow/screen_flow_and_match_setup.md); [Match lifecycle and state reset](../reference/12_simulation_model/02_match_lifecycle_and_state_reset.md) |
| match world | engine term | The container of one match: teams, structures, Essence orbs, laser bolts, effects, terrain, sea, spatial grids and route graphs. It advances the simulation in update slices and resolves simulated-object handles. | [Containers and update order](../reference/12_simulation_model/04_containers_and_update_order.md) |
| menu size | engine term | A tool-window length after large-menu scaling: with the large-menus setting on, lengths scale with the screen height by 0.96 × H ÷ 460; with it off, a length keeps its value. | [UI core and widgets](../architecture/components/ui_framework/core_and_widgets.md) |
| mesh | engine term | A hierarchical flat-shaded mesh: a tree of mesh nodes with transforms, triangles and vertex colours, carrying named mesh sockets. Meshes are authored as CMO files and cooked into a Species runtime format (ADR-019, ADR-020, O64). | [World renderers](../architecture/components/renderer/world_renderers.md); [Data schemas](../architecture/components/data_schemas/README.md) |
| mesh node | engine term | One node of a mesh's hierarchy: geometry plus a transform. | [Data schemas](../architecture/components/data_schemas/README.md) |
| mesh socket | engine term | A named point attached to a mesh node that code looks up to place ports, doors, beam origins and effects. The content build checks sockets against a schema per asset class (ADR-021). | [Data schemas](../architecture/components/data_schemas/README.md); [Asset pipeline and resources](../architecture/components/asset_pipeline_and_resources.md) |
| meteor | engine term | One rock of a meteor shower: it falls straight onto a point near the target and explodes with explosion radius 50 wu and damage 100. | [Creatures and hazards](../reference/02_units/README.md) |
| meteor shower | player concept | A Supply crate outcome: 5–9 meteors fall into a 420 × 420 wu square around the target, and game speed drops to 0.4× for a slow-motion phase (DEC-039). It is not filtered by team (see DEC-107). | [Supply crates and powers](../reference/04_supply_crates_powers_and_weapons/crates_and_powers.md) |
| Missile Barrage | player concept | An advanced Supply crate outcome: 10 barrage missiles launched from the sea strike the target, the first exactly on the point and nine within ±150 wu of it, each with explosion radius 50 wu and damage 100 (see DEC-303). | [Supply crates and powers](../reference/04_supply_crates_powers_and_weapons/crates_and_powers.md) |
| mode | player concept | One of the six match modes, in this order: Spawn Control, Zone Control, Relic Run, Siege, Launch Race and Flag Chain. The mode selects the rules that the match rules run and the lobby options offered (DEC-017, DEC-058). | [Match rules](../reference/01_skirmish_rules_and_modes/README.md) |
| mode second | player concept | The unit of the per-mode rule clocks (the match clock, the elimination countdowns, the Relic timers, the reinforcement waves and the rank checks): an explicit constant of 11 ticks, so a displayed second lasts 1.1 s (DEC-002, DEC-003). | [Match rules](../reference/01_skirmish_rules_and_modes/README.md); [Population flow](../reference/05_population_flow.md) |
| mortar turret | player concept | The turret type that lobs mortar rounds, grenades that explode on impact; it reloads in 40 ticks. | [Defences and props](../reference/03_buildings_and_world_objects/defences_and_props.md) |
| move-only flag | engine term | The flag of an order to a selected Leader or Transport that makes it take the point as its waypoint instead of receiving orders to it. In gamepad mode the south face button always gives the move-only order. | [Actions and bindings](../reference/06_controls_camera_and_commands/actions_and_bindings.md) |
| movement tab | engine term | One of the four first-tutorial instruction tabs that ask the player to move (`capture_node`, `move_to_zone`, `leader_to_zone`, `capture_far_zone`); after one, the director waits a 100-tick breather before it accepts the next tab. | [Tutorial and help](../reference/11_tutorial_and_help.md) |
| MSAA | abbreviation | Multisample anti-aliasing of the scene colour and depth targets, with Off, 2x and 4x settings (ADR-015). | [Renderer options and budgets](../architecture/components/renderer/options_and_budgets.md) |
| MSVC | abbreviation | Microsoft Visual C++, the pinned Windows compiler toolset of Species (ADR-051). | [Build tooling and distribution](../architecture/components/build_tooling_and_distribution/README.md) |
| music channel | engine term | The audio engine's dedicated streaming voice for music. Nothing plays music in a match; the library records the music hooks only (see DEC-049). | [Audio engine](../architecture/components/audio_engine/README.md); [Audio design](../reference/10_audio_design/README.md) |
| music hook | engine term | A hook kept for music, which the reference does not play: the audio engine has a music channel and the sound data names music events, but no rule of a skirmish session raises a music event. Music is for the design phase to design. | [Music hooks and sound design brief](../reference/10_audio_design/music_hooks_and_sound_design_brief.md) |
| muzzle flash | engine term | A short-lived cosmetic flash at a firing point. | [Weapons and projectiles](../reference/04_supply_crates_powers_and_weapons/weapons_and_projectiles.md) |

| Term | Kind | Definition | Owning document |
|---|---|---|---|
| native AI settlement | player concept | An AI settlement that the world generator places at world creation; it never leaves its site, founds elsewhere or becomes dormant. | [World and sites §2.7, WLD-120](../gdd/01_world_and_regions/world_and_sites.md#27-native-and-stand-in-ai-settlements-and-free-sites) |
| navigation cursor | engine term | The entry of a standard window's navigation order that keyboard or gamepad navigation has reached; it shares one visual state with pointer hover. | [UI core and widgets](../architecture/components/ui_framework/core_and_widgets.md) |
| navigation order | engine term | The ordered list of the widgets of a standard window that keyboard and gamepad navigation visit; a screen adds each navigable widget in the order it chooses. | [UI core and widgets](../architecture/components/ui_framework/core_and_widgets.md) |
| needs defending | engine term | The state of a bot's own navigation node that has a tagged zone outside Relic Run, or a link to a hostile node with more than 30 enemies of its owner while no Leader of the team is within 300 wu. Such a node gets a formation Leader. | [Bot navigation graph](../reference/07_bots/01_navigation_graph.md); [Bot decision loop and Leaders](../reference/07_bots/03_decision_loop_and_leaders.md) |
| network statistics window | engine term | A development-build window that shows network statistics, with correct units; its metric set is open (DEC-041, see DEC-208). | [Diagnostics, test and performance](../architecture/components/diagnostics_test_and_performance/README.md) |
| newcomer protection | player concept | The protection of a newly founded settlement: its founding respite and any further limit that B6 sets. | [Vision, pillars and core loops §2.9, PIL-088](../gdd/00_vision_pillars_and_core_loops.md#29-safety-floor-and-fair-information) |
| no team | engine term | The team value of an object that no team owns. A structure with no team can be captured, a Spawn Node with no team produces nothing, and a Transit Gate with no team never reinforces; the no-team colour is an opaque grey (DEC-078, DEC-464). | [Teams and player commands](../reference/12_simulation_model/06_teams_and_player_commands.md) |
| no-team layer | engine term | The layer of a sound event that plays when the event has no team, in place of its own and enemy layers, so that a structure that becomes neutral plays one defined sting (DEC-097). | [Event model and sound data](../reference/10_audio_design/event_model_and_sound_data.md); [Event catalogue](../reference/10_audio_design/event_catalogue.md) |
| Not available | player concept | The power-slot message shown when a Power cannot be started. | [Selection and Power slots](../reference/06_controls_camera_and_commands/selection_and_power_slots.md) |
| note loop | engine term | A re-triggering sound layer: at each release a new copy starts after the loop delay, with a new group member and new values, and cross-fades with the fading previous note. The ambience beds use it. | [Event model and sound data](../reference/10_audio_design/event_model_and_sound_data.md) |

## O

| Term | Kind | Definition | Owning document |
|---|---|---|---|
| object serial | engine term | The number that the object serial counter gives each actor and effect when it is created. Serials are rule inputs (the Barrier Emitter clearance of a Worker, the dust-vortex lift height, formation slots and the presentation variations of Workers), so they are identical on every participant only if every participant creates the same objects in the same order (R-SIM-108, R-SIM-138). | [Entity model and identity](../reference/12_simulation_model/03_entity_model_and_identity.md) |
| object under the pointer | engine term | The object that the match input pump resolves under the pointer each frame for the local team; selection, orders and hints act on it. | [Actions and bindings](../reference/06_controls_camera_and_commands/actions_and_bindings.md) |
| obstacle grid | engine term | The spatial index of structures: each world cell lists the ids of the structures that overlap it, for obstacle pushes and placement tests. It is updated incrementally (DEC-095). | [Space, routing and physics](../reference/12_simulation_model/05_space_routing_and_physics.md) |
| obstacle push | engine term | The step `PushFromObstacles` that turns the position an actor wants into one it may take: it puts a grounded actor on the terrain, then moves the position out of every structure it overlaps, in 4 wu steps directly away from that structure. An enabled Barrier Emitter never pushes; it electrocutes an actor that is not its friend (R-SIM-380, R-SIM-381). | [Space, routing and physics](../reference/12_simulation_model/05_space_routing_and_physics.md) |
| offspring budget | engine term | The number of offspring trees a tree may still create: 0 for a map tree and the creator's remaining budget for a planted one. A healthy tree with budget left creates one offspring every 50 to 100 ticks. | [Trees and crate structures](../reference/03_buildings_and_world_objects/trees_and_crate_structures.md) |
| one-minute warning | player concept | The HUD message shown once, when the remaining match time first drops to 60 mode seconds or less. | [Match rules](../reference/01_skirmish_rules_and_modes/README.md); [Audio design](../reference/10_audio_design/README.md) |
| open slot | player concept | A team slot that the host leaves open before the match. It is occupied for the whole match, by a human or by a bot that fills it at match start or takes over from a participant who leaves. The number of open slots is fixed at match start and divides the map's population cap (DEC-079). | [Match rules](../reference/01_skirmish_rules_and_modes/README.md) |
| opening progress | engine term | The progress of a Supply crate towards opening: while its owner holds the local majority it grows by up to 50 units per tick, and the crate opens on the first tick on which it exceeds 2,500 units. | [Supply crates and powers](../reference/04_supply_crates_powers_and_weapons/crates_and_powers.md) |
| opening team | player concept | The team that owns a Supply crate on the tick its opening completes; a good outcome goes to it. | [Supply crates, powers and weapons](../reference/04_supply_crates_powers_and_weapons/README.md) |
| operator | player concept | The Worker that occupies one of a structure's ports to operate or capture it. | [Buildings and world objects](../reference/03_buildings_and_world_objects/README.md) |
| options screen | engine term | The full-screen page style that Help and Options, the settings pages and the in-match menus use. | [UI core and widgets](../architecture/components/ui_framework/core_and_widgets.md) |
| order marker | engine term | The effect that follows the route to a Leader's order point and leaves order trail marks on the ground. | [Leader and formations](../reference/02_units/leader_and_formations.md) |
| order target | engine term | The point that a crowd order, a Leader or Transport order or a route preview goes to: the pointer ground point, replaced by the entrance of a Beam Dish, the position of a Supply crate, of a Transport that is not full, or of a Leader under the pointer. | [Actions and bindings](../reference/06_controls_camera_and_commands/actions_and_bindings.md) |
| order trail mark | engine term | An arrow mark on the ground left by an order marker. | [Leader and formations](../reference/02_units/leader_and_formations.md) |
| OS | abbreviation | Operating system. | [Platform layer](../architecture/components/platform_layer.md) |
| outside height | data term | The negative sea-floor height that the terrain height field gives everywhere outside the terrain tiles; the terrain definition sets it. | [Terrain](../architecture/components/terrain/README.md) |

| Term | Kind | Definition | Owning document |
|---|---|---|---|
| pack file | engine term | A Species content archive in its own indexed, chunked and hashed format, written by the content build. An ordered mount manifest lists the base packs and then the patch packs; a later pack overrides an entry only where the manifest marks it as a patch for that pack, and a Release build reads packed content only (ADR-058). | [Asset pipeline and resources](../architecture/components/asset_pipeline_and_resources.md) |
| page | engine term | One state of the front-end screen, named by its `PageId`, with its own set-up, widgets and teardown. | [UI pages and screen recipes](../architecture/components/ui_framework/pages_and_screen_recipes.md); [Screen flow and match setup](../reference/09_front_end_and_match_flow/screen_flow_and_match_setup.md) |

| palette token | engine term | A named colour of the UI palette, one `ui.palette.*` tuning key. Every colour a widget draws, other than plain white and plain black, is a palette token. | [UI layout, rendering, input and localisation](../architecture/components/ui_framework/layout_rendering_input_and_localisation.md) |
| participant | engine term | A process that takes part in a match session and runs its own copy of the match world from the sequenced command frames, one tick at a time (R-SIM-530); the local participant is the one on this machine. | passengers | player concept | The 100 Workers that must board a Launch Vessel through its fuel depot before it can launch. | [Mode objects](../reference/03_buildings_and_world_objects/mode_objects.md) |
| pause | player concept | A sequenced command that stops the match at the next tick; it is allowed only when no remote human takes part. | PCM | abbreviation | Pulse-code modulation: uncompressed sample data. Short, frequently triggered sounds are held as 16-bit PCM at 48 kHz (ADR-025). | [Audio engine](../architecture/components/audio_engine/README.md) |
| perfect-information read | engine term | A bot's read of simulation state that a human player of the same team could not see on screen. Each is listed in the perfect-information register (PI-01 to PI-09) and marked in the rule that makes it. | [Bots](../reference/07_bots/README.md) |
| permitted maps | data term | The maps that an edition offers: all, or the list of map ids in its edition manifest. | [Build tooling and distribution](../architecture/components/build_tooling_and_distribution/README.md) |
| pin (bot) | engine term | A write that sets a team's priority at one bot navigation node and sets the team's pinned flag there, or clears the flag to release the node. Objectives pin their nearest node, so that the priority field points towards them. | [Bot priority model](../reference/07_bots/02_priority_model.md) |
| pinned flag | engine term | The per-team flag of a bot navigation node that a pin sets; while it is set, the priority formulas leave that team's priority at the node alone. | [Bot navigation graph](../reference/07_bots/01_navigation_graph.md); [Bot priority model](../reference/07_bots/02_priority_model.md) |
| placement sparkles | player concept | The two sparkles that circle each target area of the current Power while it is Waiting, so the player sees where it can be placed. | [Selection and Power slots](../reference/06_controls_camera_and_commands/selection_and_power_slots.md) |
| platform clock | engine term | The engine's monotonic clock, with an injectable time source (the real, fixed-step or manual source); presentation and scheduling read it, and no simulation duration does (ADR-074). | [Platform layer](../architecture/components/platform_layer.md) |
| platform time | engine term | A reading of the platform clock: a signed 64-bit count of nanoseconds since the clock origin. It is presentation and scheduling time, never simulation time. | [Platform layer](../architecture/components/platform_layer.md) |
| player command | engine term | One entry of the player command catalogue, the only way player intent reaches the simulation apart from the team command state (DEC-008). The commands of each tick are applied in a fixed order. | [Teams and player commands](../reference/12_simulation_model/06_teams_and_player_commands.md) |
| PNG | abbreviation | Portable Network Graphics, the format of screenshots, written with the system's image encoder; it is never read as game data (ADR-076). | [Diagnostics, test and performance](../architecture/components/diagnostics_test_and_performance/README.md) |
| pod budget | engine term | The number of Seed Pods that a Spitter Plant may still launch, 3 when it is placed. When it reaches 0, the plant damages itself and starts burning. | [Trees and crate structures](../reference/03_buildings_and_world_objects/trees_and_crate_structures.md) |
| pointer ground point | engine term | The terrain point under the pointer: where a selection circle starts, and the base point of an order target. | [Actions and bindings](../reference/06_controls_camera_and_commands/actions_and_bindings.md) |
| population cap | player concept | The per-team limit on bodies that freezes Spawn Node and Transit Gate production: the map's population cap divided by the number of open player slots (DEC-079, owner decision O14), fixed for the match, with a defender cap and a shared attacker remainder in Siege. It counts the team's ungrouped actors, its bot controller, Transports, Leaders, Crawler eggs and fading corpses included, minus its Crawlers (see DEC-453). | [Population flow](../reference/05_population_flow.md) |
